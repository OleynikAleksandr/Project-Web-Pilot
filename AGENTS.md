# Project Workflow Kit

Общайся по-русски. Используй доставленный recovery; если его нет — `./scripts/workflow recover --format text`. Не перечитывай неизменившийся контекст. Один Git checkout/worktree имеет один current plan в `.harness/plans/todo-plan.md`; новый chat или клиент продолжает его без session routing. Для независимой параллельной работы используй отдельный Git worktree.

Общие правила быстрого прототипа и Git передаются в recovery из `.harness/kit/templates/PROTOTYPE.md`. Это канонический источник: минимально необходимые шаги, локальный прототип по умолчанию, проверка результата и отдельный commit каждой микрозадачи. Пользовательское поручение имеет приоритет.

При ясном задании сопоставь работу с картой проекта, запиши короткое описание результата, запуска и проверки в docs/planning/ и создай план через plan:create. Дополнительное согласование ясного поручения не требуется. Если поручения ещё нет, обсуди следующий этап. Recovery передаёт PLAN.md, SPEC.md, CONTINUE.md и STAGES.md целиком; схема и служебные поля формируются Kit. Справка `<команда> --help` адресная, нужна только при недостающих сведениях.

Обычный цикл: task:start, работа, commit --task. Фактические файлы принимаются без лимита и предварительного task:update. Проверки перечисляй у соответствующей задачи. Финальная DOCS проверяет актуальность документов; уже актуальные файлы менять не нужно. Подробности команд и продолжения — в доставленном CONTINUE.md; справочник нестандартных ситуаций — `.harness/kit/WORKFLOW.md`.

Новое поручение добавляй через plan:extend, сохраняя DONE и историю. Kit переоткрывает DOCS, а активную DOCS при необходимости откладывает с сохранением правок. Архивирование выполняется только по прямому поручению пользователя.
