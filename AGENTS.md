# Project Web Pilot — постоянные правила разработки

Карта проекта — `docs/architecture/OVERVIEW.md`, контракты модулей — `docs/modules/`. Состояние разработки — current plan и Git; факты сборки и публикации — release-manifest.json и GitHub Release. Здесь только постоянные правила.

## Порядок работы
- Имя проекта выбрал пользователь: Project Web Pilot. Рабочий корень — `/Users/oleksandroliinyk/VSCODE/Project Web Pilot`.
- Работай по доставленному recovery и OVERVIEW. Перед реализацией читай коммиты, диффы, код и контракты модулей, от которых зависит задача; весь исторический комплект читать не нужно. Доставленный пакет повторно не запрашивай.
- Статус и разрешённый объём бери из current plan и поручений пользователя. Не придумывай новый scope и не повторяй выполненные задачи.
- Один checkout — один current plan, один пишущий агент. Не заводи параллельный TODO.md и не привязывай состояние проекта к выбранному чату. Планом и `.harness/workflow.json` управляет Kit; все коммиты — его управляемыми командами, hooks не обходить (`--no-verify` запрещён).
- Сборка, упаковка, подпись, установка и публикация — только в явно названной delivery-задаче плана, в порядке Kit: работа → DOCS → сборка один раз → установка без пересборки → публикация по поручению пользователя. Push — только после DOCS текущего плана. Процедура — `docs/modules/release.md`.
- Не трогай ради документации глобальные инструкции, trust, MCP-плагины и чужие репозитории.

## Продукт
- Встроенный Chromium в одном окне со своим левым сайдбаром — выбор пользователя. Не предлагай внешний Chrome, его профиль или Safari.
- Включённая пользователем кнопка Review разрешает основному агенту запускать рецензента Claude CLI через команды Kit для согласования нового плана. Это узкое исключение: память рецензента допустима, но код выполняет основной агент. Review OFF возвращает обычную публикацию без согласия Claude.
- Модель работает только через веб-аккаунт ChatGPT. Не добавляй модельные API. Не запускай `codex exec` и других модельных агентов и не делегируй им работу без прямой просьбы пользователя. Codex App Server как исполнитель без модельных ходов разрешён.
- Единственный backend на macOS и Windows — Codex App Server (`tools/codex-app-server-mcp`), ровно девять MCP-инструментов, без доставки контекста и без управления мышью, клавиатурой и окнами. Передача Computer Use локальному агенту и универсальный Computer Use MCP не делаются и не готовятся (решение пользователя).
- Стартовый контекст приложение доставляет само: полный recovery во вложениях и короткий транспортный текст. Агент читает каждое вложение отдельно и кратко подтверждает восстановление; MCP проекта в первом ответе не вызывается. Контракт — `docs/modules/context-delivery.md`.
- Успех старта — полный пакет в реальном первом сообщении и ответ агента о выбранном проекте. Машинного ACK нет.
- Смена проекта в панели не меняет cwd работающего чата. Локальные действия привязаны к явной папке; это согласованность, а не изоляция — ограничение MCP одной папкой не обещать.
- Вход в ChatGPT выполняет пользователь. SSO-ограничения не обходить, cookies не копировать, cookies, localStorage и внутренние функции ChatGPT не менять.
- Новые IPC — узкие, с проверкой отправителя своего окна (WebContents, mainFrame, URL — как `assertLocalSender`/`assertArchiveSender`); универсального shell- или write-API нет. Аргументы процессов — массивами. Чужие порты и PID не трогать; закрытие окна службы не гасит.
- Ключ туннеля, адрес коннектора, сертификаты, ключи и выбор signing identity не попадают в Git, журналы, диагностику и чат. Ключи не создавать и не экспортировать. Consent-диалоги не нажимать, TCC.db не править, общий сброс разрешений не делать, signing identity не менять.

## Код
- `src/chatgpt-dom.mjs`, `src/chatgpt-composer.mjs` и `src/chatgpt-experience.mjs` использует Web Pilot Sidebar. Их экспорты и формат `pageScript` без явной необходимости не менять; такое изменение обязательно отметить в описании коммита. Эти модули импортируют только друг друга именованными статическими импортами, без Node API и динамических импортов. `pageOperation` — публичная функция, `ComposerError` — внутренний.
- `scripts/` может импортировать `src/`, обратное запрещено (scripts нет в asar). `resources/*-worker.mjs` и `resources/project-doctor/**` не импортируют `src/`.
- Node: Electron ровно 44.5.1 со встроенным Node 24.21.0; комплектный Node для workers — ровно 24.21.0 (`BUNDLED_NODE_VERSION`); остальное — `^24.21.0`. Требование Node 22+ в `scripts/workflow` принадлежит Kit. Переход на Node 26 — отдельное решение пользователя.
- Событийная модель: функциональных опросов в простое нет; ограниченные ожидания, watchdog и часы допустимы. Новые службы, шину событий и скрытый polling-fallback не добавлять. Сбой наблюдения — актуальное состояние или видимая ошибка с повтором, не тихая остановка.
- Новые зависимости — только по необходимости. Тест удаляется только вместе с кодом, который он проверял.
- `packages/workflow-kit` — единственный источник Kit; правится обычной задачей плана. `resources/workflow-kit` генерируется и в Git не хранится. `.harness/kit` и Kit-секцию этого файла обновляет только установщик (`install --update`), вручную не править.

## Проверки и приёмка
- Перед коммитом сверь, что назначенные `verification_ids` подходят изменению; запускает их Kit при `commit --task`. Пустые или незапущенные проверки — не успех. `npm run build` (`paired-release`) вручную до коммита задачи не запускать: появится manifest, и проверка откажет. Smoke работает на TEST FIXTURE и не проверяет живой ChatGPT.
- Сборка, HTTP, кросс-сборка и проверка упаковки — не пользовательская приёмка. Живой ChatGPT, первый запуск на чистой ОС и native Windows проверяет пользователь по инструкциям агента. Агент не запускает VM и не использует Computer Use.
- Windows-код, проверенный на Mac подменой платформы, остаётся непроверенным до приёмки на Windows. Native Windows и чистую установку не объявлять проверенными без факта.
- Реальные чаты, профили и проекты пользователя не используются для разрушительных проверок. Повреждения для проверки Доктора моделируются только на временных fixtures; реальный проект ради проверки в устаревшее состояние не возвращать. Реальный проект удаляется только по выбору и подтверждению пользователя в интерфейсе; облачные чаты не удаляются.
- macOS-часть выпуска (`build:mac` внутри `npm run build`) обновляет постоянный `Project Web Pilot.app` в корне проекта с сохранением filesystem identity (на ней держится Finder-алиас) и отдельно создаёт версионированный ZIP. Один ZIP — не готовый выпуск. Корневой app вне Git и упаковок.
