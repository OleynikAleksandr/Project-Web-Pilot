# Project Web Pilot

Project Web Pilot 0.6.22 — локальное Electron-приложение для macOS и Windows: слева проекты, сессии и ход текущего этапа, справа настоящий ChatGPT Web во встроенном Chromium. При открытии новой сессии приложение получает полный контекст выбранного проекта и автоматически отправляет его первым сообщением. Агент коротко подтверждает восстановление и описывает назначение и текущее состояние проекта. Workflow Kit 1.3.0 ведёт проекты любого типа — программные, исследовательские, проектные, творческие и прикладные.

## Запуск и первый тест

Откройте [Project Web Pilot.app](<.harness/runtime/build/Project Web Pilot-darwin-arm64/Project Web Pilot.app>). Это локальная сборка для этого Mac с Apple Silicon. Вход в ChatGPT и сохранённые чаты переносятся автоматически. Перед обновлением формата настроек создаётся локальная резервная копия.

1. Для нового workspace нажмите «Создать проект», введите имя, выберите расположение и подтвердите список добавляемых файлов.
2. Для существующей папки нажмите «Открыть папку проекта». Приложение проверит её и предложит открыть, подготовить или восстановить локальные команды. Конфликтующие файлы показаны без перезаписи.
3. Нажмите на название проекта, чтобы открыть последнюю созданную сессию. Стрелка рядом с названием раскрывает и сворачивает список без переключения чата.
4. Нажмите нужную сессию: откроется именно её чат. Название, номер и дата помогают различать разговоры.
5. Меню ⋯ проекта → «Новый Chat» или «Новый Work» добавляет ещё одну сессию в дерево. Прежние остаются доступны. Полный контекст передастся автоматически, агент коротко опишет проект.
6. Закройте и снова откройте приложение: список, выбранная сессия и раскрытие workspace сохранятся. Повторного стартового сообщения не будет.

Сессии расположены от новых к старым; три строки видны сразу, остальные доступны прокруткой. Выбор старой сессии сохраняет её место в списке.

Первый ответ не требует вызова инструментов: весь пакет уже находится в сообщении. Для дальнейших локальных действий используйте Work/доступные инструменты проекта. Новый workspace получает Workflow Kit 1.3.0, инструкции, индекс документации и текущий ToDo-plan в состоянии `NONE` с постоянными ссылками на общую структуру проекта, карту его частей и индекс. Агент обсуждает с пользователем следующий этап существующего проекта; программный стек выбирается только тогда, когда он действительно нужен. Подробный порядок — [WORKSPACE_SETUP](docs/WORKSPACE_SETUP.md).

«Обновить контекст» получает и отправляет новый полный пакет. Старые чаты версии 0.1 открываются как сохранённые сессии; обновление выполняется только по этой кнопке либо в новом чате. При изменении плана интерфейс показывает устаревший пакет. Если в поле есть черновик или ChatGPT отвечает, автоматический старт ждёт. При неизвестном результате Send приложение проверяет сообщение, прежде чем разрешить новую отправку.

Шестерёнка внизу справа открывает Settings. В разделе «Оформление» можно выбрать светлую или тёмную тему оболочки Web Pilot; она применяется к левому сайдбару и верхней панели окна и сохраняется между запусками. Там же можно скрывать или показывать служебные строки «Вызываемый инструмент» во встроенном ChatGPT; при скрытии Web Pilot также убирает занимаемый ими служебный layout-контейнер, чтобы автопрокрутка заканчивалась у последнего видимого текста. Сами tools/MCP продолжают работать. Тема ChatGPT Web настраивается отдельно в самом ChatGPT. Ниже находится архив проектов: в меню ⋯ рядом с проектом выберите «Перенести в архив». В архиве можно вернуть проект в активные или удалить его папку с диска вместе с локальной историей. Перед удалением показан точный путь; для подтверждения нужно ввести имя проекта. Чаты в ChatGPT остаются.

Настройка пути к существующему Codex Local Mac находится в «Подробностях подключения». Там же видны размер, версия и время переданного пакета. Закрытие приложения сохраняет общие локальные службы для других чатов. Встроенному ChatGPT разрешены микрофон для диктовки и геолокация; камера и остальные разрешения браузера блокируются. При первом использовании macOS может отдельно запросить доступ к микрофону и Location Services для Project Web Pilot.


## Блок «План»

Под выбранным проектом находится самостоятельная карточка «План». Она показывает все микрозадачи текущего scope и их фактическое состояние: `✓` — выполнена и закоммичена, `●` — выполняется сейчас, `○` — ожидает. Последняя задача каждого рабочего scope автоматически называется «Актуализация всех документов проекта» и выполняется после остальных задач. Только её завершение переводит scope в «Все задачи выполнены · ожидается ваша приёмка». Технический `plan_revision` в пользовательском интерфейсе не показывается.

Кнопка «Принять» становится активной только после завершения всех задач, включая финальную актуализацию документации. Она отправляет в текущий ChatGPT-чат обычное пользовательское сообщение с явной командой штатно архивировать scope. Пользовательская приёмка остаётся отдельным gate и не выполняется агентом автоматически. Если до архивирования пользователь поручает исправления уже предъявленного результата, тот же ACTIVE scope возвращается в `IN_PROGRESS`, новые correction-задачи добавляются перед повторно открытой `DOCS`, а после неё результат снова предъявляется на приёмку. После архивирования Workflow Kit возвращается в `NONE`, но не в пустое состояние: текущий ToDo-plan сохраняет обязательные ссылки на `OVERVIEW`, `MODULES` и `DOCUMENTATION_INDEX` и предлагает обсудить следующий этап проекта. Новый рабочий scope автоматически не создаётся.

## Доктор проекта

В настройках выберите проект и нажмите «Проверить и исправить». При ошибке подключения папки доступна отдельная кнопка «Доктор проекта». Он создаёт локальную резервную копию и исправляет известные проблемы установочной записи, отсутствующих служебных файлов, команд и проверок; затем проверяет полный контекст и локальное подключение. Неизвестные изменения и потерянные пользовательские документы не перезаписываются. После успеха доступны прежняя сессия, новый Chat/Work и обновление контекста.

Выпуск 0.6.20 впервые предоставил Доктор проекта. 16.09.2026 пользователь реально запустил его на текущем Project Web Pilot: stale manifest был безопасно reconciled до Workflow Kit 1.3.0 с резервной копией и повторной readiness. 0.6.21 закрепил этот результат; текущий 0.6.22 сохраняет его без изменений Project Doctor и больше не требует намеренно держать проект неисправным. Контракт: [Project Doctor](docs/modules/project-doctor.md).

## Границы прототипа

Дерево содержит сессии, созданные и сохранённые в Web Pilot. Из версии 0.2 переносится та связь с чатом, которую она сохранила для workspace. Более ранние связи, уже заменённые старой версией, автоматически из веб-истории не импортируются.

- Использует веб-аккаунт ChatGPT и локальный Codex runtime через MCP/tunnel. Runtime lifecycle умеет переиспользовать совместимую установку или развернуть bundled runtime; tunnel credentials остаются вне ChatGPT и Git.
- Создание и подключение используют встроенный Workflow Kit 1.3.0. Неизменённые установки 1.1/1.2 могут быть безопасно обновлены до 1.3; fresh workspace сразу получает contextual `NONE`, обязательную навигацию проекта и универсальные шаблоны.
- Передача контекста выполняется при старте новой сессии или явном обновлении. Автоматическое восстановление после внутреннего compact ChatGPT не объявляется реализованным без подтверждённого сигнала.
- macOS arm64 и Windows x64 собираются из одного source of truth. Windows package проверяется автоматически; физический запуск на целевой Windows 10/11 остаётся пользовательской проверкой. Изменение разметки ChatGPT может потребовать обновления адаптера.

Результаты реального запуска, проверок и ограничения описаны в [VERIFICATION](docs/VERIFICATION.md). Пользовательская приёмка остаётся за пользователем.

## Разработка

Требуются Node.js 22.17.0 или совместимый, npm и настроенный Codex Local Mac.

```bash
npm ci
npm start
npm test
npm run smoke
npm run build
```

Проверки включают полную Node suite и интеграционный Electron smoke. Smoke создаёт настоящий временный Workflow Kit через форму, проверяет проекты/сессии, контекст, архив, настройки, удаление, переход после scope и новый gate документации: завершение обычной задачи ещё не включает пользовательскую приёмку, сначала должна завершиться `DOCS`. Используется отдельный TEST FIXTURE; он не заменяет проверку настоящего ChatGPT и физический запуск Windows.

Профиль Chromium, настройки и привязки находятся в `~/Library/Application Support/Project Web Pilot`, вне Git. Полный подготовленный текст хранится локально для безопасного возобновления отправки. Диагностика содержит только переходы состояния и метаданные; содержимое сообщений, cookies и ключи туда не записываются.

### Размер панели и архив

Правую границу левого сайдбара можно перетаскивать мышью; исходные 312 px остаются минимальной шириной, выбранный размер сохраняется. В Settings кнопка «Архив проектов…» открывает отдельное окно. Там Shift выбирает диапазон, ⌘ на macOS / Ctrl на других системах добавляет или убирает отдельные проекты. «Убрать из списка» стирает только локальную запись Web Pilot — папка и чаты ChatGPT остаются, поэтому папку можно подключить снова. «Удалить с диска…» по-прежнему работает только с одним проектом и требует точного подтверждения.

Полный абсолютный путь активного workspace больше не занимает место под карточкой проекта: под деревом сессий остаётся только строка плана. Путь можно скопировать из меню ⋯ рядом с проектом командой «Скопировать полный путь».
