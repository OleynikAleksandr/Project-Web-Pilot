# Project Web Pilot

Project Web Pilot — локальное Electron-приложение для macOS и Windows: слева проекты, чаты и текущий план, справа ChatGPT Web во встроенном Chromium. Новая сессия получает полный контекст текущего checkout; сохранённый чат открывается без повторной отправки. Файлы и команды доступны через локальный MCP/tunnel, модельные API не используются.

## Автовыполнение

Включайте или выключайте «Автовыполнение» в любой момент. Выбор сохраняется между разговорами, reload и полным перезапуском. Клиент ждёт доступную паузу: ChatGPT не busy, поле готово, нет draft/connection error, current plan подтверждён, ACTIVE и содержит незавершённую работу. Если режим включён на такой паузе, отправляется одно точное «Продолжай»; если во время busy — клиент ждёт завершения ответа. Новый Chat с NONE продолжится после появления ACTIVE-плана и обычного окончания ответа.

Агент выполняет одну микрозадачу с проверкой и коммитом либо сохраняет безопасную промежуточную точку и заканчивает ответ. Клиент продолжает фактическую текущую работу, не требует нового DONE или особой последней строки и не анализирует смысл вопроса агента. Для своего ответа выключите режим или подготовьте черновик. Draft сохраняется; после ручного Send клиент ждёт нового ответа, в том числе после reload. Ручной Stop может создать подходящую паузу с частичным ответом. После всех DONE, включая DOCS, продолжение не отправляется.

Каждая пауза имеет устойчивую машинную идентичность. Сохранённые sending/sent исключают повтор после OFF/ON, смены контекста и restart; неизвестный Send блокирует только свою паузу. Техническое ожидание пересматривается по следующему событию страницы или плана. Три минуты без прогресса при busy дают STALL_WARNING и сохраняют ожидание; новые данные снимают предупреждение. Sidebar показывает счётчик подтверждённых отправок и причины состояния. Подробности — [контракт AutoPlan 0.6.77](docs/planning/auto-plan-client-driven-refactor.md).

## Локальное подключение

После первоначальной настройки MCP и tunnel запускаются при входе пользователя в систему: macOS через LaunchAgent, Windows через HKCU Run и стабильный private launcher. Закрытие интерфейса Web Pilot сохраняет службы для других чатов.

На macOS Settings переключает Codex Local Mac / Codex App Server Local Mac за одним стабильным Secure MCP Tunnel/ChatGPT connector. Выбор сохраняется после входа в систему; после переключения приложение перезапускается.

На Windows распакуйте **всю** папку Windows ZIP на локальный диск и запустите `Project Web Pilot.exe`. Экран «Начнём работу» доступен также через «Начальная настройка» внизу сайдбара. Для Windows создайте отдельный туннель и подключение **Codex Local Windows MCP**: основной сайдбар ChatGPT → Plugins → «+» → Connection: Tunnel → туннель этой Windows → No authentication. Дождитесь списка инструментов; в новом чате добавьте это подключение через меню инструментов. Установленный ранее Codex Local Mac относится к другому компьютеру.

## Подключение MCP в ChatGPT — Mac и Windows

Обе версии показывают шаг 4 «Подключение в ChatGPT» после настройки туннеля.
На новом Mac создайте **Codex Local Mac**: основной сайдбар ChatGPT → **Plugins →
«+» → Connection: Tunnel → туннель этого Mac → No authentication**. Для Windows
аналогично создайте **Codex Local Windows MCP**, выбрав туннель этой Windows.
Можно задать своё имя. Если нужное подключение уже создано, проверьте его туннель
и список инструментов; добавлять дубликат не нужно. В новом чате выберите это
подключение через меню инструментов.

### Разрешения MCP

После создания подключения откройте **Settings → Plugins → ваше подключение →
Permissions** в ChatGPT. Выберите подходящий режим:

- **Always ask** — спрашивать перед чтением и изменениями.
- **Allow read actions** — читать без подтверждения, спрашивать перед изменениями.
- **Allow low-risk actions** — автоматически разрешать действия низкого риска;
  действия с чувствительными данными могут быть отклонены. Режим по умолчанию.
- **Allow all actions** — читать и выполнять действия без повторных подтверждений.

Для удобной самостоятельной работы агента можно выбрать **Allow all actions**.
Он сможет в том числе изменять файлы через MCP без отдельного вопроса. Режим
выбирает пользователь и может изменить здесь же. Права подключения и ограничения
ChatGPT сохраняются. Названия соответствуют интерфейсу на 19.09.2026.

## Запуск и первый тест

На основном Mac откройте `Project Web Pilot.app`. Это постоянное приложение в корне проекта для этого Mac с Apple Silicon. App и готовые ZIP не хранятся в Git; клонирование репозитория получает исходники. Поставки и SHA-256 описаны в [RELEASE](docs/RELEASE.md), Windows — в [инструкции передачи](docs/TRANSFER_TO_WINDOWS.md). Один раз создайте Finder-алиас на него: следующие релизы обновляют тот же объект. После обновления полностью завершите приложение (⌘Q) и запустите снова. Вход в ChatGPT и сохранённые чаты переносятся автоматически. Перед обновлением формата настроек создаётся локальная резервная копия.

На новом Mac распакуйте ZIP и откройте app: приложение предложит перенос в «Программы». Экран «Начнём работу» объясняет вход или регистрацию в ChatGPT, подготовку компьютера и подключение файлов. Отдельное приложение ChatGPT не требуется. Следуйте подсказкам мастера; после настройки создайте первый проект. Для возврата к мастеру доступна «Начальная настройка» внизу сайдбара. Если сайт справа не открылся, скопируйте диагностику кнопкой мастера и вставьте отчёт в сообщение разработчику. Регистрация и вход предлагаются после появления страницы.

1. Для нового workspace нажмите «Создать проект», при первом создании выберите расположение папки для проектов, затем введите имя, посмотрите изменения и нажмите Chat или Work — проект и первая сессия создадутся сразу. Выбранное расположение запоминается; для следующих проектов можно сразу ввести имя либо изменить папку специальной кнопкой.
2. Для существующей папки нажмите «Открыть папку проекта». Приложение проверит её и предложит открыть, подготовить или восстановить локальные команды. Конфликтующие файлы показаны без перезаписи.
3. Нажмите на название проекта, чтобы открыть последнюю созданную сессию. Стрелка рядом с названием раскрывает и сворачивает список без переключения чата.
4. Нажмите нужную сессию: откроется её прежний ChatGPT conversation, а карточка plan покажет **актуальный current plan выбранного workspace**. Разные старые чаты одного checkout показывают один и тот же scope/revision/tasks. Просмотр сохранённого чата не запускает новую отправку контекста.
5. Меню ⋯ проекта → «Новый Chat» или «Новый Work» добавляет новый разговор и автоматически передаёт recovery того же current plan. Новый чат не создаёт второй Workflow Kit plan; независимая параллельная работа требует отдельного Git worktree.
6. Закройте и снова откройте приложение: список, выбранная сессия и раскрытие workspace сохранятся. Повторного стартового сообщения не будет.

Сессии расположены от новых к старым; три строки видны сразу, остальные доступны прокруткой. Выбор старой сессии сохраняет её место в списке.

Первый ответ не требует вызова инструментов: весь пакет уже находится в сообщении. Для дальнейших локальных действий добавьте подключение этого компьютера в чат через меню инструментов. Полный пакет проекта сам по себе MCP не подключает. Новый workspace получает Workflow Kit 1.5.1, инструкции, индекс документации и единый current ToDo-plan в состоянии `NONE` с постоянными ссылками на общую структуру проекта, карту его частей и индекс. Агент обсуждает с пользователем следующий этап существующего проекта; программный стек выбирается только тогда, когда он действительно нужен. Подробный порядок — [WORKSPACE_SETUP](docs/WORKSPACE_SETUP.md).

«Обновить контекст» получает и отправляет новый полный пакет. Старые чаты версии 0.1 открываются как сохранённые сессии; обновление выполняется только по этой кнопке либо в новом чате. При изменении плана интерфейс показывает устаревший пакет. Если в поле есть черновик или ChatGPT отвечает, автоматический старт ждёт. При неизвестном результате Send приложение не отправляет пакет повторно автоматически; передача после вызова Send завершается без поиска текста в DOM и ожидания ответа.

Шестерёнка внизу справа открывает Settings. В разделе «Оформление» можно выбрать светлую или тёмную тему оболочки Web Pilot; она применяется к левому сайдбару и верхней панели окна и сохраняется между запусками. Там же можно скрывать или показывать служебные карточки инструментов и ответов приложений во встроенном ChatGPT; при скрытии Web Pilot также убирает занимаемый ими служебный layout-контейнер, чтобы автопрокрутка заканчивалась у последнего видимого текста. Сами tools/MCP продолжают работать. Базовая светлая/тёмная тема ChatGPT выбирается в самом ChatGPT; кнопка «Цвета чата…» в Settings Web Pilot позволяет отдельно настроить пять цветов. Ниже находится архив проектов: в меню ⋯ рядом с проектом выберите «Перенести в архив». В архиве можно вернуть проект в активные или удалить его папку с диска вместе с локальной историей. Перед удалением показан точный путь; для подтверждения нужно ввести имя проекта. Чаты в ChatGPT остаются.

Настройка пути к существующему Codex Local Mac находится в «Подробностях подключения». Там же видны размер, версия и время переданного пакета. Закрытие приложения сохраняет общие локальные службы для других чатов. Встроенному ChatGPT разрешены микрофон для диктовки и геолокация; камера и остальные разрешения браузера блокируются. При первом использовании macOS может отдельно запросить доступ к микрофону и Location Services для Project Web Pilot.


## Текущий plan проекта и чаты

Карточка «Текущий план проекта» показывает микрозадачи **единственного plan текущего checkout**: `✓` — выполнена и зафиксирована, `●` — выполняется, `○` — ожидает. Переключение между чатами меняет разговор справа, но не выбирает другой plan. Новое поручение расширяет current plan через Workflow Kit, сохраняя выполненные задачи и commit references; финальная DOCS актуализирует документацию.

`plan:prepare`, `plan:bind` и session ownership больше не являются рабочим lifecycle. Legacy `planId`, `originSessionId`, `legacyPlanId`, `owner_session_id` и подобные поля могут оставаться в старых данных для history/diagnostics, но приложение не использует их для runtime selection. При upgrade на single-active Workflow Kit исторические session plans переносятся в read-only archive. Для действительно независимой параллельной работы используется отдельный Git branch/worktree.

## Доктор проекта

В настройках выберите проект и нажмите «Проверить и исправить». При ошибке подключения папки доступна отдельная кнопка «Доктор проекта». Он создаёт локальную резервную копию и исправляет известные проблемы установочной записи, отсутствующих служебных файлов, команд и проверок; затем проверяет полный контекст и локальное подключение. Неизвестные изменения и потерянные пользовательские документы не перезаписываются. После успеха доступны прежняя сессия, новый Chat/Work и обновление контекста.

Доктор проверяет current plan и обязательные документы checkout; historical plan payloads сохраняются, но не блокируют готовность. Намеренные повреждения проверяются только на fixtures. Контракт: [Project Doctor](docs/modules/project-doctor.md).

## Границы прототипа

Дерево содержит сессии, созданные и сохранённые в Web Pilot. Из версии 0.2 переносится та связь с чатом, которую она сохранила для workspace. Более ранние связи, уже заменённые старой версией, автоматически из веб-истории не импортируются.

- Использует веб-аккаунт ChatGPT и локальный Codex runtime через MCP/tunnel. Runtime lifecycle умеет переиспользовать совместимую установку или развернуть bundled runtime; tunnel credentials остаются вне ChatGPT и Git.
- Создание и подключение используют Workflow Kit 1.5.1 из generated runtime, автоматически staged из `@webpilot/workflow-kit`. Совместимые установки 1.1.0–1.4.13 обновляются штатным installer с резервной копией; legacy `by-id`/`by-session` plans мигрируют в read-only history, fresh workspace сразу получает contextual `NONE`, обязательную навигацию проекта и универсальные шаблоны.
- Передача контекста выполняется при старте новой сессии или явном обновлении. Автоматическое восстановление после внутреннего compact ChatGPT не объявляется реализованным без подтверждённого сигнала.
- macOS arm64 и Windows x64 собираются из одного source of truth. Windows package проверяется автоматически; физический запуск на целевой Windows 10/11 остаётся пользовательской проверкой. Изменение разметки ChatGPT может потребовать обновления адаптера.

Результаты реального запуска, проверок и ограничения описаны в [VERIFICATION](docs/VERIFICATION.md). Пользовательская приёмка остаётся за пользователем.

## Разработка

Для текущих исходников требуются Node.js `^24.21.0` (не ниже 24.21.0 и ниже 25), npm и настроенный Codex Local Mac. Electron закреплён на 44.5.1; встроенный и комплектный Node — 24.21.0.

```bash
npm ci
npm start
npm test
npm run smoke
npm run build
```

Проверки включают полную Node suite и интеграционный Electron smoke. Smoke создаёт настоящий временный Workflow Kit через форму, проверяет проекты/сессии, контекст, архив, настройки, удаление, собственные планы, подготовку/отмену/создание Chat/Work и обязательную последнюю `DOCS`. Завершение задач сохраняет план и не вызывает переход автоматически. Используется отдельный TEST FIXTURE; он не заменяет проверку настоящего ChatGPT и физический запуск Windows.

Профиль Chromium, настройки и привязки находятся в `~/Library/Application Support/Project Web Pilot`, вне Git. Полный подготовленный текст хранится локально для безопасного возобновления отправки. Диагностика содержит только переходы состояния и метаданные; содержимое сообщений, cookies и ключи туда не записываются.

## Продолжение работы

Начните с [WORKFLOW_START](docs/WORKFLOW_START.md) и актуального recovery packet. Каждый Git checkout/worktree имеет ровно один current plan — `.harness/plans/todo-plan.md`; новый Chat/Work продолжает этот же plan. Для независимой параллельной работы создаётся отдельный Git worktree. Каталог документов — [DOCUMENTATION_INDEX](docs/DOCUMENTATION_INDEX.md), контракт доставки контекста — [CONTEXT_DELIVERY](docs/CONTEXT_DELIVERY.md), устройство приложения — [ARCHITECTURE](docs/architecture/ARCHITECTURE.md).

WF001 и Codex Local Mac ([исходные проекты](docs/SOURCE_WORKSPACES.md)) остаются отдельными репозиториями. По поручению пользователя MCP обновлён для прямой передачи контекста. Профили браузеров и секреты не переносились. Приёмка не архивирует scope; следующий объём определяется отзывом пользователя.

### Размер панели и архив

Правую границу левого сайдбара можно перетаскивать мышью; исходные 312 px остаются минимальной шириной, выбранный размер сохраняется. В Settings кнопка «Архив проектов…» открывает отдельное окно. Там Shift выбирает диапазон, ⌘ на macOS / Ctrl на других системах добавляет или убирает отдельные проекты. «Убрать из списка» стирает только локальную запись Web Pilot — папка и чаты ChatGPT остаются, поэтому папку можно подключить снова. «Удалить с диска…» по-прежнему работает только с одним проектом и требует точного подтверждения.

Полный абсолютный путь активного workspace больше не занимает место под карточкой проекта: под деревом сессий остаётся только строка плана. Путь можно скопировать из меню ⋯ рядом с проектом командой «Скопировать полный путь».

## Цвета чата

Settings → «Цвета чата…» открывает отдельное перемещаемое окно. Можно независимо выбрать общий фон чата, фон плашки пользователя, фон поля ввода и цвета текста пользователя/агента. Выбор цвета или корректного HEX сразу отображается в открытом ChatGPT и автоматически сохраняется для всех чатов Web Pilot. ↺ возвращает стандартный цвет строки; «Вернуть оформление ChatGPT» сбрасывает всю палитру. ## Постоянное приложение и выпуск

`npm run build:mac` собирает и обновляет `Project Web Pilot.app` в корне проекта, сохраняя Finder-алиас. Отдельный ZIP создаётся в `.harness/runtime/releases/<version>/` и копируется в `~/Downloads/WebPilot-<version>/`. Повторная публикация готовой сборки: `npm run release:mac`. Backup и проверка версии выполняются автоматически; контракт — [RELEASE](docs/RELEASE.md). Используйте Finder-алиас на корневой app.

После обновления полностью завершите приложение и запустите постоянный app из корня проекта.

## Сохранение размеров интерфейса

Web Pilot запоминает размер и положение основного окна и восстанавливает их при следующем запуске. Для этого используется штатное сохранение bounds Electron с постоянным именем главного окна; состояние хранится в userData приложения и переживает замену `.app` новым релизом. Ширина левого сайдбара сохраняется отдельно в том же стабильном userData (`settings.json`) при перетаскивании разделителя или изменении с клавиатуры. Полноэкранный/максимизированный режим намеренно не является частью этого контракта.
