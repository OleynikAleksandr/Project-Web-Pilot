# Project Web Pilot

Electron-приложение для macOS и Windows: слева локальные проекты, чаты и текущий план, справа ChatGPT Web во встроенном Chromium. Модель работает через веб-аккаунт; файлы и команды доступны через локальный MCP и туннель, без модельных API.

## Версия
Project Web Pilot **0.6.97**, Workflow Kit **1.6.0**, Electron **44.5.1**, Node **24.21.0**. Сведения о сборке, публикации, артефактах и контрольных суммах — в release-manifest.json и GitHub Release.

## Установка и первый запуск
- macOS Apple Silicon: распакуйте приложение и откройте Project Web Pilot.app. На новом Mac приложение предлагает перенос в «Программы». На рабочем Mac проекта используйте постоянный app в корне репозитория и Finder-алиас на него: обновление сохраняет его filesystem identity.
- Windows 10/11 x64: распакуйте **всю папку** Windows ZIP на локальный диск и запустите Project Web Pilot.exe.
- После обновления полностью завершите приложение (на Mac — ⌘Q) и откройте снова. Профиль ChatGPT, настройки и сохранённые сессии остаются в пользовательских данных.
- Экран «Начнём работу» проводит через вход в ChatGPT, подготовку компьютера, туннель и подключение файлов. Вернуться к нему можно через «Начальная настройка» в сайдбаре. Ошибка открытия сайта имеет кнопку копирования диагностики.

На обеих системах локальный исполнитель — Codex App Server. Нужен установленный Codex: на Mac CLI либо приложение ChatGPT, на Windows — CLI; способ установки показывает мастер. На новом Mac может потребоваться Apple Command Line Tools. Node и компоненты Windows поставляются вместе с приложением; отдельный сервер инструментов из старого Windows-архива не запускается.

В Settings выберите канал: Secure MCP Tunnel или настроенный VPS. Для него подключите соответствующий плагин в ChatGPT; Web Pilot не переключает плагины за пользователя. При создании подключения используйте туннель **этого компьютера**, режим No authentication и имя Codex App Server Local Mac / Local Windows. Уже существующее правильное подключение достаточно обновить; в новом чате добавьте его через меню инструментов.

Разрешения подключения выбирает пользователь в Settings → Plugins → подключение → Permissions. Allow all actions разрешает агенту изменения без повторных вопросов в пределах правил ChatGPT; это не выдаёт системных разрешений macOS. Для снимков экрана macOS отдельно запрашивает Screen Recording. Микрофон и геолокация также имеют отдельные разрешения. Управление мышью/клавиатурой через MCP не предусмотрено.

Службы запускаются при входе в ОС (LaunchAgent на Mac, HKCU Run на Windows) и продолжают работать после закрытия интерфейса Web Pilot. Ключи туннеля не передаются модели и не хранятся в Git.

## Проект и разговор
1. «Создать проект»: сначала выберите расположение, затем имя. Расположение запоминается; его можно изменить. Проверьте путь и добавляемые файлы, выберите Chat или Work.
2. «Открыть папку проекта»: приложение проверяет папку и предлагает открыть, подготовить или восстановить служебные команды. Конфликты не перезаписываются.
3. Название проекта открывает последнюю созданную сессию; стрелка раскрывает список. Сессия открывает сохранённый разговор без повторной отправки контекста.
4. Меню ⋯ → «Новый Chat» / «Новый Work» создаёт разговор того же проекта. Один checkout имеет один план; чаты его не дублируют.
5. Новая сессия получает короткое сообщение и до **7 вложений** с полным контекстом. Каждая часть — до 28000 байт по умолчанию, общий пакет — до 180000 байт. Send выполняется после загрузки всех частей. Агент читает каждое вложение отдельно и кратко подтверждает восстановление.
6. «Обновить контекст» подготавливает актуальный пакет. Черновик, работающий ответ, ошибка загрузки или неопределённый исход отправки не разрешают автоматический дубль. При ошибке проверьте показанную причину и состояние вложений.

Сам пакет не подключает MCP. В первом ответе агент может читать вложения, но не вызывает MCP проекта. Для дальнейших локальных действий подключение компьютера должно быть доступно в чате. Меню проекта позволяет скопировать полный путь и строку для внешнего клиента.

Обсуждение и исследование не требуют фиктивного плана. Задачи и подтверждённые коммиты показывает карточка текущего плана. Перед выпуском выполняется DOCS, затем явные задачи сборки/установки/публикации; без выпуска обязательная DOCS не добавляется. Завершённый план остаётся видимым до команды пользователя на закрытие.

## Автовыполнение
Переключатель сохраняется между чатами и перезапусками. При подходящей паузе и незавершённом ACTIVE-плане клиент отправляет «Продолжай» с данными следующей задачи. Текст ответа агента не является триггером. Busy, черновик и неготовая история блокируют отправку; после ручного Send ожидается новый ответ. Неопределённая отправка не повторяется. Для своего ответа выключите режим либо подготовьте черновик. После всех DONE продолжения нет.

## Настройки и восстановление
Settings управляет темой оболочки, служебными карточками инструментов и пятью цветами чата; скрытие карточек не отключает инструменты. Положение окна и ширина сайдбара сохраняются, минимальная ширина панели — 312 px; fullscreen/maximized в этот контракт не входят.

«Архив проектов…» открывает отдельное окно. «Убрать из списка» сохраняет папку; удаление с диска требует точного имени и удаляет локальные файлы/историю. Облачные чаты остаются. В архиве доступны диапазон Shift и множественный выбор ⌘/Ctrl.

«Доктор проекта» исправляет известные служебные неисправности с резервной копией. Неизвестные изменения и отсутствующие пользовательские документы не восстанавливаются догадкой. После ремонта повторяется проверка готовности.

Профиль Chromium и локальные настройки находятся вне Git (на Mac — ~/Library/Application Support/Project Web Pilot). Подготовленный пакет сохраняется локально для возобновления; диагностика не записывает текст беседы, cookies или ключи.

## Запуск из исходников
Нужны Node.js ^24.21.0 и npm. Клонирование репозитория получает исходники, не готовый app.

```bash
npm ci
npm start
npm test
npm run smoke
npm run check --prefix packages/workflow-kit
```

Сборка выполняется только в предусмотренной задаче выпуска: npm run build. Процедура — [RELEASE](docs/RELEASE.md). Новый живой транспорт ChatGPT, чистая установка и нативная Windows требуют пользовательской приёмки; fixture и сборка её не заменяют. Разметка ChatGPT может потребовать обновления адаптера. Восстановление после внутреннего compact без подтверждённого сигнала не заявляется.
