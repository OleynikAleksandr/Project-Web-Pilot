# Project Web Pilot

Project Web Pilot — локальное Electron-приложение для macOS и Windows: слева проекты, сессии и ход текущего этапа, справа настоящий ChatGPT Web во встроенном Chromium. При открытии новой сессии приложение получает полный контекст выбранного проекта и автоматически отправляет его первым сообщением. Агент коротко подтверждает восстановление и описывает назначение и текущее состояние проекта. Workflow Kit 1.4.1 ведёт проекты любого типа — программные, исследовательские, проектные, творческие и прикладные.

19.09.2026 выпущена **0.6.42** для macOS arm64 и Windows x64 одной командой `npm run build`; ZIP находятся в ~/Downloads/WebPilot-0.6.42/. На обеих платформах подключение разделено на последовательные шаги ID туннеля и API key. Ссылка API keys видна в основном содержимом второго шага; объяснены создание ключа, копирование полного sk-значения и вставка в защищённое системное поле. Ручной путь останавливается после ID и показывает инструкцию ключа. Windows сохраняет комплектные Python/Git/MCP и DPAPI. Выбор расположения проектов и существующие настройки сохранены. Исходники и упаковки сверены; реальный проход пользователь выполняет самостоятельно. Агент не запускает VM и не использует Computer Use.

На Windows распакуйте **всю** папку Windows ZIP на локальный диск и запустите `Project Web Pilot.exe`. Экран «Начнём работу» доступен также через «Начальная настройка» внизу сайдбара. Для Windows создайте отдельный туннель и подключение Codex Local Windows MCP в ChatGPT.

## Запуск и первый тест

На основном Mac откройте `Project Web Pilot.app`. Это постоянное приложение в корне проекта для этого Mac с Apple Silicon. App и готовые ZIP не хранятся в Git; клонирование репозитория получает исходники. Поставки и SHA-256 описаны в [RELEASE](docs/RELEASE.md), Windows — в [инструкции передачи](docs/TRANSFER_TO_WINDOWS.md). Один раз создайте Finder-алиас на него: следующие релизы обновляют тот же объект. После обновления полностью завершите приложение (⌘Q) и запустите снова. Вход в ChatGPT и сохранённые чаты переносятся автоматически. Перед обновлением формата настроек создаётся локальная резервная копия.

На новом Mac распакуйте ZIP и откройте app: приложение предложит перенос в «Программы». Экран «Начнём работу» объясняет вход или регистрацию в ChatGPT, подготовку компьютера и подключение файлов. Отдельное приложение ChatGPT не требуется. Следуйте подсказкам мастера; после настройки создайте первый проект. Для возврата к мастеру доступна «Начальная настройка» внизу сайдбара. Если сайт справа не открылся, скопируйте диагностику кнопкой мастера и вставьте отчёт в сообщение разработчику. Регистрация и вход предлагаются после появления страницы.

1. Для нового workspace нажмите «Создать проект», при первом создании выберите расположение папки для проектов, затем введите имя, посмотрите изменения и нажмите Chat или Work — проект и первая сессия создадутся сразу. Выбранное расположение запоминается; для следующих проектов можно сразу ввести имя либо изменить папку специальной кнопкой.
2. Для существующей папки нажмите «Открыть папку проекта». Приложение проверит её и предложит открыть, подготовить или восстановить локальные команды. Конфликтующие файлы показаны без перезаписи.
3. Нажмите на название проекта, чтобы открыть последнюю созданную сессию. Стрелка рядом с названием раскрывает и сворачивает список без переключения чата.
4. Нажмите нужную сессию: её собственный план и чат открываются сразу после короткого чтения. Полная проверка идёт в фоне; при ошибке доступны повтор и Доктор. Просмотр сохранённого чата не запускает новую отправку контекста.
5. Меню ⋯ проекта → «Новый Chat» или «Новый Work» добавляет самостоятельную сессию с NONE. Прежние планы остаются в своих сессиях. Общая навигация проекта передастся автоматически.
6. Закройте и снова откройте приложение: список, выбранная сессия и раскрытие workspace сохранятся. Повторного стартового сообщения не будет.

Сессии расположены от новых к старым; три строки видны сразу, остальные доступны прокруткой. Выбор старой сессии сохраняет её место в списке.

Первый ответ не требует вызова инструментов: весь пакет уже находится в сообщении. Для дальнейших локальных действий используйте Work/доступные инструменты проекта. Новый workspace получает Workflow Kit 1.4.1, инструкции, индекс документации и текущий ToDo-plan в состоянии `NONE` с постоянными ссылками на общую структуру проекта, карту его частей и индекс. Агент обсуждает с пользователем следующий этап существующего проекта; программный стек выбирается только тогда, когда он действительно нужен. Подробный порядок — [WORKSPACE_SETUP](docs/WORKSPACE_SETUP.md).

«Обновить контекст» получает и отправляет новый полный пакет. Старые чаты версии 0.1 открываются как сохранённые сессии; обновление выполняется только по этой кнопке либо в новом чате. При изменении плана интерфейс показывает устаревший пакет. Если в поле есть черновик или ChatGPT отвечает, автоматический старт ждёт. При неизвестном результате Send приложение проверяет сообщение, прежде чем разрешить новую отправку.

Шестерёнка внизу справа открывает Settings. В разделе «Оформление» можно выбрать светлую или тёмную тему оболочки Web Pilot; она применяется к левому сайдбару и верхней панели окна и сохраняется между запусками. Там же можно скрывать или показывать служебные строки «Вызываемый инструмент» во встроенном ChatGPT; при скрытии Web Pilot также убирает занимаемый ими служебный layout-контейнер, чтобы автопрокрутка заканчивалась у последнего видимого текста. Сами tools/MCP продолжают работать. Базовая светлая/тёмная тема ChatGPT выбирается в самом ChatGPT; кнопка «Цвета чата…» в Settings Web Pilot позволяет отдельно настроить пять цветов. Ниже находится архив проектов: в меню ⋯ рядом с проектом выберите «Перенести в архив». В архиве можно вернуть проект в активные или удалить его папку с диска вместе с локальной историей. Перед удалением показан точный путь; для подтверждения нужно ввести имя проекта. Чаты в ChatGPT остаются.

Настройка пути к существующему Codex Local Mac находится в «Подробностях подключения». Там же видны размер, версия и время переданного пакета. Закрытие приложения сохраняет общие локальные службы для других чатов. Встроенному ChatGPT разрешены микрофон для диктовки и геолокация; камера и остальные разрешения браузера блокируются. При первом использовании macOS может отдельно запросить доступ к микрофону и Location Services для Project Web Pilot.


## Планы сессий

«План этой сессии» показывает собственные микрозадачи: `✓` — выполнена и зафиксирована, `●` — выполняется, `○` — ожидает. Выполненный план остаётся видимым. Напишите агенту новое поручение в этом чате: он добавит задачи, сохранив прежние результаты и коммиты. Последняя DOCS актуализирует документацию после новых задач.

В текущем разговоре можно подготовить план будущей работы. Он появится в блоке «План следующей сессии», сохранив собственный план. «Создать сессию с этим планом» открывает выбор Chat/Work; отмена сохраняет черновик. После создания исходный чат хранит просмотр того же плана и переход к его сессии, новая сессия — ссылку на источник.

Кнопок «+ Задача» и обязательной приёмки нет. Завершение задач не архивирует план и не создаёт сессию. Явное архивирование остаётся отдельным действием пользователя. При NONE сохраняется общая навигация проекта; чужой план не подставляется. Старые связи мигрируют только по однозначным данным, иначе показано объяснение, а исторические файлы сохранены.

## Доктор проекта

В настройках выберите проект и нажмите «Проверить и исправить». При ошибке подключения папки доступна отдельная кнопка «Доктор проекта». Он создаёт локальную резервную копию и исправляет известные проблемы установочной записи, отсутствующих служебных файлов, команд и проверок; затем проверяет полный контекст и локальное подключение. Неизвестные изменения и потерянные пользовательские документы не перезаписываются. После успеха доступны прежняя сессия, новый Chat/Work и обновление контекста.

Выпуск 0.6.20 впервые предоставил Доктор проекта. 16.09.2026 пользователь реально запустил его на текущем Project Web Pilot: stale manifest был безопасно reconciled до Workflow Kit 1.3.0 с резервной копией и повторной readiness. 0.6.21 закрепил этот результат. В 0.6.28 Доктор проверяет все канонические планы сессий; намеренные повреждения проверяются только на fixtures. Контракт: [Project Doctor](docs/modules/project-doctor.md).

## Границы прототипа

Дерево содержит сессии, созданные и сохранённые в Web Pilot. Из версии 0.2 переносится та связь с чатом, которую она сохранила для workspace. Более ранние связи, уже заменённые старой версией, автоматически из веб-истории не импортируются.

- Использует веб-аккаунт ChatGPT и локальный Codex runtime через MCP/tunnel. Runtime lifecycle умеет переиспользовать совместимую установку или развернуть bundled runtime; tunnel credentials остаются вне ChatGPT и Git.
- Создание и подключение используют встроенный Workflow Kit 1.4.1. Неизменённые установки 1.1/1.2/1.3/1.4.0 могут быть безопасно обновлены до 1.4.1; fresh workspace сразу получает contextual `NONE`, обязательную навигацию проекта и универсальные шаблоны.
- Передача контекста выполняется при старте новой сессии или явном обновлении. Автоматическое восстановление после внутреннего compact ChatGPT не объявляется реализованным без подтверждённого сигнала.
- macOS arm64 и Windows x64 собираются из одного source of truth. Windows package проверяется автоматически; физический запуск на целевой Windows 10/11 остаётся пользовательской проверкой. Изменение разметки ChatGPT может потребовать обновления адаптера.

Результаты реального запуска, проверок и ограничения описаны в [VERIFICATION](docs/VERIFICATION.md). Пользовательская приёмка остаётся за пользователем.

## Разработка

Требуются Node.js 22.17.0 или совместимый, npm и настроенный Codex Local Mac.

```bash
npm ci
npm start
npm test
npm run smoke
npm run build
```

Проверки включают полную Node suite и интеграционный Electron smoke. Smoke создаёт настоящий временный Workflow Kit через форму, проверяет проекты/сессии, контекст, архив, настройки, удаление, собственные планы, подготовку/отмену/создание Chat/Work и обязательную последнюю `DOCS`. Завершение задач сохраняет план и не вызывает переход автоматически. Используется отдельный TEST FIXTURE; он не заменяет проверку настоящего ChatGPT и физический запуск Windows.

Профиль Chromium, настройки и привязки находятся в `~/Library/Application Support/Project Web Pilot`, вне Git. Полный подготовленный текст хранится локально для безопасного возобновления отправки. Диагностика содержит только переходы состояния и метаданные; содержимое сообщений, cookies и ключи туда не записываются.

## Продолжение работы

Начните с [WORKFLOW_START](docs/WORKFLOW_START.md) и актуального recovery packet. Каждая сессия имеет собственный план в `.harness/plans/by-id/` либо NONE; адрес команд берётся из её recovery packet. `.harness/plans/todo-plan.md` сохранён для совместимости и истории; каталог — [DOCUMENTATION_INDEX](docs/DOCUMENTATION_INDEX.md). Канонический контракт — [CONTEXT_DELIVERY](docs/CONTEXT_DELIVERY.md); устройство приложения — [ARCHITECTURE](docs/architecture/ARCHITECTURE.md).

WF001 и Codex Local Mac ([исходные проекты](docs/SOURCE_WORKSPACES.md)) остаются отдельными репозиториями. По поручению пользователя MCP обновлён для прямой передачи контекста. Профили браузеров и секреты не переносились. Приёмка не архивирует scope; следующий объём определяется отзывом пользователя.

### Размер панели и архив

Правую границу левого сайдбара можно перетаскивать мышью; исходные 312 px остаются минимальной шириной, выбранный размер сохраняется. В Settings кнопка «Архив проектов…» открывает отдельное окно. Там Shift выбирает диапазон, ⌘ на macOS / Ctrl на других системах добавляет или убирает отдельные проекты. «Убрать из списка» стирает только локальную запись Web Pilot — папка и чаты ChatGPT остаются, поэтому папку можно подключить снова. «Удалить с диска…» по-прежнему работает только с одним проектом и требует точного подтверждения.

Полный абсолютный путь активного workspace больше не занимает место под карточкой проекта: под деревом сессий остаётся только строка плана. Путь можно скопировать из меню ⋯ рядом с проектом командой «Скопировать полный путь».

## Цвета чата

Settings → «Цвета чата…» открывает отдельное перемещаемое окно. Можно независимо выбрать общий фон чата, фон плашки пользователя, фон поля ввода и цвета текста пользователя/агента. Выбор цвета или корректного HEX сразу отображается в открытом ChatGPT и автоматически сохраняется для всех чатов Web Pilot. ↺ возвращает стандартный цвет строки; «Вернуть оформление ChatGPT» сбрасывает всю палитру. Настройки действуют только внутри Web Pilot; после изменения DOM ChatGPT возможна адаптация CSS.

Текущие ZIP 0.6.40 находятся в `~/Downloads/WebPilot-0.6.40/`; контрольные суммы — [RELEASE](docs/RELEASE.md).


## Постоянное приложение и выпуск

`npm run build:mac` собирает и обновляет `Project Web Pilot.app` в корне проекта, сохраняя Finder-алиас. Отдельный ZIP создаётся в `.harness/runtime/releases/<version>/` и копируется в `~/Downloads/WebPilot-<version>/`. Повторная публикация готовой сборки: `npm run release:mac`. Backup и проверка версии выполняются автоматически; контракт — [RELEASE](docs/RELEASE.md). Старый адрес в releases/0.6.20 один раз обновлён до 0.6.23, но для будущих выпусков используйте алиас на корневой app.

В 0.6.24 настройка плашки меняет фон самого скруглённого сообщения пользователя; внешняя строка остаётся прозрачной. После обновления полностью завершите приложение и запустите постоянный app из корня проекта.

В 0.6.25 появился пятый пункт «Фон поля ввода». Он меняет фон всего скруглённого блока, сохраняя черновик, кнопки и геометрию. Цвет текста агента применяется также к новым фрагментам потокового ответа. Оба изменения сохраняются автоматически; доступны независимый и общий сброс.

В 0.6.26 активная сессия в дереве выделяется тонкой скруглённой обводкой всей строки вместо отдельной вертикальной полосы. Chevron проекта, магистраль, ветви дерева и обводка используют один акцентный цвет и одинаковую визуальную толщину; badge `Chat/Work` и меню `⋯` находятся внутри этой обводки.

## Сохранение размеров интерфейса — 0.6.31

Web Pilot запоминает размер и положение основного окна и восстанавливает их при следующем запуске. Для этого используется штатное сохранение bounds Electron с постоянным именем главного окна; состояние хранится в userData приложения и переживает замену `.app` новым релизом. Ширина левого сайдбара сохраняется отдельно в том же стабильном userData (`settings.json`) при перетаскивании разделителя или изменении с клавиатуры. Полноэкранный/максимизированный режим намеренно не является частью этого контракта.
