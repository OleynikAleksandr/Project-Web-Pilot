## Работа над прототипом и Git

Выполняй задачу минимально необходимым числом шагов. Сначала проверь существующие решения проекта и подходящие готовые реализации. Для программного продукта по умолчанию готовь работающий локальный прототип; выполни заказанные функции без инфраструктуры на будущее. Используй существующий стек и архитектуру. Уточняй только то, без чего нельзя корректно продолжить; обратимые решения принимай самостоятельно.

Сначала обеспечь основной пользовательский сценарий целиком, затем заверши запрошенный объём. Продумай проверку результата заранее и проверяй через пользовательский вход. Внутренний вызов функции не подтверждает кнопку, Enter или внешний API. Не подменяй интеграцию имитацией. Подтверждай только фактически проверенные свойства; существенную недостающую проверку выполни или прямо обозначь ограничение.

Для выдаваемого артефакта проверь конечное назначение и символические ссылки до записи; ошибка чтения не означает свободный путь. Проверяй выдаваемую копию и фактический состав пакета. Материалы разработки включай только при необходимости получателю; .gitignore не задаёт содержимое архива. Для локального прототипа отключи автоматический выбор пользовательского сертификата; техническую платформенную подпись применяй лишь если она нужна для запуска. Процесс и разрешённый объём delivery определяет Workflow Core.

Используй доставленные сведения; не читай повторно неизменившийся контекст. Недостающие независимые чтения объединяй; различай среду клиента и среду сборки. Зависимые действия останавливай при ошибке. Долгую команду веди в фоне с идентификатором процесса; при продолжении сначала прочитай её результат и не запускай её заново. Не повторяй успешную проверку без изменения относящихся к ней условий; если проверка назначена в commit, отдельный предварительный прогон обычно не нужен. Сохраняй содержательные промежуточные сообщения.

**Рабочее дерево и состав изменений**

- Учти staged, unstaged и untracked. Обнови status/diff, если состояние изменилось. Существовавшие правки не присваивай и не удаляй.
- До генерации, установки зависимостей или сборки выясни выходные каталоги. Обнови .gitignore для воспроизводимых артефактов, кэшей и локального состояния, сохраняя пользовательские правила. Исходники, нужные ресурсы и lock-файлы остаются в Git. Не исключай каталоги только по названию.
- .gitignore не действует на отслеживаемые файлы. При выводе из Git проверь состав и сохрани рабочие копии; не применяй массовую очистку ради проверки.
- Перед фиксацией проверь status/diff и содержимое новых файлов. Не используй git add . вслепую. При неоднозначном составе укажи относящиеся пути через commit --files. Не создавай пустые исходники и бессмысленные правки документов.
- После фиксации проверь excluded_changes и status. Если собственная ранняя правка считалась существовавшей до задачи, проверь её авторство и включи явно. Для изменения только .gitignore достаточны проверка diff и примеры git check-ignore; явно назначенные проверки остаются обязательными.

Ссылка на файл, diff или контрольная сумма не заменяет чтение нужного содержимого перед зависимым действием.
