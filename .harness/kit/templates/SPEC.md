# Короткий контракт результата

Это шаблон для docs/planning/<название>.md, не дополнительный обязательный документ. Если подходящий контракт уже есть, уточни его. Заполни только относящиеся к поручению сведения, не повторяя один текст в нескольких документах.

```markdown
# <Название результата>

## Результат
<Что пользователь сможет сделать; основные входы и наблюдаемый результат.>

## Запуск
<Как открыть или использовать результат; точное место выдаваемого артефакта, если он нужен.>

## Проверка
<Действия через пользовательский вход и ожидаемые результаты, включая основные способы запуска операции и ошибку с восстановлением, если применимо.>

## Границы
<Согласованные ограничения; существующие решения, которые нужно сохранить.>
```

Связанные документы выбери по карте модулей в OVERVIEW и укажи в context_pack плана. Содержание и срок жизни документов определяет Workflow Core. Для спецификации модуля используй форму из task:start --help.

Если сессия разрешает параллельное выполнение, объясни, есть ли независимые задачи и почему выбран parallel либо sequential. Укажи зависимости, конкретные области записи и критерии интеграции. Разрешение не обязывает создавать исполнителей. Настройки берутся из сохранённого снимка сессии. Готовность отдельной ветки и проверенный результат в main — разные этапы; завершение общего пункта подтверждает только интеграция. Возможность отделить представление сессии в окно не должна определять её жизненный цикл.
