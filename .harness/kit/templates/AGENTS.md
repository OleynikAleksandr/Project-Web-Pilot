# Project Workflow Kit

Общайся по-русски. При старте/возобновлении/compact используй доставленный recovery capsule; если его нет — `./scripts/workflow recover --session <sessionId> --format text`. Во всех командах указывай sessionId из своего пакета; для чтения/подготовки другого плана также явно указывай planId. Выбор чата в интерфейсе не меняет владельца команд агента.

Workflow Kit ведёт проекты любого типа. Каждая сессия имеет собственный сохраняемый план либо NONE. Канонические планы находятся в `.harness/plans/by-id/`; прежний `.harness/plans/todo-plan.md` сохраняется для совместимости и истории. Не выбирай план по глобальному последнему указателю. Старый CLI без адреса допустим лишь до появления привязанных/подготовленных планов. При NONE используй `docs/architecture/OVERVIEW.md`, `docs/MODULES.md` и `docs/DOCUMENTATION_INDEX.md` и обсуждай следующий этап существующего проекта.

Новый запрос сначала сопоставь с частью проекта в `docs/MODULES.md`; если её нет — сначала создай и согласуй specification/planning document. Для программного модуля фиксируй facade, входы/выходы, границы и инварианты; внутреннюю реализацию дроби на узкие классы/микроклассы. План реализует согласованный контракт.

Каждый рабочий план сохраняет три required-ссылки навигации и заканчивается задачей DOCS — «Актуализация всех документов проекта». После её commit сообщи результат пользователю. Выполненный план остаётся в сессии: новое поручение добавляется через plan:apply, прежние DONE-задачи/коммиты сохраняются, финальная DOCS открывается повторно. Обязательной кнопки приёмки нет.

Будущий план готовь через plan:prepare из текущей сессии. Это отдельный канонический план; свой план не заменяй. Пользователь создаёт сессию с ним через существующий выбор Chat/Work; отмена сохраняет черновик. Исходная сессия сохраняет ссылку на тот же план. Меню проекта создаёт самостоятельные Chat/Work с NONE.

Machine-managed поля меняются только командами Workflow Kit. Перед правкой начни task; каждую микрозадачу заверши workflow commit с проверками. Один пишущий агент на worktree, ожидаемая revision и транзакционные блокировки обязательны. Не обходи hooks, не удаляй/не откатывай посторонние изменения. Архивирование требует прямого поручения пользователя и не создаёт следующего scope или сессии автоматически.

Большой `.harness/kit/WORKFLOW.md` — справочник команд, repair и установки. Дополнительные документы бери через план/spec и индекс. В Windows PowerShell/CMD используй `./scripts/workflow.cmd`; в Git Bash/macOS — `./scripts/workflow`.
