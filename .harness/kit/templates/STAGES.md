# Формы остальных этапов Workflow Kit

Эти формы уже доставлены вместе с PLAN (to-do), SPEC (планировочный документ) и CONTINUE (расширение плана). Не запрашивай их повторно. Используй только нужные поля и этапы; это не требование создавать дополнительные документы или дробить работу.

## Выполнение и проверка микрозадачи

`./scripts/workflow task:start T001` → правки → `./scripts/workflow commit --task T001`. Подставь ID своей задачи; session selector не нужен. Коммит запускает указанные в задаче проверки и сохраняет их вывод; отдельный отчёт ради статуса не нужен. Не запускай заранее ту же проверку без причины.

Для упаковки или проверки установленной копии включи в checks входа plan:create такую форму, заменив команду и пути фактическими:

```json
{"id":"artifact","executable":"node","args":["scripts/check-artifact.mjs"],"kind":"installed","evidence":"<путь к выдаваемой копии>; <пользовательское действие и наблюдаемый результат>"}
```

В соответствующей задаче: `"checks":["artifact"],"verification_kind":"installed"`. Для проверки содержимого пакета используй `package` в обоих местах. Сам текст evidence не доказывает успех: команда должна проверять результат и завершаться с ошибкой при нарушении. Проверки выбирай под проект, Node.js не обязателен. При отказе исправь конкретную причину и повтори commit той же задачи; не начинай новый план.

## Документация и завершение DOCS

Сверь доставленные документы с результатом, сохрани существующую структуру. Ниже формы для отсутствующих или нуждающихся в дополнении разделов, а не повод переписать актуальные документы.

**docs/architecture/OVERVIEW.md**
```markdown
# Обзор проекта
## Назначение
<Пользовательский результат и границы.>
## Устройство
<Основные части, связи и принятые решения; фактические пути.>
## Запуск и проверка
<Команды или действия; где находится готовый результат.>
```

**docs/MODULES.md**
```markdown
# Модули проекта
| Часть | Путь | Назначение |
| --- | --- | --- |
| <название> | <путь> | <ответственность> |
```

**docs/DOCUMENTATION_INDEX.md**
```markdown
# Документы проекта
- [Обзор](architecture/OVERVIEW.md) — назначение и запуск.
- [Модули](MODULES.md) — карта частей проекта.
- [Планировочный документ](planning/<название>.md) — результат и критерии.
```

Обнови реальные ссылки. Новые документы перечисли в индексе. Начни DOCS через task:start и заверши `commit --task DOCS`, даже если проверка показала, что править документы не требуется. Kit ведёт статусы; не составляй второй to-do в Markdown. Если выявлена незавершённая работа, используй уже доставленную форму CONTINUE.

## Сообщение пользователю

«Готово: <результат>. Запуск: <путь или действие>. Проверено: <что фактически проверено>. <Оставшееся ограничение или требуемая ручная проверка, только если есть>».

Это форма ответа в чате, не обязательный новый файл. Не объявляй ручную приёмку пользователя выполненной. План остаётся доступным; новые поручения дополняют его по CONTINUE.
