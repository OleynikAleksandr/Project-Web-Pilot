# Архитектура / структура проекта

## Состояние

Глобальная структура проекта ещё не согласована. Документ является шаблоном и не объявляет заранее ни программную архитектуру, ни конкретный способ организации предметной работы.

## Общий замысел

После обсуждения с пользователем здесь фиксируются устойчивые границы проекта, основные части и связи между ними.

## Части и контракты

Самостоятельные части проекта регистрируются в `docs/MODULES.md` и получают собственные specification/planning documents. Для программного проекта модуль описывает facade, входы/выходы, границы и инварианты; внутреннюю реализацию следует дробить на узкие классы/микроклассы. Для непрограммного проекта используется естественная предметная декомпозиция без искусственной программной терминологии.

## Проверка результата

Способ проверки выбирается по типу проекта. Для программной разработки после выбора стека агент настраивает применимые команды через `workflow config:apply`; пустая конфигурация не означает успешных тестов. Для исследования, проектирования или другой предметной работы критерии проверки задаются соответствующим scope.
