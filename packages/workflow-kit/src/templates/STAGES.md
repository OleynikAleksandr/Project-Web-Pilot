# Формы проверки и документов

Процесс задачи, DOCS и выпуска задан Workflow Core; техника работы и Git — PROTOTYPE. Здесь только формы данных. Используй нужные поля без дополнительных обязательных файлов.

## Проверка выдаваемого результата

```json
{"id":"artifact","executable":"node","args":["scripts/check-artifact.mjs"],"kind":"installed","evidence":"<путь к выдаваемой копии>; <действие и наблюдаемый результат>"}
```

В задаче: `"checks":["artifact"],"verification_kind":"installed"`. Для пакета — `package` в обоих местах. Подставь фактическую команду проекта; Node не обязателен. Текст evidence описывает проверку, результат подтверждает её выполнение.

## OVERVIEW

```markdown
# Обзор проекта
## Назначение и устройство
<Результат, основные части, связи, постоянные ограничения.>
## Карта модулей
<Ссылки на действующие контракты и ответственность каждой части.>
## Запуск и проверка
<Краткие сведения и ссылки без повтора подробностей README и модулей.>
```

## Контракт модуля

```markdown
# <Модуль>
## Ответственность и поведение
<Текущая реализация и существенные причины действующих решений.>
## Контракт и зависимости
<Входы, выходы, ошибки, порядок вызовов; связи с другими модулями.>
## Проверка
<Команды и наблюдаемые результаты; необходимые живые проверки.>
```

## README

```markdown
# <Проект>
<Назначение для пользователя.>
## Версия
<Версия приложения.>
## Установка и запуск
<Необходимые действия и команды.>
```

## Ответ пользователю

«Готово: <результат>. Запуск: <действие>. Проверено: <фактические проверки>. <Существенное ограничение, если есть>».

Это сообщение в диалоге, не новый отчётный файл.
