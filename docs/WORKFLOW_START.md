# Начало работы

Project Web Pilot использует адресованный recovery Workflow Kit: пакет принадлежит sessionId и planId выбранной сессии. Прочитай уже доставленный контекст, кратко подтверди восстановление. Повторно запрашивать полный пакет для первого ответа не нужно.

Используй доставленный recovery capsule: он адресован конкретным sessionId и planId и содержит Workflow Core, цель, оставшиеся задачи и обязательную навигацию OVERVIEW, MODULES, DOCUMENTATION_INDEX. При отсутствии пакета выполни `./scripts/workflow recover --session <sessionId> --format text`. Во всех дальнейших командах сохраняй этот адрес.

1. При NONE обсуди следующий этап существующего проекта по общей структуре и индексу.
2. Найди затрагиваемую часть в MODULES и согласуй её specification/planning document. Для программного модуля определи facade, входы/выходы и инварианты.
3. Создай собственный план через scope:create либо продолжи существующий через plan:apply. Завершённые задачи и commit references сохраняются.
4. Перед изменениями выполни task:start, после каждой микрозадачи — управляемый commit с применимыми проверками. Одновременно пишет один агент.
5. Единственная последняя задача DOCS актуализирует все документы. После неё сообщи результат; выполненный план остаётся доступным и может быть продолжен новым поручением.
6. Будущее продолжение подготовь через plan:prepare. Пользователь создаст сессию через Chat/Work; отмена сохраняет план, исходная сессия сохраняет ссылку. Самостоятельные Chat/Work из меню получают NONE.
7. Завершение задач не архивирует план и не создаёт сессию. Архивирование выполняется только по прямому поручению пользователя.

Большой WORKFLOW.md и исторические документы читаются по необходимости. Планы других сессий можно читать параллельно, но просмотр не меняет адрес текущих команд.

## Разработка Project Web Pilot

Общий source macOS/Windows: https://github.com/OleynikAleksandr/Project-Web-Pilot. Mac — основная среда разработки; Windows native validation выполняется отдельно. Runtime, userData и платформенные сборки в Git не переносятся.

Встроенный Chromium показывает настоящий ChatGPT Web. Локальные действия доступны через MCP/tunnel; модельных API нет. Фасады и владельцы — docs/MODULES.md, контракт текущего этапа — docs/modules/first-run-onboarding.md.

Scope session-opening-performance-029 выполнен по прямому поручению пользователя до 0.6.29 / Kit 1.4.1. Быстрый показ собственного плана и чата, фоновая готовность и строгая доставка проверены на source и packaged приложении. Все изменения в main, лишние worktrees и временная ветка удалены. Текущий прогресс брать из адресованного плана; evidence — docs/VERIFICATION.md. Принятые собственные планы и ручной выбор продолжения сохраняются.

На старте checkout был 0.6.26, установленный app — 0.6.27. Сопоставление app.asar подтвердило единственное различие src/ui/index.html: тонкая обводка дерева; она сохранена при интеграции. Следующий выпуск и доказательства фиксируются в docs/RELEASE.md и docs/VERIFICATION.md.

Текущий план сохраняется в этой сессии после завершения задач. Архивирование не поручено. Новое поручение добавляет задачи и повторную DOCS через plan:apply; будущий план готовится через plan:prepare и открывается пользователем вручную.

## Проверки и выпуск

Обязательны Node suite и Electron smoke на изолированных fixtures. Реальные чаты/профили и пользовательские VM для разрушительных проверок не использовать. Контракт выпуска — docs/RELEASE.md: npm run build:mac обновляет постоянный Project Web Pilot.app в корне с сохранением identity папки и создаёт отдельный ZIP. Запущенное приложение получит обновление после полного выхода и повторного запуска.

Текущий scope first-run-onboarding-031 продолжается в своей сессии. После двух таймаутов 0.6.35 другой исходный клон успешно открыл сайт без Chrome и дополнительной перезагрузки; вход подтверждён. Пользователь поручил исправить следующую проблему — скрытое окно Apple. C010/C011/C012 и B006/R005 подготовили 0.6.37: установщик активируется через штатный open, при ошибке показа есть подсказка. Ранее подготовленная C009 направляет открытие без проекта прямо на /auth/login; это не доказательство устранения сетевого дефекта. Продолжение T017: на клоне без установленного компонента Apple нажать кнопку, убедиться, что окно спереди, затем пройти полный путь до тестового файла. Полные критерии прежних T014/T015/T016 сохранены в T017. Все клоны, по подтверждению пользователя, созданы до экспериментов. Computer Use отложен; финальная DOCS остаётся последней.

## Подготовка компонентов — актуальное исправление 0.6.37

В 0.6.37 устранён воспроизведённый отказ MAC_RUNTIME_EXTERNAL_MODIFIED после установки Apple: точный известный control.py из комплектного ZIP принимается через facade, собственная папка отличается от внешней. Завершённая установка используется повторно с сохранением настроек. Неизвестно изменённые файлы остаются защищены. Время Apple описано без обещания нескольких минут; ошибки подготовки больше не подменяются советом проверить интернет. Проверены холодная установка и восстановление отдельной ранее неудачной установки; гостевая проверка пользователем остаётся T017.
