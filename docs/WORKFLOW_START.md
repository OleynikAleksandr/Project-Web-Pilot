## Порядок восстановления

1. Открыть этот workspace как локальный проект Codex и начать новую сессию в нём. Полученные AGENTS и packet имеют приоритет перед историческими снимками документации.
2. Если актуальный packet отсутствует, выполнить `./scripts/workflow recover --format text`. Проверить COMPLETE и правильные project_id/workspace. Затем `./scripts/workflow status` для текущей задачи, Git и незавершённой транзакции.
3. Прочитать документы из context pack и нужные материалы через `docs/DOCUMENTATION_INDEX.md`: PRODUCT, DECISIONS, ARCHITECTURE, CONTEXT_DELIVERY, SOURCE_WORKSPACES, VERIFICATION.
4. Если есть поручение реализации, продолжить следующую разрешённую задачу через task:start. При одном запросе восстановить контекст сообщить факты и готовность продолжения, не запускать весь TODO автоматически.
5. Перед функциональными изменениями проверить профиль и реальные команды. Документы и код фиксировать вместе через workflow commit; статусы вручную не менять.

Если именно настоящий hook доставил DELIVERY-MARKER в дополнительном контексте, подтвердить его штатным hook:ack с фактическим клиентом. Не искать маркер в журнале ради отметки успешности. Обычный recover проверяет пакет, но не доставку hook. Диагностика установки — `./scripts/workflow doctor`.

## Две разные сессии

Сессия Codex, в которой разрабатывается Project Web Pilot, использует установленный в этой папке Workflow Kit и его hooks. Будущий встроенный ChatGPT внутри нашего продукта получает отдельное стартовое сообщение и работает с выбранным пользователем workspace через MCP. Доставка локального Codex hook не подтверждает работу внутреннего ChatGPT, и наоборот.
