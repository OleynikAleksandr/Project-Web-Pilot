## Пользовательский путь

1. Получить готовый пакет, понятно установить/распаковать и запустить приложение.
2. Увидеть короткое объяснение следующего действия; техническая подготовка выполняется автоматически, с понятным состоянием ожидания.
3. Выполнить только неизбежные личные действия: вход в аккаунт, выдача системного разрешения, выбор папки или ввод собственных данных подключения.
4. Для внешнего действия получить точную кнопку/ссылку, короткую инструкцию и проверку результата после возврата. Настройка туннеля включает получение необходимых данных: нельзя ограничиться необъяснённым полем «введите API key».
5. Создать первый проект, выбрать Chat/Work, получить доставленный контекст и подтверждение агента.
6. Выполнить разрешённое действие с тестовым файлом именно внутри гостя.
7. После перезапуска приложения и ОС продолжить работу с сохранёнными настройками.

До первого окна приложения используются минимальные сопровождающие подсказки поставки. Системные защитные диалоги проходят штатно, без отключения защиты как инструкции пользователю.

Нормальный путь не требует Terminal/PowerShell, ручной установки Node/Git/Python, знания MCP/портов/путей runtime или объяснений разработчика. Углублённая диагностика может быть отдельной, но не обязательной частью первого запуска. Личные входы и системные разрешения не имитируются и не подменяются автоматическими действиями.

## Уточнение пользователя: никаких предварительных условий

Первый запуск исходит из отсутствия прежнего входа или аккаунта ChatGPT, Node/Git/Python, MCP и настроенного туннеля. Отдельное приложение ChatGPT не устанавливается: Web Pilot использует встроенную веб-версию. Пользователю объясняются вход или создание аккаунта и доступность требуемого подключения; личные действия сопровождаются понятной инструкцией и проверкой результата.

При запуске проверяются необходимые компоненты и состояние подготовки. Автоматическая установка доступных технических компонентов, личный вход, настройка туннеля и подтверждение доступности инструментов являются отдельными этапами. Наличие веб-страницы не доказывает готовность инструментов, а отсутствие туннеля не должно объяснять любую ошибку загрузки сайта. Штатный путь не требует предварительно открыть ChatGPT в Safari или выполнить команды разработчика.

F001 добавляет проверку готовности поверх существующих facade, T004/T005 обеспечивают компоненты и runtime, T006/T007 дают последовательный интерфейс. Индикация задержки содержит понятное действие и повтор. Если обязательное внешнее условие недоступно, приложение сообщает конкретное препятствие и следующий допустимый шаг.

## Границы и facade

Первый запуск координируется тонким facade поверх существующих модулей. До изменения конкретного участка задачи фиксируют его точные входы/выходы; внутренние операции остаются небольшими и проверяемыми.

Входы: платформа и версия пакета, доступные bundled-компоненты, фактический runtime status/readiness, сохранённое состояние подготовки и явные действия пользователя. Выходы: текущий понятный шаг, прогресс, одно требуемое действие либо готовность; при отказе — конкретное сообщение и доступный повтор. UI получает только несекретное состояние.

Runtime Lifecycle владеет установкой компонентов, процессами и проверкой подключения; WorkspaceSetup — созданием/проверкой проекта; доставка — существующим COMPLETE recovery и Send. Мастер не дублирует эти механизмы и не выдаёт просмотр чата за готовность локальных инструментов. Точные UI-детали выбираются по первому наблюдаемому прохождению.

Инварианты:
- Готовность подтверждается фактическими проверками; устаревший успех не разрешает дальнейшую доставку.
- Повтор после ошибки/перезапуска продолжает подготовку, не теряет ввод и не создаёт дубликаты установок/проектов.
- При ожидании внешнего действия видны причина и следующий шаг; при сбое доступны повтор и безопасная диагностика.
- Секреты вводятся штатно, остаются в предназначенном приватном хранилище и исключаются из чата, Git, renderer-диагностики и отчётов.
- Наличие рабочего MCP основного Mac не считается подтверждением работы MCP гостя.

## Повторяемый цикл исправлений

Первый проход — macOS; после доведения основного пути проверяется Windows. На каждом проходе фиксируются версия/хеш пакета, ОС/архитектура, исходный клон, шаг, ожидание, фактический результат и требовавшаяся помощь.

Реестр наблюдений ведётся в docs/CLEAN_INSTALL.md, доказательства и границы — в docs/VERIFICATION.md. Это факты испытаний и ссылки на задачи канонического плана, не второй менеджер задач.

Каждая подтверждённая проблема получает конкретные микрозадачи: исправление с проверкой и документацией → новая проверенная сборка → повтор на новом клоне. Они добавляются через plan:apply с актуальной revision до следующего приёмочного шага и финальной DOCS. По умолчанию одна задача меняет не более трёх функциональных файлов; более широкое изменение предварительно дробится. Выполненные задачи и коммиты сохраняются. Число циклов заранее не ограничено.

Первоначальные задачи задают проверяемые части пути. Их пути и проверки уточняются до изменения по фактической причине ошибки. Если часть уже исправна, сохраняется доказательство проверки; искусственные правки ради коммита не создаются. Незавершённый пользовательский проход не отмечается DONE.

## Критерии завершения

- На свежих клонах полный путь от полученного пакета до действия агента с тестовым файлом пройден по подсказкам поставки и приложения.
- Обязательные компоненты подготавливаются приложением; внешние входы, разрешения и настройка подключения объяснены на нужном шаге.
- У пользователя нет необъяснённого ожидания, тупиков, скрытых предварительных требований и необходимости разбираться в техническом устройстве.
- Подтверждены сохранение настроек и продолжение после перезапуска; проверены фактически обнаруженные сбои и повтор.
- Финальные пакеты имеют прослеживаемое происхождение, проходят применимые проверки и соответствуют испытанной версии.
- macOS, Windows ARM64/x64-эмуляция и нативная Windows x64 имеют отдельные статусы доказательств. Непроверенная платформа не объявляется успешно проверенной.
- Пользователь подтверждает, что весь путь его устраивает; обновлена вся затронутая документация.
- План сохраняется в этой сессии. Архивирование — только по отдельной прямой команде пользователя.

## Первая итерация: релиз после MAC-001/MAC-002

Новый пользователь может не иметь ни аккаунта OpenAI/ChatGPT, ни истории посещения сайта. Мастер явно предлагает штатные «Войти» и «Создать аккаунт» на веб-странице ChatGPT; вход в Safari не является условием. Наличие поля сообщения в гостевом режиме не доказывает вход: используется наблюдаемая кнопка профиля, неизвестное состояние остаётся неподтверждённым.

Проверка и подготовка компонентов независимы от загрузки ChatGPT. Node.js 22.17.0 arm64 включается в пакет по официальному архиву с SHA-256; повторно используется установленный механизм extra-resource. Git проверяется без вызова системного установщика; при отсутствии кнопка открывает штатную установку Apple Command Line Tools с объяснением необходимых подтверждений, затем проверка повторяется. Пользователь не вводит команды и не ищет установщики.

StartupReadiness — небольшой coordinator: входы являются функциями probe компонентов, ensure существующего runtime и несекретными событиями страницы; выход — снимок проверок, текущий шаг/ошибка/действие. Операции сериализованы и повторяемы, завершённый старый запрос не меняет состояние после закрытия. macOS tunnel setup выполняется отдельным Python worker с нативными диалогами; секрет не возвращается в Electron и не передаётся аргументом команды. Существующий control facade и private store сохраняются.

UI состоит из самостоятельного startup view в сайдбаре, использующего существующие IPC guards. Он виден на новом профиле, отображает шаги до создания проекта и не скрывает действия за раскрываемыми техническими подробностями. После задержки загрузки доступны повтор/пояснение; фоновые результаты не перезаписывают текущее действие. Готовность локальных служб отличается от подключения плагина в аккаунте и реального действия агента.

Официальные источники проверены 17.09.2026:
- Node: https://nodejs.org/dist/v22.17.0/SHASUMS256.txt — macOS arm64 tar.gz SHA-256 615dda58b5fb41fad2be43940b6398ca56554cbe05800953afadc724729cb09e.
- Apple: https://developer.apple.com/library/archive/technotes/tn2339/_index.html — штатная установка Command Line Tools через xcode-select --install.
- OpenAI: https://developers.openai.com/api/docs/guides/secure-mcp-tunnels — создание туннеля, личный runtime key, связь с ChatGPT workspace и developer-mode подключение. Доступ к этим возможностям проверяется отдельно от существования аккаунта; не обещается доступность всем новым аккаунтам.

## Контракт C004 — ограниченное первое открытие

Существующий navigate использует узкую функцию openStartupPage(contents, url, options) только при открытии без проекта в пустом browser. Входы: WebContents, адрес, проверка текущей navigation generation, уведомление и тайм-аут; выход: первый DOM либо конкретная ошибка ограниченного ожидания. Внутри нет хранения аккаунтов, второго runtime или новой системы логирования.

До появления первого документа допускается одна автоматическая попытка после остановки старого запроса, закрытия соединений этой browser session и очистки только DNS-кэша штатными Electron API. После появления документа повтор не выполняется, cookies/сохранённый вход остаются. Все действия ограждаются navigation generation; новая навигация не прерывается старой. Смена IP вручную, обход TLS, отключение sandbox/GPU и смена User-Agent в поставку не входят. Готовность первого DOM позволяет отдельно наблюдать login controls, не ожидая всех дополнительных ресурсов. Локальные проверки не заменяют T015 на госте.

В поставке 0.6.34 пределы составляют 15 секунд на первый запрос, до 5 секунд на восстановление и до 15 секунд на повтор. Проверка аккаунта использует готовый DOM через mainFrame; этот сигнал не означает готовность инструментов или разрешение доставки контекста.

## Диагностический контракт 0.6.35

По новым отчётам 0.6.34 и поручению пользователя первоначальный запрос автоматически открывается один раз и ожидает первый DOM до 120 секунд. Через 15 секунд меняется только пояснение; соединения и DNS не сбрасываются. Повтор на время запроса блокируется и в интерфейсе, и в main. Существующие проекты сохраняют навигационный контракт.

ChromiumDiagnostics сохраняет начало и конец отчёта текущего процесса с числом пропущенных событий. Узкий StartupNetworkTrace использует штатный Electron netLog default только для начального открытия без проектов: вход — session.netLog и временный путь; выход — сводка этапов соединения и первого документа. Сырой файл ограничен размером и временем, после получения сводки удаляется. В копируемый отчёт входят только разрешённые имена этапов, фазы, интервалы, числовые ошибки и адреса соединения; заголовки, cookies, query, тела и значения полей исключаются. Необходимая проверка — непрерывный запрос в том же Test macOS 01; затем полный чистый T016. Windows-мастер не считается адаптированным.

## Показ установщика Apple — C010

Пользователь прошёл вход в ChatGPT в 0.6.35 и обнаружил следующий блокер: системное подтверждение установки Command Line Tools оказалось под окном Web Pilot. installMacGit после успешного xcode-select --install теперь вызывает /usr/bin/open -a с абсолютным путём штатного Install Command Line Developer Tools.app. LaunchServices выводит helper вперёд, не создаёт отдельную новую копию и не требует AppleScript/Accessibility. Источники: системная man open (обычный запуск активирует приложение, -g запрещает это) и Apple TN2339; наличие helper и его bundle identifier подтверждено чтением системного Info.plist. Открытый issue https://github.com/ShawHahnLab/chiimp/issues/54 подтверждает асинхронность установщика, но не считается доказательством исправления окна.

Вход функции — исполнитель системных команд, выход — успешно запрошенная установка/активация либо отдельное понятное сообщение об ошибке запуска или показа. После показа Git остаётся неподтверждённым до inspectMacGit. При ошибке активации есть инструкция свернуть Web Pilot и вернуться к проверке. Подтверждения и условия Apple пользователь принимает сам. Проверены порядок асинхронных действий, повторные нажатия, оба отказа и повтор; тесты используют подставной исполнитель, установщик основного Mac не запускается. Фактический передний план на чистой VM ожидает T017.

## Комплектный runtime после установки Apple — C011

На чистом клоне после завершения Apple Command Line Tools подготовка остановилась, после перезапуска показан MAC_RUNTIME_EXTERNAL_MODIFIED. Независимая холодная установка из фактического resources/mac-runtime.zip воспроизвела тот же код за 34.465 с: setup завершился, marker записан, но hash комплектного control.py (84a68f…58f9) отсутствовал в списке известных версий адаптера. Ошибка не доказывает проблему интернета или изменение файлов пользователем.

MacRuntimeBootstrap принимает эту точную поставляемую версию через существующий facade, возвращает facade также после первой установки и отличает собственную папку от внешней. Повторный запуск использует завершённую установку и её настройки. Неизвестный внешний control.py и изменённый комплектный файл по-прежнему блокируются; одного marker недостаточно для доверия. Управляемый Python получает явно заданное окружение. Регрессия использует реальный ZIP, проверяет первый запуск, повтор после регистрации собственной папки и отказ для изменённых файлов. Основной MCP и профиль не меняются.

## Ожидание и ошибки подготовки — C012

Пользователь сообщил о загрузке Apple дольше двадцати минут. Onboarding больше не обещает «несколько минут»: предупреждает о возможных десятках минут и указывает системное окно Apple как источник хода установки. После запроса установки показано ожидание её завершения; после ошибки — «Подготовка остановлена», а не продолжающаяся работа.

StartupReadiness отображает безопасные заранее заданные объяснения известных ошибок и их код, не raw stderr/аргументы. Неизвестный сбой не объявляется проблемой интернета. Повторная проверка сохраняет уже пройденный Git; при подготовке локальных инструментов описаны ожидание и следующий шаг. Проверены отказ MAC_RUNTIME_EXTERNAL_MODIFIED, успешный повтор и отсутствие утечки произвольных сообщений/кодов.

## Исправления новой сессии — first-run-corrections-032 / 0.6.38

18.09.2026 в WebPilot-Test-macOS 02 подтверждены вход и переход «Компоненты готовы» после установки Apple. Ошибка MAC_RUNTIME_EXTERNAL_MODIFIED не повторилась. Показ установщика Apple по-прежнему потребовал ручного открытия скрытого окна. После создания отдельного туннеля кнопка ввода воспроизводимо завершалась ошибкой до появления первого поля.

Пользователь поручил исправить ввод, убрать оставшуюся кнопку установки Apple и выпустить новый релиз для свежего клона. В новой сессии 01a0b318-cc66-7743-9de7-696f05fff6e6 был NONE, поэтому создан собственный план first-run-corrections-032 по этому контракту; first-run-onboarding-031 сохраняет прежнего владельца и незавершённые задачи полного пути. Computer Use для тестовой VM прямо разрешён пользователем в этой сессии.

T001 сохраняет Unicode в строках AppleScript вместо JSON-последовательностей \\u, которые системный компилятор отклоняет с -2741. Оба окна проходят реальный osacompile; ключ остаётся скрытым, отмена не сохраняет данные. Worker выдаёт только известный код отказа открытия окна, неверных данных либо сохранения, без аргументов, stdout окна и секретов. Дальнейшая часть интерфейса отображает код через фиксированные безопасные сообщения. Проверка ввода на свежем клоне после выпуска остаётся отдельным пользовательским результатом.

T002 переводит только известные коды worker в фиксированные пользовательские сообщения: отказ открытия окна, неверный формат и общий отказ настройки различимы. Произвольный stderr, stdout и неизвестные коды не отображаются. После отмены доступен повтор; успешный результат продолжает существующую проверку подключения.

T003: успешный запрос Apple и отказ вывода её окна разделены. Отказ фокуса становится предупреждением при продолжающейся установке; повторный запуск исключён. После запроса выполняется последовательная фоновая проверка Git с паузой 5 секунд, максимум 720 попыток. Успех переводит шаг в «Компонент Apple установлен» и оставляет явную проверку/подготовку; сам runtime автоматически не подготавливается. Ручная проверка и закрытие facade отменяют устаревшие результаты. По исчерпании попыток доступна ручная проверка, а при отменённой установке — повторный запуск.

## Принятый чистый запуск и интерфейс 0.6.39

18.09.2026 пользователь прямо подтвердил весь первый запуск 0.6.38 на абсолютно
чистой macOS без ошибок. Его снимок 09.05.19 показывает My_Test_001, доставленный
контекст и ответ агента. Это пользовательская приёмка macOS onboarding; она не
подменяет отдельную проверку Windows.

Новое поручение продолжает first-run-corrections-032: один текст NONE; понятные
и автоматически сменяющиеся шаги туннеля; условная помощь Plugins; создание
первого проекта одним нажатием Chat/Work; диагностика при обнаруженной проблеме.

По уточнению пользователя переходы не требуют «сохранено/скопировано».
`TunnelClipboard` — узкий facade основного процесса: входы — доступность шага,
чтение clipboard и configure callback; выход — только step/hasTunnelId. Пока
мастер подключения открыт после входа и подготовки компонентов, он распознаёт
новый `tunnel_…`, затем новый `sk-…`. Исходное содержимое буфера не применяется.
ID удерживается в памяти, ключ передаётся worker через stdin и исключается из
renderer, аргументов процессов, environment и журналов. Закрытие шага/окна
останавливает чтение и очищает память. Автоматическое завершение подтверждается
runtime readiness, а не одной формой строки. Ошибка оставляет ручной ввод и
возможность повторного копирования. Основной рабочий туннель не заменяется
автоматически: сохраняется защита runtime.

Тексты опираются на официальные инструкции:
https://developers.openai.com/api/docs/guides/secure-mcp-tunnels и
https://developers.openai.com/plugins/deploy/connect-chatgpt (прочитаны 18.09).
Read/Manage для создания и Read/Use для работы различаются. Документы описывают
добавление плагина, но не доказывают, почему он уже присутствовал у пользователя.
Поэтому помощь условная: уже настроенное подключение повторно добавлять не нужно;
наличие названия плагина не доказывает его связь с новым туннелем.

U002: карточка NONE оставляет только статус «План ещё не создан»; пустой заголовок
скрыт. При появлении scope заголовок снова показывает цель плана.

### 0.6.39 — A001: Защищённый ввод для worker

mac-first-run принимает ограниченный JSON через stdin. Переданные ID/ключ не вызывают повторные окна; при одном ID остаётся защищённое поле ключа. Прежний ручной сценарий сохранён.

### 0.6.39 — A002: Передача данных в runtime

MacRuntimeBootstrap.configureTunnel принимает необязательные credentials. Новый исполнитель передаёт их только через stdin, без аргументов и environment; ошибки остаются allowlisted.

### 0.6.39 — A003: Распознавание буфера

TunnelClipboard работает только в основном процессе. Начальное содержимое игнорируется; новый tunnel_ переводит к ключу, новый sk- запускает одну настройку. В renderer передаются только стадия, признак ID и безопасная ошибка.

### 0.6.39 — A004: Подключение автоматики к мастеру

Основной процесс опрашивает буфер только на активном шаге macOS после входа и готовности компонентов. Выход из шага и закрытие окна очищают состояние. Уже полученный ID используется при ручном вводе. Успех требует готового туннеля.

### 0.6.39 — U003: Последовательные подсказки туннеля

Первый шаг объясняет создание и копирование ID, второй — API keys, Read/Use и копирование ключа. Подтверждающих кнопок нет; завершённые шаги скрываются. Ручной ввод остаётся запасным действием, следующий этап прокручивается в видимую область.

### 0.6.39 — U004: Условная помощь Plugins

После готового туннеля основное действие — создание проекта. Инструкция добавления или проверки подключения ChatGPT находится в закрытой подсказке; повторное добавление существующего подключения не требуется.
