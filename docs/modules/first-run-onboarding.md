# Первый запуск и начальная настройка

Мастер «Начнём работу» в сайдбаре ведёт пользователя macOS или Windows от запуска пакета до первого проекта: вход в ChatGPT → подготовка компьютера → туннель → подключение в ChatGPT → проект. Это тонкий координатор поверх служб исполнителя ([runtime-lifecycle.md](runtime-lifecycle.md)) и подготовки проектов ([workspace-setup.md](workspace-setup.md)); своего установщика у него нет. Здесь же — протокол ручной проверки чистой установки.

## Код
- `src/startup-readiness.mjs` (`StartupReadiness`, `inspectMacGit`, `installMacGit`, `offerMacInstallation`; внутренняя таблица `PREPARATION_ERRORS`), `src/startup-platform.mjs` (`startupSupported`, `startupPlatformOptions`).
- `src/browser-startup.mjs` (`openStartupPage`), `src/startup-network-trace.mjs` (`StartupNetworkTrace`), `ChromiumDiagnostics.startupReport()` ([chromium-diagnostics.md](chromium-diagnostics.md)).
- `src/tunnel-clipboard.mjs`, `src/tunnel-setup.mjs` (`TUNNEL_ID_PATTERN`, `runTunnelHelper`), `tools/codex-app-server-mcp/tunnel_prompt.py`; тексты и `configureTunnel` — `src/mac-runtime-switch.mjs`; компоненты Windows — `src/windows-runtime.mjs`.
- `src/ui/startup.mjs`, `#startup-panel` в `src/ui/index.html`; в `src/main.mjs` — `createStartupFlow`, `startupAction` (IPC `pilot:startup`), первое открытие в `navigate`; признаки входа — `src/chatgpt-page-observer.mjs`.

## Поведение

### Цель (требование пользователя)
Путь от пакета до действия агента с тестовым файлом проходится только по подсказкам приложения: без устных инструкций, Terminal/PowerShell (кроме установки Codex CLI на Windows готовой командой), ручной установки Node/Git/Python и знания MCP, портов, путей. Исходно может не быть аккаунта ChatGPT, Node, Git, Python, MCP, туннеля; приложение ChatGPT и вход в Safari не нужны; доступ к Tunnels и developer mode не обещается. Пользователь делает только личные действия (вход, системные подтверждения, туннель и ключ, выбор папки) — с кнопкой, инструкцией и проверкой; они не имитируются, защиту ОС отключать не предлагается.

### Запуск мастера
- Только darwin и win32 вне TEST FIXTURE: в `--smoke` мастер выключен, чтобы smoke не ставил службы разработчику.
- Открывается сам при пустом списке проектов, иначе — «Начальная настройка» внизу сайдбара (готовые компоненты и туннель сохраняются; службы после настройки живут без окна — [runtime-lifecycle.md](runtime-lifecycle.md)). При создании окна — `check({ prepare: startupActive })`: без проектов подготовка идёт сразу, не дожидаясь входа.
- IPC `pilot:startup`: `show | check | install-git | paste-tunnel-id | configure-tunnel | copy-diagnostics | chat | signup | plugins | tunnels | keys | help | continue`; кроме `show`, всё требует открытого мастера. ChatGPT и Plugins — во встроенном браузере; Tunnels, API keys и инструкция Secure MCP Tunnel — в системном (`shell.openExternal`).

### Состояние
`snapshot()` несекретный (фаза, флаги готовности, вход, страница, ошибка; main добавляет `clipboard`, `active`). Операции сериализованы, после закрытия окна поздние результаты не публикуются. Готовность — только по факту: `runtime = mcp.ready`, `tunnel = tunnel.ready && tunnel.configured` (до первой активации статус не читается, после неудачной — читается); страница ≠ службы ≠ подключение в аккаунте ≠ действие с файлом. Шаги 3–5 и подробности шага 2 видны только после подтверждённого входа.

### Шаг 1. ChatGPT и вход
- Без проекта первая навигация, повтор и регистрация — `https://chatgpt.com/auth/login` (явный `entryUrl` важнее), потому что в чистом профиле `/` непостоянно зависала (запрос уходит, ответа нет; повтор не помогает), а прямой вход открывался быстро. Это обход, причина не установлена.
- `openStartupPage` (нет проекта, пустой `webContents`): один `loadURL`, первый DOM до 120 с, `dom-ready` завершает ожидание. Через 15 с меняется только пояснение; соединения и DNS не сбрасываются, автоповтора нет. Срок — `PAGE_RESPONSE_TIMEOUT` (документа нет, запрос останавливается) или `PAGE_DOCUMENT_TIMEOUT`. Во время ожидания повтор заблокирован в UI и main, после отказа — «Повторить открытие». Текст ошибки — по коду, иначе общий.
- Вход по page observer (только на `https://chatgpt.com`): кнопки login/signup или ссылка `/auth/login` → `signed-out`; кнопка профиля → `signed-in`; иначе `unknown` = не подтверждено (гостевой composer вход не доказывает). Указания «Войти / Зарегистрироваться» — только после наблюдаемого экрана входа.

### Диагностика первого открытия
- Журнал стартует до первого `loadURL`. «Скопировать диагностику» (с начала открытия, нужна и при успехе) кладёт в буфер JSON: первые ≤31 и последние ≤30 стартовых событий, `eventsOmitted`, сводку сети.
- `StartupNetworkTrace` — только при запуске без проектов и не в smoke: `netLog` `captureMode: default` во временный `diagnostics/startup-network.json` (0600), стоп на 4 MiB (опрос 250 мс) или через 125 с, >8 MiB не разбирается, сырой файл удаляется всегда. `maxFileSize` не используется: ограниченному экспорту Chromium нужна временная папка, недоступная в sandbox сетевого сервиса, а sandbox не отключается. Сводка — этапы DNS/TCP/TLS/HTTP запросов `/` и `/auth/login` (время, `net_error`, IP, статус), без заголовков, cookies, query.

### Шаг 2. Подготовка компьютера
`probe`: встроенный Node (отказ → «скопируйте полное приложение в Applications» / «распакуйте Windows ZIP полностью») → Git → службы. «Проверить и продолжить» при неготовых MCP или туннеле: `activateRuntime` → `status` → `start` (`--mcp-only`, пока туннель не настроен). Готовые службы не перенастраиваются.

macOS:
- Git: `/usr/bin/xcode-select -p`, и только при абсолютном пути — `/usr/bin/git --version`, потому что шим `/usr/bin/git` без Command Line Tools открывает системный диалог. До Git службы не трогаются (`/usr/bin/python3` без CLT — тоже заглушка Apple).
- «Установить компонент Apple»: `xcode-select --install`, затем `/usr/bin/open -a "/System/Library/CoreServices/Install Command Line Developer Tools.app"` — окно Apple выходит вперёд без AppleScript и Accessibility. Если окно не вывелось — предупреждение «сверните Web Pilot жёлтой кнопкой»; установка считается запрошенной и не дублируется.
- Пока установка идёт, кнопка скрыта; Git проверяется каждые 5 с до 720 раз. Найден — «Компонент Apple установлен», службы готовит только «Проверить и продолжить»; попытки исчерпаны — ручная проверка или новый запуск. Текст: установка «может занять десятки минут» (бывает дольше 20 мин). Подготовка служб (`control.py setup`) требует интернета.

Windows: до Git — `prepareComponents` (`WindowsExecutorBootstrap.ensure()`: uv, tunnel-client, ripgrep, MinGit из архива пакета и свой Python 3.13; первый раз — интернет). «Git готов» = инструменты распакованы, MinGit идёт в Workflow Kit через окружение. Системные Git/Node/Python не нужны, Mac-подсказок нет; коды `WINDOWS_RUNTIME_*`, `WINDOWS_GIT_*`.

Обе ОС:
- Нет Codex → `MAC_CODEX_NOT_FOUND` / `WINDOWS_CODEX_NOT_FOUND` до загрузок: Mac — «Установите Codex CLI или приложение ChatGPT»; Windows — команда `powershell -ExecutionPolicy ByPass -c "irm https://chatgpt.com/codex/install.ps1 | iex"`. Мастер Codex не ставит.
- Ошибка — только заранее заданный текст с кодом из `PREPARATION_ERRORS` или `publicMessage`; raw stderr, аргументы и неизвестные коды не выводятся, потому что в них бывают секреты. Неизвестный сбой — нейтральный текст, не «проблема интернета». После ошибки — «Подготовка остановлена»; готовое при повторе не переустанавливается.

### Шаг 3. Туннель
Виден после входа и готовности компонентов и MCP, пока туннель не готов. Каждому компьютеру — свой туннель; подключения Mac и Windows раздельны. Подшаги идут по одному, завершённые скрываются.
1. ID: «Открыть Tunnels в OpenAI Platform» → создать туннель, связать с пространством ChatGPT → Copy tunnel ID; Web Pilot сам замечает ID в буфере. Запасной путь «Вставить ID туннеля» — всегда системное окно (буфер не читается), отмена оставляет шаг без ошибки.
2. Ключ (кнопка скрыта до ID): «Открыть API keys» → та же организация → Create new secret key → Copy полного `sk-…`, не имени и не ID; замечается автоматически, запасной путь — «Ввести API key» (скрытое поле, ID заново не вводится). Права: создать туннель — Tunnels Read + Manage, работать — Read + Use.

`TunnelClipboard` (только main; renderer видит `step | hasTunnelId | error`):
- Буфер читается раз в 500 мс, только если мастер открыт без формы проекта и настроек, вход подтверждён, компоненты и MCP готовы, туннель не готов и нет операции; уход с шага очищает память.
- Первое значение — точка отсчёта, не применяется; дальше сравниваются SHA-256. Новый `tunnel_…` (`TUNNEL_ID_PATTERN = /^tunnel_[A-Za-z0-9_-]{16,100}$/`, общий с Python) → шаг ключа. Новый `^sk-[A-Za-z0-9_-]{16,4093}$` при наличии ID → одна настройка; успех — только при готовом туннеле, иначе «Подключение не подтверждено…»; ключ стирается после попытки.
- Ручной ввод и опрос взаимоисключающие; после закрытия окна ввода буфер снова берётся точкой отсчёта, поэтому копирование внутри окна, даже отменённого, подключение не запускает.

Секреты:
- `tunnel_prompt.py --tunnel-id` — одно окно и проверка формата, ничего не пишет; `--stdin` — JSON `{tunnel_id, api_key?}` ≤8192 байт, недостающее спрашивается окном (ключ скрыт). Окна: macOS — `osascript` со строками Unicode (`\u`-экранирование AppleScript не понимает, ошибка -2741), Windows — WinForms. ID и ключ не попадают в argv, environment, stdout, renderer, диагностику, Git, чат.
- Запись — `configure_tunnel` под `operation_lock`; свой запущенный tunnel-client сначала останавливается. Если ключ отозван или туннель удалён, активация падает на ожидании туннеля, но MCP работает: после такой попытки (`activationAttempted`) мастер читает статус служб, показывает шаг 3, а `configureTunnel` при готовом MCP не блокируется ошибкой активации — ID и ключ вводятся заново.
- Отказ — только код `MAC_|WINDOWS_` + `TUNNEL_ID_INVALID | TUNNEL_PROMPT_FAILED | TUNNEL_INVALID_DATA | TUNNEL_SETUP_FAILED` с фиксированным текстом. Если туннель не запустился, работающий MCP сохраняет шаг ввода и ID.

### Шаг 4. Подключение в ChatGPT
Виден только при готовом туннеле. Подключение в аккаунте само не появляется, Web Pilot его не проверяет.
- Plugins в основном сайдбаре ChatGPT (кнопка открывает `https://chatgpt.com/plugins`) → «+» → имя `Codex App Server Local Mac` / `… Windows` → Connection: Tunnel → туннель этого компьютера → No authentication → дождаться списка инструментов.
- Существующее правильное подключение не пересоздавать; на Windows прежнее «Codex Local Windows MCP» с тем же туннелем — Refresh. Название не доказывает связь с туннелем, подключение Mac не подтверждает Windows. Справка: Settings → Security and login → Developer mode.
- «Разрешения MCP» (решение пользователя): Settings → Plugins → своё подключение → Permissions; Always ask / Allow read actions / Allow low-risk actions (по умолчанию) / Allow all actions. Allow all actions — добровольный удобный выбор; приложение настройки аккаунта не меняет, ограничения ChatGPT сохраняются.

### Шаг 5. Первый проект
- «Создать новый проект» или «Добавить существующую папку» (системный выбор, read-only preview, подготовка с подтверждением). Оба начинают с `continue`: перепроверка готовности и входа, иначе «Завершите вход и проверку подключения…»; при успехе мастер закрывается. Отмена возвращает в мастер; фиктивный пустой проект не нужен.
- Автор и email не спрашиваются; без Git identity worker передаёт Kit `Web Pilot` / `web-pilot@localhost`, выбор не блокируется. Расположение проектов и Chat/Work — [workspace-setup.md](workspace-setup.md).
- Подсказки: в новом чате добавить подключение через меню инструментов и попросить агента изменить тестовый файл; доступ подтверждает сохранённый файл, а не туннель или доставка контекста.

### macOS: перенос в «Программы»
Упакованное приложение без проектов вне Applications спрашивает «Установить Web Pilot в «Программы»?»: согласие — `app.moveToApplicationsFolder` с перезапуском; существующая копия заменяется только после отдельного вопроса (по умолчанию «Отмена»), данные сохраняются. Отказ или сбой — работа из текущей папки, вопрос повторится при следующем запуске без проектов.

## Решения и запреты
- Второй установщик или менеджер runtime не вводить: параллельный механизм разойдётся с действующими службами.
- Ключ — отдельным видимым шагом после ID, чтобы пользователь сначала увидел инструкцию API keys. Переустановку Apple и чистку настроек не предлагать — сначала довести начатую установку.
- Не возвращать:
  - сброс соединений и DNS, автоповтор и сроки «15 с + 5 с + 15 с» при первом открытии — не помогали и маскировали сбой;
  - закрепление IP ChatGPT, смену TLS, sandbox, GPU, User-Agent, заголовков или cookies ради старта — сетевая причина не доказана;
  - кнопки «ID сохранён / ключ скопирован» (уточнение пользователя), чтение буфера по кнопке «Вставить ID туннеля», поле ключа в renderer;
  - AppleScript/Accessibility для окна Apple; обещание «несколько минут»; «проверьте интернет» при неизвестной ошибке;
  - вопрос об авторе и email; блокировку Chat/Work без Git identity; выбор режима Permissions за пользователя.

## Проверки
- Автоматические (`unit-all`): `tests/` `startup-*`, `browser-startup`, `tunnel-*`, `chromium-diagnostics`, `mac-runtime-switch`, `windows-runtime`. `electron-smoke` мастер не проходит, `src/main.mjs` unit-тестами не покрыт. Подставные исполнители не доказывают окно Apple, системные диалоги, буфер, выбор папки; Windows-код на Mac проверен только подменой платформы.

### Протокол чистой установки (ручной)
- Выполняет пользователь; агент VM не запускает и Computer Use не использует, а готовит исправления и пакеты.
- Стенд UTM: macOS-гость — Apple Virtualization, 4 CPU / 12 GiB / 64 GiB; Windows 11 ARM64 — официальный ISO (CrystalFetch). Папка `~/Documents/WebPilot-Test-Lab/` вне Git. Clean — резерв, Base — эталон (в нём не испытывают), Test — клоны; каждый проход — новый клон Base после штатного выключения, чистота гостя подтверждается до прохода.
- Изоляция: общая папка — только доставка ZIP; распаковка на внутреннем диске гостя со сверкой SHA-256 (неполная копия, например оборванная `0x800700DF`, не засчитывается). В гостя не переносятся Node, Git, MCP, профили, ключи, проекты; недостающий компонент — результат, а не повод доустановить. Туннель, MCP и профиль основного Mac не меняются; ключи не попадают в документы, Git, сообщения, снимки.
- Порядок: ОС гостя (версия, архитектура, нет следов Web Pilot) → версия и SHA-256 поставки → запуск с записью каждого сообщения → вход → подготовка (с Codex и без) → ID → ключ → подключение → Permissions → проект → агент меняет тестовый файл через подключение этого компьютера → перезапуск приложения и ОС (настройки целы, MCP доступен без Web Pilot). На шаг: ожидаемое, фактическое, участие пользователя, подсказка.
- Не доказывают проход: сборка, fixture, проверки на основном Mac и его MCP, служба туннеля или имя плагина, подключение в списке без записи файла. macOS, Windows ARM64 (эмуляция x64) и нативная x64 — раздельные статусы.
- Цикл: наблюдение → микрозадачи → проверенная сборка → новый клон → повтор; затруднение записывается до обхода. Завершение: путь пройден по подсказкам без тупиков, продолжение после перезапуска подтверждено, пакеты прослеживаются до испытанной версии, пользователь подтверждает.

## Открыто
- Чистая macOS с исполнителем Codex App Server не проверена (без CLT и Codex, затем с ними); запуск служб при входе после перезагрузки не подтверждён.
- Настоящая Windows: мастер с исполнителем не запускался, нативная x64 — ни разу. Приёмка пользователем: загрузка Python, антивирус, WinForms и DPAPI, переход с прежнего сервера инструментов, проект, запись тестового файла, MCP без Web Pilot после перезагрузки; также обновление задач без переоткрытия сессии, цвет поля ввода, скрытие служебных карточек, ручная прокрутка, обе кнопки шага 5.
- Вывод окна Apple поверх Web Pilot на чистой VM не подтверждён.
- На объединённом экране «Log in or sign up» состояние может остаться `unknown` без подсказок «Войти / Зарегистрироваться»; для текущей страницы входа не проверено.
- Вход через Google во встроенном Chromium может ограничиваться политикой Google для embedded user agents; проверяется только вживую.
- macOS-сборка подписывается сертификатом Apple Development без нотаризации (`scripts/sign-mac-bundle.mjs`): поведение Gatekeeper на чистом Mac для ZIP из интернета и подсказки к нему не проверены.
