# Параллельное выполнение задач

Web Pilot выдаёт задачи опубликованного плана отдельным Chat/Work в управляемых Git worktree. Основной чат планирует и получает явные поручения исправить интеграцию; Kit хранит один общий план в main и проверяет результаты. Это работа через веб-аккаунт ChatGPT и штатный MCP, без модельных API, новой службы, БД, промежуточной ветки и ревью кода.

## Код и границы

`src/parallel-settings.mjs` нормализует настройку; `workspace-session.mjs` сохраняет снимок и связи; `parallel-execution.mjs` управляет выдачей и очередью main; `parallel-kit.mjs` вызывает Kit; `executor-session.mjs` ведёт отдельный AutoPlan исполнителя; `execution-projection.mjs` и `agent-timer.mjs` дают состояния и часы. Защищённые действия и представление — `main.mjs`, `preload.cjs`, `ui/sidebar.mjs`, `ui/settings-panel.mjs`.

Git-операции и доказательства — [назначения Kit](../../packages/workflow-kit/docs/modules/parallel-assignments.md). Страницы и доставка — [живые сессии](session-runtime.md), [контекст](context-delivery.md). Ручной протокол — [приёмка](parallel-execution-acceptance.md).

## Настройки и происхождение

Settings предлагает «Разрешить параллельное выполнение», по умолчанию OFF, и лимит 2. Лимит — положительное безопасное целое, без произвольного верхнего порога; неверный ввод отклоняется, 1 означает последовательный режим.

При создании новой основной сессии сохраняется неизменный `executionSnapshot`. Смена Settings, перезапуск и повторное открытие его не меняют. Исполнитель наследует снимок и Chat/Work основной сессии. Новый чат при существующем ACTIVE продолжает общий план с прежними параметрами; новый снимок относится лишь к следующему новому плану. Старые сессии и планы без полей сохраняют последовательный путь.

План фиксирует `parallel_allowed`, `max_workers`, `execution_strategy` и `execution_reason`. Разрешение не обязывает распараллеливать: агент и рецензент оценивают пользу, семантические зависимости и пересечения. Если выбрано sequential, задачи выполняет основной чат без worktree. В parallel все обычные задачи, включая исключительные и последовательные участки, получают исполнителя.

`execution_origin_session_id` из стартового сообщения обозначает происхождение снимка, не владельца плана и не получателя Review. Перед выдачей приложение находит именно эту сохранённую сессию и сверяет разрешение и лимит с планом. Выбранная строка сайдбара, текущие Settings и чужой чат не заменяют происхождение. Неизвестная связь или несовпадение блокирует выдачу с причиной. `recipient_session_id` Review остаётся отдельным адресатом продолжения.

## Выдача

AutoPlan выбранного проекта — единственный переключатель выполнения. По умолчанию новый scope начинает с OFF; явное включение до первого плана сохраняет ожидание его публикации. После публикации ON запускает первую и следующие готовые группы, OFF прекращает новые назначения и отправки. Уже начатые команды и проверенная интеграция готовых результатов могут завершиться. После последней подтверждённой интеграции AutoPlan проекта сохраняется OFF. Settings только разрешает выбор стратегии, сам работу не запускает.

Обычный AutoPlan основного parallel-чата не посылает ему задачи исполнителей. Каждая задача, включая общую основу, получает назначение. Kit отклоняет task:start в main до изменений. У исполнителя собственные контроллер, журнал и монитор; первоначальная доставка recovery и продолжения требуют разрешения родительского проекта, локальный DONE прекращает продолжения. Скрытые основные последовательные чаты также продолжаются независимо.

Прежний ошибочный main-старт восстанавливается автоматически при ON, остановившемся основном чате без черновика и отсутствии активной команды. Приложение сохраняет ID, вызывает assignment:handoff и открывает единственное назначение с перенесёнными файлами. Точный контракт допустимого восстановления, сохранённых снимков и повторов — [назначения Kit](../../packages/workflow-kit/docs/modules/parallel-assignments.md). Неподходящий состав не очищается.

Готовность вычисляется по зависимостям, волны не хранятся. Нужны подтверждённые интеграции предшественников, свободное место и непересекающиеся functional/documentation paths. `parallel_safe=false` — исключительный барьер: ждёт интеграции ранее выданных задач и не допускает соседних запусков. Разные файлы сами по себе не доказывают смысловую независимость.

Занятые назначения, ожидание пользователя, восстановление и UNKNOWN учитываются в лимите. Готовый и наблюдаемо остановившийся исполнитель освобождает слот; это не снимает барьер пересекающихся областей и зависимостей. Новый worktree получает текущий подтверждённый HEAD main. `assignment:create/setup` готовит его окружение; npm ci выполняется по собственному lockfile, node_modules из main не копируются и не связываются symlink. NEEDS_SETUP виден до запуска чата.

Назначение и ID сохраняются до создания worktree, отправки и начала интеграции. `ensureExecutor` адресует сохранённую сессию по parent scope/task/assignment/workspace/origin, не меняя текущий выбор. Recovery исполнителя поручает прочесть все вложения, вызвать task:start, выполнить только назначенную задачу, завершить commit с проверками и закончить ответ. Нового пользовательского плана, вложенных агентов или локального Review нет.

## Очередь main

На основной checkout одна последовательная очередь. Готовые результаты идут по времени готовности, при равенстве — по порядку плана; более ранняя незавершённая независимая задача не задерживает готовую.

Перед интеграцией требуются точный проверенный source SHA, чистый worktree без транзакции, финальный остановившийся ответ собственного чата, отсутствие чужого Composer/доставки и опасной либо неизвестной команды. Main также чистый, свободный и наблюдаемо готовый. [Жизненный цикл команд](command-activity.md) различает running/completed/unknown и подтверждённый read-only сервер: он не блокирует интеграцию, но блокирует удаление. Завершение команды фиксируется событием App Server без обязательного write_stdin; имя команды не определяет безопасность.

Kit готовит merge, формирует общий план, проверяет объединённый кандидат и создаёт двухродительский коммит. Только подтверждённые source и integration SHA дают DONE основного плана. Промежуточная staged-проекция этого не доказывает: `projectVerifiedPlan` скрывает неподтверждённый DONE.

Конфликт или провал проверок сохраняет незавершённую интеграцию и блокирует новые группы/слияния. При AutoPlan ON очередь сама передаёт одно поручение именно основному чату с cwd, ID операции, причиной сбоя и integration:continue; отдельной кнопки нет. OFF запрещает новую передачу. Ошибка запуска проверки с exit_code=null показывается отдельно как INTEGRATION_CHECK_START_FAILED и не передаётся агенту как конфликт кода. Действие ждёт текущую сверку, проверяет готовность чата и активные команды, сохраняет попытку до Send. Собственная вставка и inFlight Composer допустимы после начального допуска; чужой черновик, генерация и смена чата блокируют отправку. События во время отправки сводятся к последующей сверке. UNKNOWN не повторяется.

## Сохранение и восстановление

`parallelExecutionBook` индексируется workspace/scope и проверяет projectId. Хранит назначения, исправления, отдельные `diagnostic` и `finalization` (pending/sending/sent/unknown/reply-observed), привязанные к scope, projectId и точному исходному основному Session ID. В diagnostic также сохраняются assignment, source SHA и blocker с ID операции/worktree/причиной. Это журнал координации, не копия плана и не доказательство Git. Одна очередь обслуживает и diagnostic, и correction, и final; она не создаёт второго планировщика.

## Финальное поручение

**SourceReady** — доказанный исходный Kit-коммит и оконченный ответ исполнителя, независимо от разрешения интеграции. **MergeSafe** дополнительно требует чистых child/main, отсутствия конфликтующей транзакции/команды и подтверждённой identity. **DiagnosticEligible** допускает одну безопасную передачу фактов о блокере при уже проверенном source, но не запись main. **FinalEligible** учитывает сохранённое разрешение отправки, identity и отсутствие конкурирующей операции; это не разрешение объявить DONE без Kit.

Когда каждая задача DONE или имеет проверенный READY_FOR_INTEGRATION, ещё до последнего merge очередь сохраняет pending финала. При write-команде последнего исполнителя merge остаётся запрещён, но допустима одна **диагностическая отправка** основному чату: ID, source, checkout, причина и безопасные варианты восстановления, без `integration:start/continue`. После diagnostic **только очередь владеет записью main**; основной агент может читать Kit/Git и сообщить причину пользователю. Команду разрешено завершить только самозавершением с terminal event App Server, остановкой конкретной сессии по прямому поручению пользователя у владеющего executor либо ручной остановкой с подтверждением App Server. Утрата свидетельства = UNKNOWN, не фиктивный exit=0 и не автоматическое удаление marker. После подтверждённого снятия blocker очередь делает один merge; только отдельный final Send передаёт основному чату ответственность за остающиеся Kit-операции и итог. Если blocker снят ещё до diagnostic Send, используется обычный финальный путь.

Отправка использует общий AutomationSendState и Composer: до попытки Send persist `sending`, перед фактическим кликом проверка projectId/scope/HEAD, origin URL/document, команд, паузы, ручного Stop/input и назначения. До клика отмена возвращает pending, после неоднозначной попытки UNKNOWN не повторяется; при сбое записи до Send отправка не выполняется. OFF вручную, Stop, busy, чужой черновик и недоступная страница запрещают новые отправки. Автоматический completion-OFF сохраняет уже допустимый pending-final; ручной OFF — нет. Рестарт и повторные события не повторяют sending/unknown/sent. `reply-observed` требует нового user-turn своей отправки и последующего нового законченного assistant-turn в том же наблюдаемом документе, без connectionError и чужого ручного Send; busy=false и смена pause сами по себе не подтверждают ответ. Это не пользовательская приёмка. План остаётся READY_FOR_ACCEPTANCE, сервер предпросмотра продолжает работу.

При старте и событиях перечитываются план, назначения, точные связи сессий и Git. INTEGRATED подтверждается историей main. Уже созданный интеграционный коммит с незавершённой финализацией продолжает существующий журнал; неизвестный merge не запускается заново.

Зарезервированный ID без записи Kit остаётся UNKNOWN и занимает слот. Потерянная или несовпадающая сессия не заменяется новым чатом. Известный NEEDS_SETUP и незапущенная подготовка продолжаются под прежним ID по событиям при AutoPlan ON; начатая отправка, черновик и UNKNOWN сохраняются. События публикации, готовности страницы, файлов журнала и завершения команд будят очередь; функционального polling и отдельной кнопки повтора нет.

Незавершённая интеграция продолжается только по доказанной существующей операции при остановившихся чате и командах. Исправление конфликтов выполняется в main. Нет reset --hard, автоматической очистки, удаления веток/worktree или повторного Send ради восстановления. Сбой одного исполнителя сохраняет остальных и блокирует его интеграцию и зависимые задачи.

Журнал другого projectId не участвует в выдаче. Исполнитель принадлежит parentWorkspace и parentProjectId; сессия, assignment ID, scope/task/origin и Git-база сверяются. Legacy привязывается только по доказанному назначению и project_id его базового плана. Чужая/неизвестная связь показывается в восстановлении Settings, не отдельным обычным проектом. Выбор чужого или отсутствующего родителя запрещён; архивный родитель допускает только завершающую фоновую запись своей сессии. Удаление использует точный снимок дочерних identity, архивирование сохраняет данные.

## Панель и время

Под основным проектом группа «Исполнители» подписана названием сессии происхождения. Строка показывает ID/название задачи, worktree, Chat/Work, текстовый статус и время работы/ожидания; цвет дополнительный. Исполнители не становятся самостоятельными проектами списка, завершённые чаты доступны. Клик открывает собственную живую или сохранённую страницу.

Статусы различают подготовку, наблюдаемую работу, паузу, неподтверждённую команду, готовый коммит с продолжающимся ответом, готовность к слиянию, интеграцию, конфликт и проверенное завершение. Idle не считается вопросом пользователю. Без наблюдения показывается неопределённость. В основном чате карточка использует подтверждённую parallel-проекцию и пять строк: **Источник, Общий main, Диагностика, Финальное поручение, Итоговый ответ** с текстовыми статусами и адресным следующим действием. Готовый source ещё не означает проверку main; DONE после Kit/Git merge, ответ — после подтверждённого turn, пользовательская приёмка отдельно. У исполнителя вместо общего плана только карточка назначения с названием и состоянием, без кнопок AutoPlan/Review; локальный DONE не подменяет общий прогресс. Проверяется ширина 312 px, две темы, status/aria и управление клавиатурой; опасный blocker не превращается в кнопку обхода безопасности.

ExecutorTimer считает только наблюдаемую активность и ожидание открытого приложения. Переходы и пятесекундные отсчёты сохраняют totals; UI обновляет часы раз в секунду без Git/DOM/сетевых запросов. Потеря страницы приостанавливает часы, интеграция останавливает. Перезапуск возвращает сохранённое время без добавления закрытого интервала.

Узкий IPC auto-plan сохраняет штатную проверку отправителя. IPC execute-tasks, reconcile-execution и correct-integration удалены; исправление интеграции входит в разрешённый AutoPlan процесс. Основная карточка показывает состояние AutoPlan проекта; ошибка очереди различает неопубликованный/изменённый план, транзакцию, Review, активную команду, чужие изменения и неготовый основной чат. Проекция не копирует текст бесед. Наблюдение событийное, функционального polling в простое нет.

## Проверки

Unit проверяет снимки, зависимости, исключительный барьер, source/merge/diagnostic/finalization/OFF/Stop/UNKNOWN/restart, принадлежность, часы и проекцию. Electron smoke сначала проходит три задачи с конфликтом и исправлением, затем пять: исключительная основа → три независимых инструмента → итоговая задача. Проверяются восемь настоящих Git-интеграций, F03 (последний source + живой writer → read-only diagnostic → terminal event → один merge → final), подтверждение ответа и отсутствие повторов при переключении. На macOS реальный read-only HTTP-сервер остаётся доступным после финала; запись запрещена, удаление блокируется до остановки точной сессии. [Матрица F01–F20/A01–A06](parallel-execution-acceptance.md) различает доказательства и границы. TEST FIXTURE моделирует ответы, не вызывает модели и не подменяет пользовательскую приёмку.

`packages/workflow-kit/scripts/check-parallel-execution-fixture.mjs` входит в kit-check: настоящие Git worktree, локальная npm-зависимость, NEEDS_SETUP, проверки, конфликт, зависимая база и сохранение доказательств после удаления рабочего документа. Fixtures не заменяют [пользовательскую приёмку](parallel-execution-acceptance.md).
