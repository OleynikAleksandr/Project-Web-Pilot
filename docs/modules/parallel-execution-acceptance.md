# Пользовательская приёмка параллельного исполнения

Протокол выполняет пользователь на установленном выпуске. Автоматические fixtures пройдены, но не подтверждают работу реального ChatGPT, чистой ОС или native Windows. До прямой приёмки план остаётся READY_FOR_ACCEPTANCE; агент его не закрывает.

## Подготовка

Полностью выйти из Web Pilot и открыть его через прежний алиас. Проверить номер установленного выпуска в меню «О Project Web Pilot». Для сценариев создать отдельный небольшой тестовый проект, не использовать важные рабочие файлы. Войти в ChatGPT вручную. Выполнить основной сценарий отдельно в Chat и Work; не менять режим уже созданного разговора.

## Два исполнителя и зависимая задача

1. В Settings разрешить параллельное выполнение с лимитом 2, затем создать новую основную сессию. Попросить план из трёх задач: первая создаёт `alpha.md`, вторая — `beta.md`, третья создаёт `summary.md` на основе обоих документов и зависит от первых двух. Области первых двух задач не пересекаются. Если Review включён, дождаться штатного согласования.
2. Убедиться, что новый план начинает с AutoPlan OFF. После публикации включить «Автовыполнение» проекта; первая группа стартует автоматически. Изменение Settings само запускать задачи не должно. Основной чат планирует; назначенные задачи выполняют отдельные чаты.
3. Убедиться, что появилась группа «Исполнители» с двумя задачами, своими папками worktree и унаследованным Chat/Work. Переключиться между ними и основным чатом во время работы: страницы и ответы продолжаются, контекст не отправляется повторно. Проверить названия, текстовые статусы и время в светлой и тёмной темах. В основном чате назначенные задачи отмечены текущими; у исполнителя вместо общего плана только его назначение. Готовый коммит ждёт интеграции, галочка общего плана появляется после неё.
4. Во время работы первых исполнителей выключить AutoPlan, затем дождаться их коммитов и интеграций. Готовый локальный коммит ещё не означает DONE общего плана: нужны остановившийся ответ своего чата, завершённые команды и проверенная интеграция в main. При выборе исполнителя панель показывает общий прогресс.
5. При AutoPlan OFF команды и готовые интеграции могут завершиться, третья задача и новые отправки ждут ON. Включить AutoPlan вновь: зависимая задача должна стартовать автоматически. Третья задача должна получить оба интегрированных документа в своей исходной базе.
6. Проверить итоговые файлы в основном проекте и завершение трёх задач; повторные события и переключения не создают дополнительные чаты, назначения или интеграции. Завершённые чаты остаются доступны. Последняя подтверждённая галочка выключает AutoPlan; следующий план начинает с OFF. Во втором одновременно открытом проекте разрешение не меняется.

## Последовательный режим и неизменность настроек

Изменить Settings уже после создания основной сессии: её сохранённое разрешение и лимит не должны меняться. В новой сессии с разрешением OFF либо лимитом 1 обычный последовательный план выполняется основным чатом без исполнителей. Старый чат и старый план без новых полей открываются без повторной доставки и сохраняют последовательное поведение.

## Перезапуск и безопасное восстановление

На отдельном тестовом запуске полностью перезапустить приложение при незавершённой работе. Проверить привязку прежних разговоров к прежним задачам и папкам, отсутствие повторного Send использованной паузы и дубликатов. Сохранённое время возвращается без прибавления времени закрытого приложения. При неизвестном состоянии показывается точная причина; события и OFF→ON не повторяют неизвестную отправку или merge. Для прежнего ошибочного main-старта сначала обновить Kit через Доктор до 1.7.1; при ON допустимый перенос сохраняет файлы и возвращает main к опубликованной основе. Чужие изменения требуют разбора состава, а не автоматической очистки.

Если реальная ошибка связи возникла сама, проверить блок восстановления: он относится к своему чату, открывает тот же URL без повторной отправки; черновик, UNKNOWN, ручной Stop и пауза ограничения запросов защищены. Обычное длительное ожидание ответа не является ошибкой связи. Не изменять профиль или сеть ради искусственного повреждения.

## Исправление интеграции

При возникшем конфликте или провале объединённых проверок основной план остаётся незавершённым, другие интеграции и новые группы ждут. При AutoPlan ON и готовом основном чате поручение передаётся автоматически, без дополнительной кнопки; OFF, черновик и активная команда блокируют отправку. Одно поручение приходит именно в основной чат, содержит операцию, причину и команду продолжения; повторные события и UNKNOWN его не дублируют. После исправления и успешных проверок принимается одна интеграция. Ошибка запуска Node отображается как ошибка окружения и не передаётся агенту как конфликт кода. Не создавать конфликт в важном проекте ради этого пункта; автоматическая проверка конфликта уже есть на временном fixture.

## Фиксация результата

| Сценарий | Статус до пользовательской проверки |
| --- | --- |
| Реальные Chat и Work, переключение, зависимая задача | Открыт |
| AutoPlan ON/OFF, последовательный режим, старые чаты | Открыт |
| Перезапуск, связь, черновик и неизвестный исход | Открыт |
| Исправление реального конфликта | Открыт; fixture не заменяет этот результат |
| Запуск через прежний macOS-алиас | Открыт |
| Native Windows и первый запуск на чистой ОС | Открыты |

Для каждого выполненного пункта записать версию, ОС, Chat/Work и наблюдаемый результат. Невыполненный пункт не отмечать успешным. Сборка Windows на Mac подтверждает упаковку, а не native Windows. Общая фраза «всё работает» означает общую приёмку, а не доказательство каждого непроверенного сценария.
