# Module Specification — Project Doctor

## Поручение и результат

16.09.2026 пользователь согласовал Доктор проекта в Settings и на экране ошибки подготовки: проверить и автоматически исправить известные неисправности, затем открыть прежнюю/новую сессию или повторить доставку контекста. Реализовать и собрать 0.6.20. Текущее рассогласование kit-manifest реального Project Web Pilot сохранить до пользовательского запуска; проверять ремонт только на временных fixtures.

## Границы и facade

Project Doctor координирует штатные Workflow Kit и Runtime Lifecycle, не зависит от ChatGPT/MCP и не отправляет сообщения. Facade `inspect(workspace)` / `repair(workspace)` возвращает структурированные checks, repairs, issues, backupPath и projectReady. Main process выбирает явный workspace из зарегистрированного списка или setup preview; web ChatGPT не имеет IPC доступа. Исправление запускается только явной кнопкой «Проверить и исправить».

Малые компоненты: файловые снимки и резервная копия; доверенный комплект и план исправлений; изолированный worker; desktop coordinator; UI. Только bundled Node worker/Workflow Kit выполняет проверку и ремонт. До установления целостности кода проекта его launcher не запускается.

## Автоматические исправления первой версии

- Устаревшая установочная запись: все owned-файлы обязаны совпасть с известным bundled комплектом. Только тогда manifest приводится к этой версии; произвольные изменённые файлы не легализуются пересчётом hashes.
- Отсутствующие owned-файлы текущего комплекта восстанавливаются из bundled payload. Неизвестная версия/изменённые или лишние runtime-файлы требуют разбирательства; downgrade не выполняется.
- Отсутствующие Git hooks и утраченные executable bits восстанавливаются штатным содержимым с сохранением чужих частей; изменённая управляемая секция не перезаписывается.
- Читаемая проекция плана восстанавливается из валидного канонического JSON через Workflow Kit repair. Семантика задач не угадывается.
- Завершённый Git commit с незакрытым техническим журналом завершается штатным repair. Незавершённая/неподтверждённая транзакция требует продолжения своей исходной задачи и не коммитится доктором автоматически.
- Runtime Lifecycle выполняет существующий ensure/self-healing: запуск отсутствующих служб, stale PID и динамические endpoints. Неизвестные процессы, credentials и настройки аккаунта не изменяются.

Старый целостный комплект проверяется обычным Workspace Setup; при необходимости показывается существующее предложение штатного upgrade. Неизвестная или повреждённая старая версия не переустанавливается вслепую. Повреждённый JSON/история плана, отсутствующие пользовательские документы, Git merge/rebase и чужие изменения не исправляются угадыванием.

## Запись и повторная проверка

Проверка до ремонта читает файлы, не создаёт сессию и не запускает проектный код. Для записи используются общий Workflow Kit operation lock и повторная проверка снимка. Нельзя следовать symlink в служебных путях. Перед записью сохраняются оригинальные bytes/modes затрагиваемых файлов, информация об отсутствующих путях и резервная копия плана/manifest в приватном локальном runtime. Ошибка записи откатывает только собственные неизменившиеся после записи файлы; резервная копия сохраняется. После прерванной записи backup/journal позволяет безопасно повторить известные операции; чужие последующие изменения не откатываются.

После ремонта повторяются integrity, validation и COMPLETE recovery через Workspace Setup. Project readiness и readiness локальных служб показываются раздельно. Ошибка служб не объявляется успешным восстановлением сессии. Активный scope не закрывается, пользовательская работа/staging не коммитится, история сессий и облачные чаты сохраняются. Ремонт owned-файлов может оставлять их изменения в Git; это показывается пользователю.

## UI

Settings содержит выбор проекта и кнопку «Проверить и исправить». Заблокированный setup содержит «Доктор проекта», ведущую к выбранной неисправной папке. Settings доступны даже во время ошибки setup. Во время проверки/ремонта кнопки повторного запуска заблокированы. Результат показывает выполненные действия, оставшиеся проблемы, место резервной копии. При успешной проверке доступны открыть сессию, новый Chat, новый Work и обновить контекст; отправка начинается только выбранной пользователем командой.

## Проверки

Fixtures покрывают текущий сценарий stale manifest, повторный запуск, missing owned file/hook, права, неизвестный modified code, symlink, повреждённый manifest/plan, stale snapshot, backup и сохранность пользовательского файла/staging. Electron smoke проверяет путь от setup ошибки через доктор до готовности на отдельной временной папке. macOS/Windows packages содержат worker и тот же Kit. Перед передачей релиза отдельно сверяется неизменность manifest реального проекта.

## Реализация ядра — T010

Доверенный каталог строится из bundled payload. Полный список owned-путей проверяется до запуска локального launcher; неизвестные и дополнительные файлы останавливают запись. Worker возвращает только отчёт, не текст файлов. Файловые изменения используют общую блокировку Workflow Kit, snapshot и atomic rename; запись manifest идёт после восстановления известных файлов. Резервная копия содержит исходные bytes/modes и журнал выполнения, откат после ошибки не затрагивает последующие чужие изменения.

## Desktop integration — T011

`ProjectDoctor` запускает отдельный trusted worker на Node и затем обычный Workspace Setup preview. Восстановление runtime использует существующий `ensure()`; ошибка подключения остаётся отдельным issue при исправном проекте. Локальный IPC разрешён только sidebar и принимает зарегистрированную либо выбранную через setup папку. UI не запускает ремонт при открытии настроек/рендере. После явного запуска показывает резервную копию и действия открытия/новой сессии/refresh только при успешных проверках проекта и служб.

## Выпуск и приёмка

0.6.20 поставляется для macOS arm64 и Windows x64. Изолированный Electron smoke подтверждает сценарий от ошибки setup через доктор до прежней сессии, явного refresh и нового Work; исходный manifest реального проекта сохранён для физической проверки пользователя. Связанные документы, navigation map и index актуализируются финальной DOCS текущего scope. Доктор не заменяет пользовательскую приёмку.
