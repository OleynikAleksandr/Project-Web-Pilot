# Совместимость интерфейса ChatGPT — 0.6.66

## Новый Chat/Work — 0.6.66

Только явное создание новой сессии разрешает очистить восстановленный черновик. Composer использует нативный setter + input/change для textarea или выделение + execCommand(delete) для contenteditable, как существующий путь вставки. Операция выполняется в isolated world 999 и сверяет identity документа в том же вызове; разрешены только entrypoint без пользовательских сообщений, доступный редактор и отсутствие busy/login/error. После подтверждения режима разрешение снимается. Reopen/retry не очищают поле; системный clipboard и browser storage не затрагиваются.

## Общий наблюдатель — фаза 1

`createChatGPTDOM` используется composer и generated sandboxed preload. Наблюдатель передаёт ревизии редактора/черновика/пользовательских сообщений, busy, login, writable, sendEnabled, URL/experience и компактный connectionError. Равные по длине правки замечаются через input/MutationObserver; текст, хеш текста и найденные requestId через IPC не передаются. Controller выполняет существующий inspect по сигналу, включая позднее заполнение пользовательского сообщения.

Manual Send подтверждается trusted click/Enter, появлением соответствующего пользовательского текста и очисткой редактора; наружу передаётся только manualSendRevision. С 0.6.65 распознаются обе формулировки «ChatGPT stream recovery polling timed out» и «Resume stream unavailable». Terminal error ищется в видимом error UI, не в обычном ответе/цитатах. Main отвергает сообщения чужого документа, origin и фрейма. Цвета и автопрокрутка сохраняют свои прежние observer-ы; секундный страховочный проход цветов относится к следующей фазе.

Контракт: `docs/planning/event-driven-runtime.md`. Source/installed fixtures не заменяют проверку текущей вёрстки в пользовательском аккаунте.


Владелец: Workspace & Sessions. Контракт утверждён пользователем 25.09.2026 по результатам реального аудита 0.6.47.

Facade `chatgpt-dom.mjs` читает только видимый DOM: composer, send/stop, режим, сообщения, служебные блоки. Общие селекторы сериализуются в изолированный Chromium; ни cookies, ни page internals, ни модельные API не используются. Код поддерживает прежние и новые атрибуты. Отсутствие подтверждённого режима блокирует передачу, а не угадывается по URL. `/` и `/work/` — точки входа, кнопки могут изменить режим без навигации. Сохранённая неопределённая отправка не повторяется автоматически.

Границы: фильтр скрывает только опознанные служебные строки, не ответы, файлы и запросы разрешений. Цвета используют те же semantic message selectors. Прокрутка учитывает обычный и обратный поток, прекращает следование при ручном чтении и не создаёт цепочку scroll → scroll. UI завершает свои renderer-процессы, но не останавливает независимые MCP/tunnel. Их пользовательский автозапуск действует после входа в ОС; до входа личный профиль недоступен.

Приёмка: Node regression и Electron fixture обязательны; реальный DOM и Windows-проверки фиксируются отдельно. Успешная сборка не подтверждает доставку контекста в реальном чате.

## Итог реализации 25.09.2026

Контракт реализован в локальном 0.6.48. Живые новые Chat и Work получили полный пакет и подтвердили восстановление; hide/show карточки после MCP вызова проверен. Выявленный при этом transient `local-chatgpt` URL поддержан отдельной регрессией. Сборка сверяет исходники и оба ZIP; native Windows и reboot/login остаются непроверенными. Доказательства — `docs/VERIFICATION.md`, доставка — `docs/RELEASE.md`.

## Таймер работы агента — 0.6.54

Таймер в карточке плана использует тот же контракт: признак работы — видимый stop-контрол из `CHATGPT_SELECTORS.stop` (`busy()`), без сетевых данных и внутренних API. Ожидание подтверждения инструмента дольше 5 с без stop-контрола завершает замер; продолжение после подтверждения считается новым заданием, а сумма сессии включает только время работы агента.

## Плашка поля ввода — 0.6.55

Поле ввода берётся из `CHATGPT_SELECTORS.editor`, а плашка определяется по вычисленному скруглению предка, а не по классам и атрибутам вёрстки: они различаются между чатом и новой страницей одного и того же ChatGPT.


### Диагностика Send — 0.6.67
Источник composer в diagnostics/chromium-events.jsonl записывает delivery-start/result/error, action-start, observation, before-send-start/complete. Сводка содержит тип редактора, white-space, наличие и доступность Send, нормализованные длины, индекс и класс первого различия, счётчики специальных пробельных символов. Текст и HTML не сохраняются. Длительность действия показывает задержку вставки отдельно от подготовки recovery. Только outcome=clicked подтверждает вызов кнопки; sent требует пользовательского сообщения. DRAFT_CHANGED по-прежнему блокирует отправку; nonWhitespaceMatches — только диагностическая метрика. Конкретное преобразование текста живым редактором ещё не установлено.
