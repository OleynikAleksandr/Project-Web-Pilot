# Совместимость интерфейса ChatGPT — текущий source / 29.09.2026

## Внешний потребитель — Web Pilot Sidebar / 02.10.2026

Sidebar собирает `src/chatgpt-dom.mjs`, `src/chatgpt-composer.mjs` и `src/chatgpt-experience.mjs` в обычный browser content script. Эти модули импортируют только друг друга через именованные статические импорты вида `import { a, b } from './file.mjs'`; Node API и динамические импорты не допускаются.

Публичные зависимости Sidebar:

- `CHATGPT_SELECTORS`, включая `stop`; `createChatGPTDOM(selectors)` с `editor()`, `sendButton()`, `first(selector)`; `chatGPTDOMScript()`.
- `pageOperation(args, dom)` вызывается прямо на странице. Его экспорт восстановлен в T008 после уточнения внешнего потребителя; `ComposerError` Sidebar не использует, класс остаётся внутренним.
- `ChatGPTComposer(contents, { timeoutMs })` с `deliver({ text, requestId, expectedExperience })` и `inspect({ action, text })`. От `contents` Sidebar предоставляет `getURL()` и `executeJavaScript(code)`.
- `chatGPTEntrypoint(experience)` и `isPendingChatGPTConversation(url)`.

Sidebar восстанавливает точную строку `pageScript` из функции и DOM factory:

```js
`(${pageOperation})(${JSON.stringify(args)}, ${chatGPTDOMScript()})`
```

Вызовы `executeJavaScript(code)` Sidebar распознаёт по этому формату и обслуживает без eval. Имя/наличие `pageOperation` и сериализация являются частью внешнего контракта. Не менять экспорты или этот формат без явной необходимости; изменения перечисленного контракта обязательно отмечать в описании коммита.

У Sidebar три файла закреплены SHA-256 в `vendor.lock.json`. Любая правка требует проверки и повторного закрепления на его стороне. После снятия экспорта в T005 Sidebar временно извлекал функцию без `export`; после восстановления экспорта обходной путь может убрать сопровождающий Sidebar. Этот репозиторий не меняет внешний lock или сборку Sidebar.

## Новый Chat/Work — 0.6.66

Только явное создание новой сессии разрешает очистить восстановленный черновик. Composer использует нативный setter + input/change для textarea или выделение + execCommand(delete) для contenteditable, для удаления восстановленного текста. Операция выполняется в isolated world 999 и сверяет identity документа в том же вызове; разрешены только entrypoint без пользовательских сообщений, доступный редактор и отсутствие busy/login/error. После подтверждения режима разрешение снимается. Reopen/retry не очищают поле; системный clipboard и browser storage не затрагиваются.

## Общий наблюдатель — фаза 1

`createChatGPTDOM` используется composer и generated sandboxed preload. Наблюдатель передаёт ревизии редактора/черновика/пользовательских сообщений, busy, login, writable, sendEnabled, URL/experience и компактный connectionError. Равные по длине правки замечаются через input/MutationObserver; текст, хеш текста и найденные requestId через IPC не передаются. Controller выполняет существующий inspect по сигналу, включая позднее заполнение пользовательского сообщения.

Manual Send подтверждается trusted click/Enter, появлением соответствующего пользовательского текста и очисткой редактора; наружу передаётся только manualSendRevision. С 0.6.65 распознаются обе формулировки «ChatGPT stream recovery polling timed out» и «Resume stream unavailable». Terminal error ищется в видимом error UI, не в обычном ответе/цитатах. Main отвергает сообщения чужого документа, origin и фрейма. Startup-account использует этот же общий observer; явная проверка и возврат после auth-popup делают единичный snapshot из isolated world, без фонового DOM polling. Цвета сохраняют отдельный узкий observer плашки composer: editor/предки до html, childList, class/style, ResizeObserver, resize и prefers-color-scheme; секундного safety interval больше нет.

Контракт: `docs/planning/event-driven-runtime.md`. Source/installed fixtures не заменяют проверку текущей вёрстки в пользовательском аккаунте.


Владелец: Workspace & Sessions. Контракт утверждён пользователем 25.09.2026 по результатам реального аудита 0.6.47.

Facade `chatgpt-dom.mjs` читает только видимый DOM: composer, send/stop, режим, сообщения, служебные блоки. Общие селекторы сериализуются в изолированный Chromium; ни cookies, ни page internals, ни модельные API не используются. Код поддерживает прежние и новые атрибуты. Отсутствие подтверждённого режима блокирует передачу, а не угадывается по URL. `/` и `/work/` — точки входа, кнопки могут изменить режим без навигации. Сохранённая неопределённая отправка не повторяется автоматически.

Границы: фильтр скрывает только опознанные служебные строки, не ответы, файлы и запросы разрешений. Цвета используют те же semantic message selectors. Прокрутка учитывает обычный и обратный поток, прекращает следование при ручном чтении и не создаёт цепочку scroll → scroll. UI завершает свои renderer-процессы, но не останавливает независимые MCP/tunnel. Их пользовательский автозапуск действует после входа в ОС; до входа личный профиль недоступен.

Приёмка: Node regression и Electron fixture обязательны; реальный DOM и Windows-проверки фиксируются отдельно. Успешная сборка не подтверждает доставку контекста в реальном чате.

## Итог реализации 25.09.2026

Контракт реализован в локальном 0.6.48. Живые новые Chat и Work получили полный пакет и подтвердили восстановление; hide/show карточки после MCP вызова проверен. Выявленный при этом transient `local-chatgpt` URL поддержан отдельной регрессией. Сборка сверяет исходники и оба ZIP; native Windows и reboot/login остаются непроверенными. Доказательства — `docs/VERIFICATION.md`, доставка — `docs/RELEASE.md`.

## Таймер работы агента — 0.6.54

Таймер в карточке плана использует тот же контракт: признак работы — видимый stop-контрол из `CHATGPT_SELECTORS.stop` (`busy()`), без сетевых данных и внутренних API. Ожидание подтверждения инструмента дольше 5 с без stop-контрола завершает замер; продолжение после подтверждения считается новым заданием, а сумма сессии включает только время работы агента.

## Плашка поля ввода — 0.6.55

Поле ввода берётся из `CHATGPT_SELECTORS.editor`, а плашка определяется по вычисленному скруглению предка, а не по классам и атрибутам вёрстки: они различаются между чатом и новой страницей одного и того же ChatGPT.


### История диагностики Send — 0.6.67
Источник composer в diagnostics/chromium-events.jsonl записывает delivery-start/result/error, action-start, observation, before-send-start/complete. Сводка содержит тип редактора, white-space, наличие и доступность Send, нормализованные длины, индекс и класс первого различия, счётчики специальных пробельных символов. Текст и HTML не сохраняются. Длительность действия показывает задержку вставки отдельно от подготовки recovery. Только outcome=clicked подтверждает вызов кнопки; sent требует пользовательского сообщения. DRAFT_CHANGED по-прежнему блокирует отправку; nonWhitespaceMatches — только диагностическая метрика. Конкретное преобразование текста живым редактором ещё не установлено.

## История вставки и Send — 0.6.68

Contenteditable: фокус/позиция в конце, затем один webContents.insertText. Textarea: native setter + input/change. Clipboard не используется. После вставки Send не зависит от draftMatches, длины, хеша или изменений пользователем. Сравнение остаётся диагностикой и помогает узнать уже восстановленный точный пакет до новой вставки. Недоступная кнопка ожидается по событиям, доступная нажимается сразу. Документ/выбор и неопределённость отправки сохраняют прежнюю защиту от неверного адресата и дубля. Контракт — docs/CONTEXT_DELIVERY.md.

## Paste — 0.6.69

Composer передаёт ClipboardEvent(paste) штатному обработчику страницы с text/plain и экранированным HTML. Пустые строки и пробелы сохраняет data-pm-slice. В системный clipboard ничего не записывается. Отсутствие обработчика даёт PASTE_UNHANDLED без автоматического fallback на insertText. Лог отмечает метод, принятие события, время и click. Installed fixture использует настоящий ProseMirror, проверяет точный текст и одну paste transaction; это не копия всех расширений редактора ChatGPT.

## Завершение recovery — 0.6.70

После clicked нет ожидания messageSeen. ChatGPT может преобразовать Paste во вложение; пустой текст сообщения не препятствует завершению и привязке URL. Вставка и доступность Send проверяются до клика; после него не добавляется поясняющий текст или повторная отправка.


## AutoPlan — 0.6.78

Observer больше не выдаёт количества DOM-узлов за ID сообщения. Native data-message-id читается также внутри semantic wrapper Work; fallback принадлежит сохраняемому циклу генерации AutoPlan. IPC содержит источник native/cycle/none, текст беседы не передаётся. Пустой snapshot загружаемой истории не разрешает автоотправку.

Публичные экспорты и точный формат pageScript сохранены. pageOperation принимает необязательный draftToken и дополнительное действие clear-owned-draft; sendUserMessage поддерживает cleanupOnCancel=false. Только AutoPlan включает очистку своей отменённой вставки. Она требует совпадения токена конкретного editor, неизменённого текста и отсутствия trusted input; пользовательский черновик и unknown Send сохраняются. Recovery deliver не изменён. Внешнему Sidebar потребуется обычное обновление vendor lock при принятии новой версии; его workspace здесь не менялся.
