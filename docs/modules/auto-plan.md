# AutoPlan — автовыполнение текущего плана

AutoPlan разрешает Web Pilot продолжать план выбранного проекта. Sequential отправляет одно «Продолжай» основному чату на подходящей паузе. Parallel создаёт отдельные чаты/worktree и принимает проверенные интеграции; основной чат не выполняет обычные задачи в main. Конфликт или падение объединённого теста при ON автоматически передаётся основному чату один раз; отдельной кнопки нет. Ошибка запуска проверки требует исправления окружения, не кода агентом. Протокол очереди — [parallel-execution](parallel-execution.md).

## Разрешение

AutoPlan и Review независимы между собой и между проектами. Пользователь управляет ими кнопками карточки проекта, текст агента режимы не меняет. ON зелёный с aria-pressed=true в обеих темах; во время действия панели кнопка временно недоступна.

По умолчанию OFF. Явное ON до первого плана сразу отображается и сохраняет ожидание его публикации; без подтверждённого плана работа не начинается. OFF отменяет ожидание. Restart сохраняет выбор только своего проекта.

Хранение: settings.json, projectAutoPlan[workspace] = {scopeId,enabled,sessionId,sessions,awaitingPlan}. Ожидание первого плана имеет scopeId="" и awaitingPlan=true; первый scope снимает awaitingPlan. Старое глобальное autoPlanEnabled=true игнорируется. Подтверждённое завершение сохраняет OFF; следующий scope OFF. Staged DONE и незавершённая транзакция не подтверждают завершение. Ошибка чтения запрещает Send/назначение и выключает уже привязанное разрешение.

sessions[sessionId] содержит отдельные autoPlanCheckpoint/automationCheckpoint без текста беседы. Защита Review/AutoPlan от повторной отправки сохраняется при смене scope; UNKNOWN не повторяется.

## Контроллеры

project-auto-plan.mjs хранит разрешения; project-session-auto-plan.mjs создаёт AutoPlan, AutomationSendState и PlanMonitor каждого основного runtime. Скрытые чаты адресуются самостоятельно; другой выбранный проект не переносит отправку. Один основной Session ID продолжает sequential; исполнители наследуют разрешение родителя.

main.mjs связывает защищённый pilot:auto-plan с чтением плана, сохранением и событиями; ui/sidebar.mjs — с кнопкой. auto-plan-state.mjs проверяет план, транзакцию и Review; auto-plan.mjs управляет продолжением, Composer отправляет. Функционального polling и model API нет.

Для Send нужны подтверждённый незавершённый план, свой доступный чат с историей и ответом assistant, поле без черновика, отсутствие ручного Stop, активной команды и другой доставки. Пауза используется один раз; checkpoint сохраняется до Send. Публикация и готовность страниц возобновляют очередь событиями; ручное сообщение пользователя приоритетнее.

Полный порядок допусков, коды ожидания, checkpoint, формат сообщения, watchdog, диагностика и защита Review — [auto-plan-send](auto-plan-send.md). Другие границы — [доставка](context-delivery.md), [живые страницы](session-runtime.md).

## Проверки

Unit проверяет разрешения, restart, OFF, завершение/новый scope, Send/UNKNOWN/Review/Stop. Electron TEST FIXTURE проверяет настоящие кнопку/preload/IPC до первого плана, противоположные состояния AutoPlan/Review двух проектов, публикацию parallel, назначения и завершение OFF. Живой ChatGPT, чистую ОС и native Windows принимает пользователь.
