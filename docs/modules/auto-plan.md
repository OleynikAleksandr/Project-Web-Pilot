# AutoPlan — автовыполнение текущего плана

AutoPlan разрешает Web Pilot продолжать текущий план выбранного проекта. Последовательный основной чат получает одно «Продолжай» на подходящей паузе. В parallel-плане приложение создаёт назначения и отдельные чаты/worktree, затем принимает результаты проверенными интеграциями. Основной чат не выполняет задачи parallel-плана в main.

## Переключатель и хранение

- AutoPlan и Review независимы друг от друга и между проектами. Пользователь переключает их кнопками карточки выбранного проекта; текст агента режимами не управляет. AutoPlan ON зелёный и имеет aria-pressed=true в обеих темах. Во время действия панели кнопка временно недоступна.
- По умолчанию OFF. Пользователь может явно включить AutoPlan до создания плана: кнопка сразу показывает ON, разрешение сохраняется для первого опубликованного плана этого проекта. Без подтверждённого плана работа не начинается. OFF отменяет ожидание.
- В settings.json хранится projectAutoPlan[workspace] = {scopeId,enabled,sessionId,sessions,awaitingPlan}. Ожидание первого плана обозначено scopeId="" и awaitingPlan=true; после привязки awaitingPlan снимается. Старое глобальное autoPlanEnabled=true игнорируется. Явный выбор переживает restart, не переносится между проектами.
- Подтверждённое завершение всех задач сохраняет OFF. Следующий scope начинается OFF; старое разрешение не переносится. Staged DONE и незавершённая транзакция завершение не подтверждают. Ошибка чтения не разрешает Send или назначение; уже привязанное разрешение выключается при неизвестном плане.
- У каждой sessions[sessionId] собственные autoPlanCheckpoint и automationCheckpoint. Общая защита Review/AutoPlan от повторной отправки сохраняется при смене scope; UNKNOWN никогда автоматически не повторяется. Текста разговора в журналах нет.

## Контроллеры и допуски

`project-auto-plan.mjs` хранит разрешения workspace/scope. `project-session-auto-plan.mjs` создаёт AutoPlan, AutomationSendState и PlanMonitor для каждого основного runtime. Скрытые чаты продолжаются по собственным адресам; выбор другого проекта не переносит отправку. Только один основной Session ID продолжает sequential-план; исполнители наследуют разрешение родителя.

`main.mjs` связывает узкий IPC pilot:auto-plan с чтением плана, сохранением разрешения и событиями. `ui/sidebar.mjs` подключает реальную кнопку. `auto-plan-state.mjs` проверяет план, транзакцию и Review. Сам контроллер находится в `auto-plan.mjs`, отправка — в Composer. Функционального polling и модельного API нет.

Для Send нужны подтверждённый незавершённый план, свой доступный чат, загруженная история, ответ assistant, доступное поле без черновика, отсутствие ручного Stop, активной команды и другой доставки. Одна пауза используется один раз; checkpoint записывается до Send. Публикация и готовность страниц возобновляют очередь событиями. Ручные сообщения пользователя приоритетнее автоматических.

Подробный [протокол отправки](auto-plan-send.md) определяет порядок допусков, коды ожидания, checkpoint, формат «Продолжай», watchdog, диагностику и защиту Review. [Параллельная очередь](parallel-execution.md) определяет выдачу, восстановление и интеграции. [Доставка контекста](context-delivery.md) и [живые страницы](session-runtime.md) сохраняют собственные границы.

## Проверки

Unit-тесты покрывают разрешения проектов, restart, OFF, завершение и новый scope; тесты контроллеров — Send/UNKNOWN/Review/ручной Stop. Electron TEST FIXTURE проверяет реальные кнопку, preload и IPC до первого плана, разные положения обеих кнопок в двух проектах, публикацию parallel-плана, назначения и завершение OFF. Это не проверка живого ChatGPT, чистой установки или native Windows; их принимает пользователь.
