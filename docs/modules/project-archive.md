# Архив проектов

Локальный архив проектов Web Pilot: перенос проекта в архив, отдельное окно архива, возврат в активные, «Убрать из списка» и безопасное удаление папки проекта с диска. Архив — состояние Web Pilot в `workspaces.json`, не Workflow Kit. Хранилище, миграции и архив отдельных сессий активного проекта описаны в [workspace-sessions.md](workspace-sessions.md).

## Код

- `src/workspace-session.mjs` — `WorkspaceSessions.setArchived`, `forgetArchived`, `forgetArchivedMany`, `landing`; ошибки `PROJECT_ARCHIVED`, `PROJECT_REPLACED`, `PROJECT_NOT_ARCHIVED`.
- `src/workspace-deletion.mjs` — `WorkspaceDeletion`: `preview`, `apply`, `finish`, `recover`, `inspect`, `guard`, `purgeCopies`, `isPending`, `clear`.
- `src/main.mjs` — `openArchiveWindow`, `assertArchiveSender`, `archiveRecords`, `registerArchiveAction`, `archiveSnapshot`/`projectedArchives`; IPC сайдбара `pilot:archive-project`, `pilot:open-archive-window`; IPC окна `archive:get-state|restore|forget|preview-delete|cancel-delete|delete-project|recover-deletions|close` (и `archive:restore-sessions|delete-sessions` для вкладки сессий); создание `WorkspaceDeletion` и доведение незавершённых удалений при старте.
- `src/archive-preload.cjs` — `window.webPilotArchive`; `src/ui/archive.html`, `src/ui/archive.mjs` — окно; `src/ui/settings-panel.mjs` — кнопка «Архив…»; `src/ui/sidebar.mjs` — пункт ⋯ «Перенести в архив».

## Поведение

### Архивирование

- Архив локальный и не меняет Kit: `execution_scope_status`, план и файлы проекта остаются как есть; DOCS и продолжение плана архивирование не вызывают (решение пользователя).
- «Перенести в архив» в меню ⋯ проекта сохраняет папку, план, все сессии, выбранную сессию, названия, URL и попытки отправки; недоступно при ошибке чтения хранилища.
- Архивация выбранного проекта: текущая доставка отменяется (`controller.cancel()`), выбор снимается (`selectedWorkspace=null`), окно ChatGPT уходит на адрес без проекта; при ошибке записи выбор возвращается. Остальные проекты продолжают работу; закрытие Настроек или отмена настройки проекта открывает следующий активный проект (`landing`).
- Поздние обновления сессий архивного проекта отклоняются `PROJECT_ARCHIVED`. Выбор или подключение папки архивного проекта открывает окно архива с выделенным проектом — скрытого восстановления нет.
- Запись хранилища последовательная и атомарная; ошибка не меняет состояние. Для архивации и возврата папка не нужна. Облачные чаты не удаляются никогда.

### Окно архива

- Вход: шестерёнка справа от «Подробностей подключения» → Настройки → «Архив…» (списка архива в Настройках нет). Окно открывается и при попытке открыть архивную папку.
- Один `BrowserWindow` «Архив — Project Web Pilot»; повторное открытие — `show()` + `focus()`. Закрытие окна сбрасывает подготовленное удаление.
- Изоляция: локальный `ui/archive.html`, свой preload, `sandbox`, `contextIsolation`, без `nodeIntegration`; навигация и новые окна запрещены. Каждый IPC проверяет отправителя (точный WebContents, mainFrame, URL), иначе `IPC_FORBIDDEN`; окну доступны только каналы `archive:*`; из архивных действий сайдбару — только `pilot:archive-project|archive-session|open-archive-window`. Странице ChatGPT ничего из этого недоступно.
- Store main — единственный источник; `publish()` шлёт проекцию и сайдбару, и окну. В проекции нет текстов сообщений: workspace, projectId, имя (`displayName` или имя проекта), дата архивации, число сессий, признак незавершённого удаления.
- Вкладки «Проекты» и «Сессии» (архив сессий активных проектов — [workspace-sessions.md](workspace-sessions.md); сессии архивных проектов там не дублируются).
- Выбор: клик — одна строка; Shift — диапазон от опорной строки; ⌘/Ctrl — переключить строку. «Вернуть в активные» и «Убрать из списка» применяются ко всему выделению, «Удалить с диска…» — только к одной строке. Проект с незавершённым удалением блокирует все три действия и показывает «Повторить очистку».
- Действия окна выполняются в общей очереди действий main. Перед действием main сверяет каждую пару `{workspace, projectId}` с хранилищем («Список архива изменился. Повторите выбор.»); ошибка показывается уведомлением в окне.

### Возврат

`archive:restore` делает выбранные проекты активными. Проект не выбирается и контекст не отправляется; при следующем открытии возвращается его прежняя выбранная сессия, открытие проходит обычную проверку папки ([workspace-setup.md](workspace-setup.md)). Пока идёт удаление проекта — отказ.

### «Убрать из списка»

`archive:forget` → `forgetArchivedMany`: одна атомарная мутация; весь набор проверяется заранее (`PROJECT_REPLACED`, `PROJECT_NOT_ARCHIVED`, повтор или некорректный элемент — `WORKSPACE_REQUIRED`) — убираются все или ни один. Удаляется запись проекта со связями сессий; папку, план, резервные копии хранилища и ChatGPT не трогает. Повторное подключение той же папки создаёт новую запись.

### Удаление с диска

- Только архивный проект с тем же `project_id` (`PROJECT_NOT_ARCHIVED`, `PROJECT_REPLACED`); при незавершённом удалении того же проекта — `DELETE_PENDING`.
- **Preview** (`archive:preview-delete`): проверка пути (ниже), чтение `project_id` из папки, обход дерева без перехода по ссылкам с отпечатком (относительный путь, inode, mode, size, mtime, ctime). Окно получает путь, имя, число сессий, число файлов, размер и одноразовый токен; отпечаток и device/inode корня остаются в main. Новый preview, отмена, закрытие окна и любой другой переход гасят токен. Нет папки → preview с `missing`, подтверждение очищает только локальную историю.
- **Подтверждение** — ввод точного имени проекта, показанного в панели удаления (имя проекта, не локальный псевдоним), иначе `DELETE_CONFIRMATION`; кнопка «Удалить безвозвратно» до этого заблокирована. Верное имя расходует токен (повтор — `DELETE_PREVIEW_EXPIRED`). Перед удалением `project_id`, отпечаток дерева и число сессий сверяются заново (`DELETE_PREVIEW_CHANGED`).
- **Запрещено** (`DELETE_PROTECTED`): не абсолютный или ненормализованный путь, корень диска, домашняя папка и её предки, пересечение (в любую сторону) с данными приложения, журналом удалений, `app.getAppPath()` и папкой состояния исполнителя (`runtimeFolder`). Пересечение с другим зарегистрированным проектом — `DELETE_NESTED_PROJECT`; корень — symlink, не каталог или подменён (`realpath` ≠ путь) — `DELETE_PATH_CHANGED`; внутри смонтирован другой том — `DELETE_MOUNTED_FOLDER`. Symlink внутри проекта удаляется как ссылка, его цель остаётся.
- **Ход**: журнал `<userData>/deletions/<uuid>.json` (каталог 0700, файл 0600, создаётся эксклюзивно) → проверка device/inode и отпечатка → `rename` корня в соседний `.web-pilot-delete-<uuid>` с повторной проверкой identity → стадия `removing` в журнале → `rm -r` карантина → очистка копий хранилища и диагностики → удаление записи проекта → удаление журнала.
- **Восстановление**: незавершённые журналы доводятся при старте приложения (ошибка показывается и открывает Настройки) и кнопкой «Повторить очистку». После стадии `removing` трогается только переименованный каталог: новая папка на прежнем пути не удаляется. Изменившаяся запись проекта (`DELETE_RECORD_CHANGED`) или подменённый каталог останавливают очистку; при ошибке проект остаётся в архиве, журнал сохраняется. Некорректный журнал — `DELETE_RECOVERY_FAILED`.
- **Что удаляется**: папка проекта (с планами), запись проекта со всеми локальными сессиями, URL и попытками, его записи во всех миграционных копиях `workspaces.json.v1-backup`…`.v5-backup` и строки `diagnostics.jsonl` и `diagnostics.jsonl.1` этого workspace, а также все брошенные временные копии хранилища ([workspace-sessions](workspace-sessions.md)). Профиль ChatGPT остаётся, к ChatGPT обращений нет, облачные разговоры сохраняются.

## Решения и запреты

- Облачные чаты ChatGPT не удаляются ни архивом, ни удалением (решение пользователя: «Сессии пусть валяются в веб»).
- Удаление необратимо, поэтому только по одному проекту, только из архива, после preview с путём, размером и числом сессий и ввода точного имени.
- Реальный проект удаляется только выбором и подтверждением пользователя в UI; автотесты удаляют лишь свои fixtures.

Не возвращать: список архива в Настройках вместо отдельного окна; массовое удаление с диска; удаление облачных чатов; прежние IPC `pilot:*-archive/delete/restore` вместо каналов `archive:*`.

## Проверки

- `tests/workspace-deletion.test.mjs` — подтверждённое удаление (файлы, сессии, ссылки в копиях, брошенные временные копии, внешние цели symlink целы), отказы для активного, защищённого, вложенного, подменённого и symlink-корня, отмена и устаревшее подтверждение, доведение прерванной очистки без удаления новой папки на прежнем пути, отсутствующая папка, восстановление после прерванного rename.
- `tests/workspace-session.test.mjs` — архив и возврат с сохранением сессий и выбора, `landing` после архивации или удаления выбранного, сбой записи без потери состояния, атомарное «Убрать из списка» нескольких проектов без касания папок.
- Проверка `electron-smoke`: одно окно архива без Node в странице, Shift-диапазон и ⌘-выбор, массовые возврат и «Убрать из списка», папки сохранены и подключаются заново, preview, отмена и точное подтверждение удаления одного проекта, соседние архивы не тронуты.
- Вручную: фактическое удаление реального проекта выполняет только пользователь; живой прогон на установленной сборке входит в приёмку выпуска ([release.md](release.md)).
