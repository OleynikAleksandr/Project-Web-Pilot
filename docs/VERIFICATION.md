## Реальная проверка прототипа

1. Запустить новое приложение на Mac пользователя. Видны собственный сайдбар и реальный ChatGPT в одном окне; пользователь проходит вход доступным штатным способом.
2. Выбрать подготовленный тестовый workspace. Для первого read-only опыта допустим WF001; путь записать явно, заранее сохранить его Git-состояние.
3. Приложение проверяет и при необходимости запускает существующие MCP/tunnel. Приложение получает полный пакет; доступ к tools у агента требуется для дальнейшей работы с файлами.
4. Приложение само отправляет ровно одно стартовое сообщение без копирования пользователем. В нём правильные workspace, новые идентификаторы и весь recovery packet.
5. Агент кратко подтверждает получение и описывает проект без дополнительного вызова инструментов. Сайдбар показывает «Контекст передан» для выбранного проекта и версии.
6. Сохранить небольшой отчёт: версии приложения/Electron, путь и project_id, chat URL/ID, session_id, request_id, размер/hash пакета, факты, время и видимый результат. Не сохранять cookies, ключи или полный приватный контекст в отчётах.
7. Сравнить Git тестового workspace до/после. Первый сценарий не меняет его файлы.

Только после этого можно считать основную цепочку прототипа проверенной. Пользователь подтверждает физический результат. Если вход, плагин или поле недоступны, сохранить точную причину и наблюдение; не объявлять успех по одному рендеру окна.

## Повторный запуск и ошибки

Проверить сохранённый вход и привязку чата, повторное открытие без дублирующего сообщения, другой workspace во время работы чата, существующий черновик, продолжающуюся генерацию, пропавший MCP tool, неготовый tunnel, таймаут Send с неизвестным исходом, изменившийся план, неправильный session_id и прежнюю доставку. Автоматический повтор не должен создавать второй пользовательский ход при неизвестном результате первого.

Закрытие окна не останавливает общие службы других чатов. Подключение существующей папки и её план в будущих этапах не должны сбрасываться. Встроенный браузер не заменяется внешним как неявный способ засчитать проверку.

## Что не считается приёмкой

- Наличие hooks.json, новый plugin metadata или ручной workflow_context_hook.
- ACK из прежнего теста или подтверждение, отправленное самой оболочкой вместо агента.
- Рабочий MCP в Safari как доказательство входа и работы встроенного Chromium.
- Успешная сборка как доказательство пользовательского сценария.
- Пауза, reconnect, счётчик сообщений или новый пакет как доказательство auto compact.
- Кросс-сборка как доказательство запуска на Windows.

## Комплектный runtime после установки Apple — C011

На чистом клоне после завершения Apple Command Line Tools подготовка остановилась, после перезапуска показан MAC_RUNTIME_EXTERNAL_MODIFIED. Ошибка не доказывает проблему интернета или изменение файлов пользователем.

MacRuntimeBootstrap принимает эту точную поставляемую версию через существующий facade, возвращает facade также после первой установки и отличает собственную папку от внешней. Управляемый Python получает явно заданное окружение. Регрессия использует реальный ZIP, проверяет первый запуск, повтор после регистрации собственной папки и отказ для изменённых файлов. Основной MCP и профиль не меняются.
