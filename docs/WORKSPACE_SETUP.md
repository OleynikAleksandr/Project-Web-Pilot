# Создание и подключение workspace

Контракт Web Pilot 0.6.97 / Workflow Kit 1.6.0. Kit находится в packages/workflow-kit этого репозитория; Web Pilot Sidebar — отдельный потребитель browser-адаптера.

## Пользовательский сценарий
«Создать проект»: сначала явно выбрать расположение папок, затем имя. Выбор сохраняется между запусками; отмена не подставляет VSCODE и не создаёт каталог. «Изменить расположение» заменяет сохранённый путь; открытие существующего проекта его не меняет.
Preview показывает конечный путь и добавляемые файлы. Chat/Work одной операцией применяет preview и открывает первую сессию; персональные имя/email не запрашиваются. Повторное открытие зарегистрированного проекта не создаёт сессию. «Открыть папку» принимает и Git-подкаталог, показывая фактический корень перед подтверждением. Новый Chat/Work доступен в меню ⋯ проекта.

Если Kit отсутствует, предлагается подготовка; отсутствующие команды/hooks совместимой установки можно восстановить. Изменённое ядро, повреждённый current plan, отсутствующие required-документы и неизвестная версия блокируют запись. Doctor/Recheck показываются по причине, не на успешном preview. Отмена или ошибка сохраняют прежний чат.

## Preview/apply и сохранность
Preview не меняет проект. Apply принимает одноразовый непрозрачный token основного процесса, привязанный к папке/режиму/fingerprint, и перепроверяет состояние. Изменение папки требует нового preview. Интерфейс недоступен странице ChatGPT.

Установщик сохраняет пользовательские документы/AGENTS/hooks и дополняет только управляемые секции. Чужие изменения не присваиваются служебному коммиту, исходный staging сохраняется. Если install:commit ещё ожидается, это показывается явно. При отсутствующей Git identity используется только локальная служебная Web Pilot <web-pilot@localhost>; имеющиеся полные или частичные значения сохраняются, глобальная конфигурация не меняется.

## Состав Kit 1.6.0
Новый workspace получает служебные файлы/шаблоны/команды, AGENTS с указанием recovery, README и docs/architecture/OVERVIEW.md, один current todo-plan в NONE. README — пользовательский документ, его отсутствие не делает новый формат неготовым. OVERVIEW — обязательный общий источник. Модули и рабочие спецификации создаются по мере необходимости.

Упразднённые MODULES, DOCUMENTATION_INDEX, PRODUCT, WORKFLOW_START и ARCHITECTURE заново не создаются и не дополняются установщиком. Старые документы до согласованной миграции читаются; их required-ссылки нельзя оставлять на отсутствующие файлы. Legacy MODULES/INDEX в recovery — проверенные ссылки с размером.

Обновляемые версии берутся из единого upgradeFrom установщика, включая 1.5.6. Новый runtime принимает budget с soft_tokens/hard_tokens и без них. Установленный runtime и его Kit-секция AGENTS вручную не редактируются.

## Обновление и история
Установка/upgrade используют проверку owned/managed файлов, backup и служебный коммит kit-update. Current todo-plan — единственный источник состояния, повреждённый план не заменяется догадкой. Legacy by-id/by-session и archive больше не создают копий: удаление возможно только для tracked-файлов, совпадающих с HEAD и index. Изменённый, отсутствующий tracked или untracked файл останавливает удаление. История сохраняется в Git.

Обновление приложения и установленного Kit — разные операции. В текущем scope T005 собирает приложения старым Kit, T006 начинает задачу старым, устанавливает приложение, выполняет install --update и завершает задачу новым Kit. До T006 конфигурация сохраняет обязательные поля 1.5.6. [Полный переход](planning/workflow-kit-context-transition.md).

## Readiness и кеш
Проверяются manifest/integrity, инструкции/required-документы, current plan/Git references, launcher/hooks и COMPLETE recovery. Historical payloads не восстанавливаются и не блокируют готовность. Реальный SessionStart/auto-compact не является условием открытия и не выдаётся за проверенную доставку.

Worker использует согласованную полную инспекцию; inputKey зависит от содержимого, Git/index/hooks, конфигурации/runtime, planning/NONE-источников, transaction/evidence. Ключ меняется и при повторной правке уже dirty-файла того же размера. Источник кеша recovery — этот же readiness key; отдельного contextInputKey нет.

Сохранённый чат открывается после короткой проверки identity/пути, полная ready выполняется в фоне. Для новой отправки она обязательна. Cache hit подтверждается свежим ключом, параллельные проверки объединяются; preview/apply и ремонт кешем не подменяются. При ошибке — повтор/Doctor, без скрытого пропуска проверки. Активная commit transaction не разрешает ready.

## Окружение
Рабочее приложение использует Node 24.21.0; допустимый worker Node — ^24.21.0, проверяется централизованно. Сам Kit поддерживает Node 22+. Generated resources/workflow-kit создаётся перед start/test/smoke/build из getRuntimeRoot(); готовое приложение самодостаточно. Worker — отдельный Node-процесс с явной папкой и JSON, не Electron под видом Node.

Windows прежде запуска worker получает проверенные WORKFLOW_GIT_BIN/WORKFLOW_GIT_HOME/Path из распакованных vendor-компонентов MinGit. Для подготовки Git-проекта Codex и запущенные службы не нужны; для последующих локальных инструментов нужен Codex. NODE_OPTIONS/NODE_PATH очищаются только в дочернем Windows-процессе независимо от регистра; системное окружение не меняется. Неработающий кандидат Node не мешает поиску другого. NODE_MISSING/TOO_OLD/START_FAILED различаются, stderr/окружение не раскрываются.

На новом Mac Git/Apple Command Line Tools проверяет мастер; установка подтверждается пользователем, завершение обнаруживается автоматически. MCP и туннель обслуживает существующий runtime/общий мастер, их ключи в проект не переносятся.

## Доктор и проверка
Doctor запускается явным действием и чинит только известные служебные неисправности с backup; неизвестные правки и потерянные пользовательские документы не перезаписываются. После ремонта повторяется полный readiness. [Контракт Доктора](modules/project-doctor.md).

Проверки: workspace-setup, project-doctor, session-plans, workflow-kit-recovery/source; runtime/upgrade fixtures и переход 1.5.6→1.6.0. Electron fixture проверяет форму и первую сессию. Live ChatGPT, чистая установка и нативная Windows — отдельная пользовательская приёмка; успех Mac-тестов её не заменяет.
