# Перенос на Windows 10/11

Последняя сборка, проверенная упаковщиком и описанная в этом checkout: **Project Web Pilot 0.6.40, x64**. Архив `Project-Web-Pilot-0.6.40-Windows-x64.zip` подготовлен в `.harness/runtime/releases/0.6.40/` на Mac. SHA-256 архива: `c2961ca920281188795f10db2c7cb8f134229ffd68bf2885c9040f23816d728e`. Все исходники по-прежнему принадлежат одному репозиторию `OleynikAleksandr/Project-Web-Pilot`; отдельный исходный проект Win Project Web Pilot больше не нужен.

1. Перенесите ZIP на Windows и полностью распакуйте его в новую папку на локальном диске.
2. Закройте старый Web Pilot. В распакованной папке `Project Web Pilot-win32-x64` запустите `Project Web Pilot.exe`.
3. Сохраняйте вместе EXE, папку `resources` и остальные файлы. Запуск из просмотра ZIP или перенос только EXE не является установкой полной сборки.
4. Откройте нужный проект. При ошибке подготовки запустите «Доктор проекта» в Settings или с экрана ошибки; затем проверьте прежнюю и новую сессию.
5. Если ошибка повторится, сохраните полный текст сообщения и версию приложения. NODE_MISSING, NODE_TOO_OLD и NODE_START_FAILED теперь различают отсутствие Node, старую версию и отказ запуска.

Portable Node.js 22.17.0 включён; отдельно устанавливать Node для этой готовой поставки не требуется. Исправление очищает внешние NODE_OPTIONS/NODE_PATH только у дочерних Windows-процессов. Существующие проекты и пользовательские данные не нужно переносить в папку приложения или удалять.

Контрольные суммы обеих поставок находятся рядом в `SHA256SUMS.txt`; файл проверен после упаковки. Для 0.6.40 также подтверждена целостность ZIP, версия 0.6.40 внутри Windows `app.asar` и побайтовое совпадение всех 38 файлов src и 32 файлов resources с source.

Сборка и автоматические проверки пройдены на Mac; реальный запуск на Windows 10 ожидает пользовательской проверки. Актуальный scope и его приёмка определяются todo-plan.
Редактор цветов: Settings → «Цвета чата…». В отдельном перемещаемом окне выберите фон чата, плашку пользователя, фон поля ввода и цвета текста обеих сторон; изменения видны сразу и сохраняются автоматически. «Вернуть оформление ChatGPT» снимает все пять переопределений. Копия архива на Mac для переноса: `~/Downloads/WebPilot-0.6.40/`.

## Порядок выявления и исправления препятствий Windows

Первый проход начинать с полной распакованной поставки на чистом госте, без предварительной установки Chrome, ChatGPT, Node, Git, Python, MCP или туннеля. Личный вход/создание аккаунта и разрешения выполняет пользователь; готовность проверяет приложение. Наличие portable-компонентов в ZIP не доказывает, что их запуск и весь мастер работают на Windows.

На первом препятствии записать версию, шаг, точное сообщение, длительность ожидания, скриншот и безопасную диагностику. Внешняя подсказка агента в обход недостающего интерфейса считается выявленным недостатком. Отдельно проверить платформенный мастер: автоматическое считывание ID/ключа в 0.6.39–0.6.40 реализовано для macOS и не считается готовым Windows-сценарием.

После установления причины следующий агент добавляет в свой план узкие задачи: исправление через существующие WindowsRuntimeBootstrap/Runtime Lifecycle/WorkspaceSetup, проверка, согласованная сборка обеих платформ и повтор на новом клоне. Сохраняются настройки и уже установленное; повтор после отказа не создаёт дубликаты и не требует ручных команд пользователя. Чужие процессы, рабочий runtime основного Mac и секреты не затрагиваются. Без выявленного дефекта искусственные изменения Windows не требуются.

## Оставшиеся критерии пользовательского прохождения

1. На новом клоне пройти установку/распаковку, открытие ChatGPT и вход либо регистрацию, подготовку компонентов и подключение к файлам по подсказкам поставки и приложения.
2. Создать первый проект: до первого явного выбора папка не подставляется, после выбора расположение сохраняется; изменение и отмена работают также после перезапуска. Нажатие Chat/Work применяет показанные изменения и создаёт одну первую сессию.
3. Получить полный контекст и ответ агента, затем поручить безопасное действие с отдельным тестовым файлом внутри гостевого проекта и проверить фактическое изменение. Рабочий MCP основного Mac не является доказательством работы гостя.
4. Проверить замеченные ошибки, повтор, отмену/возврат, перезапуск приложения и ОС. Настройки, вход, проекты и установленное сохраняются; нет необъяснённого ожидания и повторной установки.
5. Записать версию/хеш окончательного пакета, гостевую ОС/архитектуру, наблюдения и пользовательскую оценку полного пути. После каждого исправления повторять сборку и чистую проверку.
6. Windows 11 ARM64/x64-эмуляцию и нативную Windows x64 оценивать отдельно. Ни упаковка, ни macOS fixtures не закрывают гостевые критерии.

Для macOS в истории приняты 0.6.38 и 0.6.39. Пользовательская проверка нового выбора расположения 0.6.40 и отдельное доказательство изменения гостевого файла остаются явно ограниченными, см. docs/CLEAN_INSTALL.md. Закрытие 031 по поручению пользователя не меняет эти факты и не закрывает план first-run-corrections-032 другой сессии.
