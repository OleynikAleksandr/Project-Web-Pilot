# Перенос на Windows 10/11

Текущая поставка — **Project Web Pilot 0.6.41, Windows x64**, собранная вместе с macOS arm64 из одного репозитория. Исходный проект Win Project Web Pilot не нужен.

## Файл для переноса

`~/Downloads/WebPilot-0.6.41/Project-Web-Pilot-0.6.41-Windows-x64.zip`

- Project-Web-Pilot-0.6.41-macOS-arm64.zip: 181060637 bytes; SHA-256 `3fe1c59871c420eac939b2ca23998f8e5c66842434dbf7fe22c51f8231dedc00`.
- Project-Web-Pilot-0.6.41-Windows-x64.zip: 316332963 bytes; SHA-256 `8830efbfe1fe339f724709a0a1e4c3818fa0df0a2dd794b01d83d31429e597ac`.

Контрольные суммы, инструкция и общий manifest лежат рядом. Полностью распакуйте ZIP на локальный диск Windows; запускайте `Project Web Pilot.exe` из полученной папки. Не переносите один EXE отдельно от resources. Для обновления завершите старое приложение и распакуйте новую поставку в отдельную папку; данные аккаунта и проектов в пользовательском профиле сохраняются.

## Первый запуск

Мастер «Начнём работу» теперь включён и в Windows. Он доступен повторно через «Начальная настройка» внизу сайдбара и настройку подключения Windows.

1. Войти в ChatGPT на странице справа.
2. Дождаться подготовки комплектных Python, Git, MCP и tunnel-client. Отдельная установка системного Git/Node не требуется; переносимый Node включён. Для загрузки зависимостей может потребоваться интернет.
3. Создать отдельный туннель для этой Windows в той же организации OpenAI и связать его с пространством ChatGPT. Скопировать tunnel_id, затем личный ключ с Tunnels Read + Use. Мастер переходит между шагами автоматически. Ручной ввод открывает системное окно Windows; ключ скрыт и сохраняется через DPAPI текущего пользователя, не в renderer/diagnostics/argv.
4. В ChatGPT Plugins добавить или проверить **Codex Local Windows MCP**, Connection: Tunnel, выбрать туннель этой Windows, No Auth. Работающая служба туннеля ещё не доказывает выбор правильного подключения в ChatGPT; одно имя плагина тоже недостаточно.
5. Создать первый проект на локальном диске гостя, выбрать расположение папок и Chat/Work. Полный контекст отправляет приложение первым сообщением.

Туннель и подключение Mac остаются отдельными. Установленные совместимые компоненты переиспользуются. Отмена ручного ввода или неверные данные не меняют сохранённую конфигурацию; ошибки показываются в мастере с возможностью повтора.

## Доказательства и самостоятельная проверка

Оба ZIP, версии и упакованные src/resources сверены. Автоматические проверки выполнены на основном Mac. Пользователь сам проводит все дальнейшие проверки; агент не запускает UTM и не использует Computer Use по прямому поручению 18.09.2026.

Windows 11 ARM64 в UTM запускает x64-приложение через эмуляцию; это отдельный результат от нативной Windows x64. Запуск и вход в 0.6.40 подтверждены пользователем, Windows-мастер 0.6.41 и работа MCP пока не приняты.

Оставшийся пользовательский результат: пройти мастер, подключить правильный туннель, создать проект, получить краткое восстановление контекста, попросить агента прочитать/изменить тестовый файл только в гостевом проекте и проверить сохранение готовности после перезапуска. Реальные ключи, профили браузера и проекты с Mac не переносить в тестовый архив.

Если копирование большого ZIP через общую папку UTM сообщает 0x800700DF, это проблема переноса WebDAV, ранее наблюдавшаяся для 301 МБ, а не запуска приложения. Не считать успешно переданной неполную копию; сверить SHA-256.

Scope выпуска — windows-onboarding-033 собственной сессии; планы 031 и 032 не изменяются. Реестр наблюдений — docs/CLEAN_INSTALL.md, контракт — docs/modules/first-run-onboarding.md, детали выпуска — docs/RELEASE.md.
