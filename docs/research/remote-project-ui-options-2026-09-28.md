# Удалённая панель Project Web Pilot: MCP UI или мобильное приложение

Связанные проекты (02.10.2026): **Workflow Kit** — планы и recovery; **Web Pilot Sidebar** — отдельно разрабатываемый браузерный интерфейс. [Рабочие каталоги и границы интеграции](../SOURCE_WORKSPACES.md).

Дата исследования: **2026-09-28**. База: Web Pilot **0.6.58**, Workflow Kit **1.5.0**. Scope: `remote-project-ui-research-20260928`.

## Основания и границы

Пользователь подтвердил синхронизацию одного разговора между Project Web Pilot, ChatGPT Desktop на Mac и ChatGPT на iPad. Это наблюдение о переписке; оно само по себе не доказывает поддержку custom UI, закрепление PiP, автоматическое обновление данных или выполнение нового MCP-вызова из каждого мобильного клиента. Новый scope исследовательский: приложение, службы, tunnel и чужие проекты не изменяются; реальные device/host tests в нём не выполняются.

Задача — добавить видимость проектов, разговоров и единственного current plan, сохранив уже работающий канал общения. Один checkout/worktree остаётся источником текущего плана; интерфейс на другом устройстве не получает собственного плана или копии задач.

Владельцы данных по действующим контрактам: Workflow Kit — plan/tasks/revision; Workspace & Sessions — проекты, сохранённые chatUrl и разговоры; Runtime Lifecycle — доступ к локальному исполнителю. Основания: [модули](../MODULES.md), [сессии](../modules/workspace-sessions.md), [действующий план](../modules/session-owned-plans.md). Данные из текущего чата и локальных файлов отделены ниже от публичной документации и проектных предложений.

## Вариант A — дополнительный MCP plugin с UI внутри ChatGPT

### Возможность и назначение

Да: MCP Apps позволяет связать инструмент с HTML UI resource и отображать результаты в поддерживающем клиенте. Документация OpenAI предусматривает inline, fullscreen и PiP. UI может запрашивать данные через tool bridge; это не требует отдельного модельного API. Это основа для информационной панели, но не право изменять произвольные области интерфейса ChatGPT. [S01–S03, S05]

Для нашей задачи предлагаются два уровня: компактная PiP-карточка текущего плана и подробный список по кнопке. В компактной карточке достаточно имени проекта, scope, выполнено/всего, текущей задачи, revision и времени последнего успешного чтения. Постоянное полное дерево всех проектов в PiP перегрузит небольшую область. Inline остаётся запасным отображением, а fullscreen нужен для деталей, не как обязательный основной экран.

PiP закрепляется внутри ChatGPT, а не поверх любых приложений операционной системы. Его жизненным циклом и доступной геометрией управляет host. Reference отдельно предупреждает, что на мобильном устройстве запрос PiP может стать fullscreen. Наличие API запроса режима не гарантирует его принятие. [S01, S03]

Важная неопределённость: справка о custom/developer-mode MCP apps и руководство по общим UI-возможностям имеют разную область применимости. Нельзя ни объявить все виды apps недоступными на мобильных устройствах, ни обещать, что private plugin автоматически получит все мобильные UI-возможности. В отчёте не выбрана удобная версия противоречия: совместимость ограничена наблюдаемыми фактами и требует отдельного smoke test. [S03, S04]

### Снимок состояния не равен живому мониторингу

Предлагаемый render-tool открывает UI один раз; отдельный read-only data-tool возвращает новое состояние без создания новых карточек на каждую проверку. OpenAI описывает такое разделение render/data tools. Каноническое состояние должно жить на серверной стороне, а не в widgetState или localStorage. [S02]

Для первого эксперимента: ручная кнопка «Обновить». Затем — ограниченный опрос, только пока панель видима, с паузой при скрытии, backoff после ошибки и обязательным свежим чтением при возврате. Начальный инженерный ориентир — 5–10 секунд, а не обещанная частота: допустимость и задержку tool-вызовов во время генерации нужно измерить. Если host не допускает обновление, это ограничение продукта, а не повод выдавать старый снимок за live.

Время обновления, revision и явные состояния «Mac недоступен / данные устарели» обязательны. Успешное чтение должно возвращать новые данные; наличие старой карточки и сообщения в облачной истории недостаточно. Несколько устройств могут видеть разные по свежести снимки; следующий успешный read должен свести их к одному canonical revision. Состояние закрепления/раскрытия панели на каждом устройстве не следует считать синхронизированным с перепиской.

### Список сессий и навигация — разные функции

Показать разговоры Web Pilot можно по его локальному registry. Но чтение списка, выбор проекта в панели и переключение native ChatGPT conversation — разные операции. Документированный `openExternal` открывает внешнюю ссылку, а не обещает переключить центральный разговор Desktop. Анонимизированный `openai/session` пригоден для корреляции, но не является нашим sessionId или подтверждённым conversation URL. [S03]

Предлагается передавать явный project/worktree reference в каждый read. Не выбирать адресата по глобальному «сейчас открыт на Mac»: другой пользовательский клик может изменить его, пока на телефоне открыт прежний проект. Открытие другого разговора не должно создавать/переключать plan. В первой версии список разговоров информационный; управление native navigation не входит в критерии успеха.

### Нужен ли отдельный сервер и tunnel

Отдельный plugin — разумная изоляция read-only UI от мощного локального executor, но новый plugin не обязательно означает новый процесс или вторую систему состояния. Итоговый endpoint/маршрутизация зависят от возможностей действующего сервера; они здесь не проверялись и не перенастраивались. Для первого эксперимента production connector следует оставить нетронутым.

Secure MCP Tunnel — путь приватного MCP к поддерживаемым OpenAI-клиентам, не универсальная публикация HTTP-панели для Safari. Документация также отличает private developer connection от публичной публикации plugin: последняя требует доступного HTTPS MCP endpoint. Следовательно, «просто опубликовать plugin ради мобильного доступа» — отдельная задача, не бесплатное следствие наличия tunnel. [S08]

## Вариант B — Web Pilot для iOS и Android

### Это не дополнительная сборка Electron

Официально Electron поддерживает macOS, Windows и Linux, но не iOS/Android. Поэтому изменить только build target существующего приложения нельзя. HTML/CSS/часть JavaScript можно использовать повторно; Electron main process, IPC/preload, управление окнами и локальные Node.js/Git операции потребуют другого размещения или адаптации. Это инженерный вывод из платформенных границ Electron и текущей архитектуры Web Pilot. [S09]

Для удалённого сценария переносить исполнителя на телефон не требуется. Предлагаемая граница: Mac сохраняет Git checkout, Workflow Kit, файлы и исполнение; мобильный клиент отображает состояние и передаёт разрешённые запросы. Когда Mac недоступен, клиент показывает последний снимок как устаревший, а не обещает продолжение локальной работы на телефоне.

### Два существенно разных мобильных продукта

**B1. Полный интерфейс с собственным списком проектов и встроенным ChatGPT.** Ближе всего к настольному Web Pilot: приложение управляет своей компоновкой и открываемым веб-разговором. Однако вся связка требует проверки: вход в ChatGPT, сохранение авторизации, открытие существующего chatUrl, потоковые ответы, клавиатура, загрузка файлов, микрофон и восстановление после ухода в фон. Работа одного URL в Safari не подтверждает тот же сценарий в embedded WebView.

Capacitor — существующая web-first основа для iOS/Android/PWA. На iOS используется WKWebView; Android использует Android WebView. Это не перенос комплектного Electron Chromium на оба устройства. Browser plugin на iOS открывает SFSafariViewController: удобный поддерживаемый браузерный путь, но вызов Browser.open сам по себе не даёт управляемую область ChatGPT рядом с нашим sidebar. [S10–S13]

Отдельный блокирующий риск — вход через стороннего провайдера. Например, Google документирует disallowed_useragent для встроенных user agents, включая WKWebView. Это не доказательство запрета всех способов входа в ChatGPT, но достаточная причина проверять реальные используемые способы авторизации до разработки полного мобильного UI. Открытие OAuth в системном браузере не является доказательством передачи готовой ChatGPT-сессии в нашу WebView; копирование cookies/секретов не предлагается. [S14]

Для App Store действуют дополнительные условия: требования к браузерному движку и самостоятельной функциональной ценности приложения. У Apple есть исключения для альтернативных движков по специальным условиям, поэтому абсолютное утверждение «на iOS возможен только WebKit» некорректно. Но планировать обычный прототип вокруг таких исключений для этой задачи неоправданно. Публикация полезной панели возможна как отдельный этап, но не гарантируется фактом успешной локальной сборки. [S15]

**B2. Мобильная панель-компаньон без встроенного ChatGPT.** Показывает проекты, current plan, задачи, состояние Mac; разговор остаётся в официальном ChatGPT или обычном браузере. Устраняется необходимость воспроизводить вход, голос и веб-интерфейс ChatGPT. Взамен на телефоне пользователь переключается между разговором и панелью: это не обещанный постоянный sidebar рядом с native ChatGPT.

Для B2 сначала достаточно адаптивного web UI; устанавливаемая web/PWA-форма или Capacitor-оболочка нужны только при подтверждённой потребности. Это не предложение заменить принятый desktop Web Pilot внешним браузером: рассматривается отдельный удалённый экран. Разработка двух отдельных нативных интерфейсов на Swift/Kotlin сейчас не даёт преимуществ, соразмерных дополнительной работе.

### Доступ мобильного клиента к Mac — отдельный вопрос

Наличие Secure MCP Tunnel означает доступ поддерживаемого OpenAI-клиента к private MCP, но не даёт произвольному мобильному приложению URL для чтения нашего HTTP dashboard. Для B1/B2 потребуется свой разрешённый путь к read-only API: аутентифицированный HTTPS endpoint либо доступ через частную сеть. Конкретный вариант выбирать после определения личного/распространяемого использования; новый транспорт в этом исследовании не создаётся. [S08]

В обоих мобильных вариантах никакие SSH, Git или shell инструменты на устройстве не нужны для простого наблюдения за проектом. Сам факт установки приложения также не устраняет доступность Mac, ограничения сети и авторизацию.

## Сопоставление и решение

**Рекомендация: начать с ограниченного read-only MCP UI эксперимента на реальных целевых клиентах, а не с полного мобильного Web Pilot.** Это вывод о следующем шаге, не обещание универсальной совместимости. Поддержка панели внутри ChatGPT на iPad/iPhone остаётся критерием проверки, а не установленным фактом.

| Критерий | A: MCP UI внутри ChatGPT | B1: мобильный Web Pilot со встроенным ChatGPT | B2: отдельная мобильная панель |
| --- | --- | --- | --- |
| Продолжать уже открытый разговор | Сохраняется родной интерфейс, если host поддерживает UI | Нужно открыть и авторизовать веб-разговор внутри приложения | Разговор остаётся в другом приложении/вкладке |
| Контроль над нашей панелью | Ограничен режимами и жизненным циклом host | Собственная компоновка приложения | Собственная адаптивная компоновка |
| План рядом с разговором на телефоне | Не гарантирован: PiP может стать fullscreen | Собственную компоновку можно разработать, но малая площадь остаётся ограничением | Не обещается: обычно переключение экранов |
| Основной технический риск | Реальная поддержка private plugin, обновлений и PiP | Embedded login, WebView и полный цикл мобильной поставки | Защищённый доступ к Mac и удобство переключения |
| Новая авторизация в ChatGPT | Не нужна как отдельная функция нашей панели | Требуется проверка авторизации своей WebView | Не нужна нашей панели; вход в API панели отдельный |
| Повторное использование | MCP examples, прежний UI, canonical Kit | Web UI и данные; Electron runtime не переносится | Web UI и данные, без повторения ChatGPT |
| Относительная работа для первого результата | Наименьшая при работающем host; ранний тест решает | Наибольшая из этих вариантов | Меньше B1, но больше одной MCP-карточки из-за собственного доступа |

Фактические ограничения таблицы обоснованы [S01–S04, S08–S14]; оценки объёма и приоритетов — инженерные выводы, не измеренный срок или бюджет.

У вариантов разные критерии успеха. Для «видеть ход работы не уходя из уже открытого ChatGPT» сначала проверяется A. Для «полностью владеть интерфейсом независимо от возможностей ChatGPT» подходит собственная панель B2, но она честно предполагает отдельный экран. B1 оправдан только при отдельном требовании иметь собственный мобильный браузерный клиент ChatGPT вместе с панелью.

Не нужно сразу реализовывать все три. Небольшой общий read-only фасад данных позволит выбрать один UI после проверки, не создавая вторую систему проектов и планов. Не следует заранее строить универсальную платформу виджетов, редактор UI, push-инфраструктуру или новый менеджер задач.

## Данные, полномочия и обновление

Предлагаемый минимальный snapshot: projectId/worktreeRef, scopeId, planRevision, scope/delivery status, currentTask, completed/total, задачи с implementation/commit status, observedAt и availability. Это предложение контракта, не уже существующий endpoint. Разговоры читаются отдельно из Web Pilot registry; они не становятся владельцами задач.

Панель должна быть привязана к явно выбранному проекту. Переключение проекта в окне Mac не меняет молча адресата панели на телефоне. Два читателя допустимы; параллельные изменения того же checkout не означают двух независимых исполнителей.

Первая версия — чтение, раскрытие подробностей и «Обновить». Позднейшие команды управления должны идти через существующие фасады и Workflow Kit, с проверкой полномочий, ожидаемой revision и защитой от повторного запроса. Нельзя дать браузерной кнопке произвольный shell или право непосредственно переписывать todo-plan.md. Архивирование, удаление и запуск новой работы требуют явного поручения пользователя; устаревшая панель не должна менять другой scope.

Для внешнего API обязательны аутентификация, ограничение допустимых проектов на сервере и отсутствие секретов в HTML/URL. Для MCP нужны корректные read-only annotations и разрешения подключения, а не только надпись «read-only» в UI. Точный механизм аутентификации выбирается при отдельной реализации, готовый не заявляется. Смена UI-клиента не отменяет доступность локального runtime и tunnel.

| Проверка | Критерий успеха |
| --- | --- |
| Один настоящий проект | Панель получает канонический current plan 1.5.0, включая NONE; не использует owner_session_id |
| Разделение клиентов | Отдельно записаны tool-call, отображение UI, Refresh и фактический displayMode для desktop Web, Safari iPad/iPhone, native iPad/Desktop; Android не засчитывается по результату iOS |
| Работающий агент | Во время реальной следующей разрешённой задачи панель отражает start/commit/revision; проверка не подменена статическим JSON |
| Закрепление | После прокрутки сохраняется нужное представление; если host заменяет PiP на fullscreen, это явно показано пользователю |
| Идентичность проекта | Смена выбранного проекта на Mac не перенаправляет старую удалённую панель |
| Потеря связи и возврат | После недоступности Mac и возврата мобильного приложения нет ложного live-статуса; свежий read восстанавливает состояние |

Начать с ручного Refresh и двух кнопок: «Обновить», «Подробнее». Автоматическое обновление добавлять только после подтверждения UI и tool bridge. Повторное открытие панели на другом устройстве считать отдельной проверкой: синхронизация облачного сообщения недостаточна.

Условие остановки A: обязательный для пользователя клиент не отображает private UI либо не даёт приемлемо следить за текущим планом. Тогда не повторять эксперименты с управлением native ChatGPT navigation и не раздувать adapter; перейти к оценке отдельной B2-панели. Условие продолжения A: полезный UI реально работает на выбранных устройствах и показывает новые canonical revisions, после чего можно добавлять список проектов/разговоров и ограниченные команды управления.

## Проверка этого исследования

Выполнены чтение первичных источников, сравнение с действующими контрактами и чтение source старого adapter. Проверка research-report подтверждает наличие разделов/источников и отсутствие whitespace errors. Она **не проверяет** доступность custom plugin, отображение PiP, вход в ChatGPT WebView или live updates на устройствах.

Новый MCP, HTTP API, мобильная сборка, подключение, сертификаты, публикация, изменение production tunnel и GUI smoke не выполнялись. Продуктовая версия остаётся 0.6.58. Исследование даёт обоснованный выбор следующего эксперимента; поддержка всех устройств не объявлена готовой.
