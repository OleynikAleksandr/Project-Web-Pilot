# Краткая архитектура проекта

Исходники: Web Pilot **0.6.97**, пакет Workflow Kit **1.6.0**. Это карта устройства проекта, а не свидетельство установки или публикации. Факты поставки находятся в release-manifest.json и GitHub Release; ход работы — в текущем плане и Git.

## Назначение и границы

Electron-приложение объединяет встроенный ChatGPT Web и левую панель локальных проектов, чатов и плана. Модель работает через веб-аккаунт пользователя, без модельного API. Приложение готовит контекст; локальный Codex App Server исполняет команды через MCP. UI приложения и независимые службы исполнителя имеют разные жизненные циклы.

Один Git checkout/worktree имеет один current plan. Сессии Web Pilot хранят чат, URL и состояние интерфейса, но не владеют планом. Для независимой параллельной разработки нужен отдельный worktree. Переключение проекта в панели не меняет рабочую папку уже открытого чата.

## Поток новой сессии

Kit формирует recovery из Workflow Core, PROTOTYPE, проектных ограничений AGENTS, OVERVIEW и контекста плана. Kit-секция AGENTS повторно в ядро не попадает. README — пользовательский документ и не обязательный источник. ACTIVE включает все задачи, рабочую спецификацию и выбранные целые документы; NONE — общие документы, краткие строки задач прошлого плана и ссылки Git. Сырые JSON плана и diff не доставляются. Перед реализацией агент читает коммиты, диффы и код, от которых зависит задача.

Единый предел документа и части — `budget.document_bytes`, по умолчанию 28000 байт UTF-8 со служебным оформлением. Recovery ограничен 180000 байт и семью частями одновременно. Превышение даёт CONTEXT_TOO_LARGE без усечения. Старые MODULES и DOCUMENTATION_INDEX передаются проверенными ссылками; большой документ делится с пометкой «разделить при следующей правке».

Web Pilot проверяет актуальность пакета и прикрепляет все части через File/DataTransfer. После завершения загрузки отправляет одно короткое сообщение. В нём предписано читать каждое вложение отдельным вызовом, не объединять вывод и дочитывать при обрезке. В первом ответе разрешено чтение вложений, но не MCP проекта. Пакет готовится для новой сессии или явного обновления, не при обычном открытии сохранённого чата. Неопределённый Send не повторяется автоматически.

## События, состояние и безопасность

PageStateSource получает ограниченные наблюдения из sandboxed preload: документ, origin/frame, ревизии, busy, доступность редактора/Send, ошибки. Текст беседы, cookies и внутренние API не используются. Общий ContextCache привязан к workspace и фактическим входам Kit: повторная правка уже dirty документа меняет ключ. Перед Send состояние сверяется повторно.

PlanMonitor наблюдает файлы, AutoPlan — подтверждённые события паузы. Сохраняются выбор пользователя и идентичность обработанной паузы; загрузка истории, черновик, ручной Send и перезапуск не должны создавать дубль. AutoPlan передаёт короткое «Продолжай» с данными nextTask и не выдаёт их за новый scope. Завершение всех задач останавливает продолжение. Watchdog предупреждает, но не перезапускает работу агента.

ConversationRecovery обслуживает известный URL и распознанную терминальную ошибку потока; это не разрешение заново отправить recovery. Произвольный текст ответа не считается ошибкой интерфейса. Ручное чтение прерывает автопрокрутку; скрытие служебных карточек не скрывает ответы, файлы и запросы разрешений.

Профиль ChatGPT и локальное состояние приложения находятся в пользовательских данных, не в Git. Diagnostics сохраняет технические признаки и идентификаторы, не тела recovery и беседы. Секреты туннеля не переносятся в проект. Оформление, размеры окна/панелей и пять цветов сохраняются независимо от исполнения плана.

## Исполнитель и платформы

На macOS и Windows действует один backend Codex App Server и каталог из девяти MCP-инструментов: команды, stdin, patch, изображения, статус, watchdog и три инструмента наблюдения экрана. Контекст через MCP не передаётся; управления UI и модельных запросов нет. Codex устанавливается пользователем. Приложение использует Node 24.21.0; пакет Kit допускает Node 22+.

Службы живут независимо от окна приложения и запускаются при входе пользователя: LaunchAgent на macOS, HKCU Run на Windows. Канал Secure MCP Tunnel/VPS хранится в конфигурации исполнителя. VPS следует за текущим портом MCP. Windows использует из закреплённого runtime-архива только uv, tunnel-client, ripgrep и MinGit, а не старый сервер инструментов. Runtime bootstrap, worker и Python-компоненты сохраняют самостоятельные границы.

## Исходники и потребители

`packages/workflow-kit` — единственный источник Kit. `resources/workflow-kit` создаётся staging для приложения и не хранится в Git. `.harness/kit` — установленный runtime конкретного проекта, обновляемый установщиком; его нельзя подменять вручную при обычной работе.

Web Pilot Sidebar — отдельный репозиторий, повторно использующий три browser-модуля. Их публичные экспорты и формат pageScript совместимы; vendor lock обновляет владелец Sidebar. Production Host API — отдельная будущая работа. WF001 и прежний отдельный WorkflowKit не изменяются. [Границы репозиториев](../SOURCE_WORKSPACES.md).

## Переход и проверка

До T006 этот checkout работает установленным Kit 1.5.6. Старые soft_tokens/hard_tokens сохраняются вместе с document_bytes; удалять их раньше перехода нельзя. Установка нового runtime — отдельный служебный коммит kit-update между task:start T006 и commit T006. Проверки источников не доказывают, что новый Kit уже установлен.

DOCS обновляет контракты перед сборкой. Старый состав папок сохраняется до отдельной миграции Claude после T007 и возможных доработок, перед перезапуском пользователя. Две рабочие спецификации остаются до закрытия scope: [требования](../planning/workflow-kit-context-refactor.md) и [переход](../planning/workflow-kit-context-transition.md). Старые подробные документы и выпущенные planning описывают прежние решения; при расхождении доставки, recovery и lifecycle планов действуют эти спецификации и текущие контракты выше.

Node/Kit fixtures, Electron smoke и упаковка проверяют разные уровни. Реальный ChatGPT File/DataTransfer, чистая установка и native Windows остаются пользовательской приёмкой после нового выпуска. Ручное чтение семи файлов не подтверждает автоматическую вставку. Для macOS сохраняются filesystem identity корневого app и Finder-алиас; ZIP сам по себе не доказывает установку. Факты сборки, установки и публикации не подменяются текстом документации.
