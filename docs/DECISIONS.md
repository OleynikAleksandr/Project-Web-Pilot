## Delivery-порядок и единый управляющий plan — 03.10.2026

Пользователь установил жёсткий порядок для любых delivery-действий: `build/package/sign/notarize/release/publish` выполняются только в явно названной активной микрозадаче; относящиеся документы должны быть актуализированы и зафиксированы **до** build или GitHub publish. Для delivery-плана порядок — `работа → DOCS → delivery`; если build/publish не указан в плане, его не выполнять.

Если сессия открыта в Project Web Pilot и работа затрагивает связанный WorkflowKit, управляющим остаётся current plan **Project Web Pilot**. В WorkflowKit нельзя оставлять отдельный незавершённый current plan, иначе при открытии этого репозитория пользователь увидит ложную незавершённую работу. Технический managed scope в спутнике допустим только если его требуют hooks/transaction semantics и он закрывается/архивируется до контрольной точки; итоговый WorkflowKit current state для этой cross-repository работы — `NONE`.

Electron с WebContentsView используется для собственного Chromium и интерфейса. В T004 выбраны Electron 44.3.0 и @electron/packager 20.3.0; полный профиль записан в ARCHITECTURE. Смена продуктового решения о встроенном браузере требует обсуждения.

## Диагностический журнал Chromium — scope 005

## 05.10.2026 — причина correction release 0.6.93 для command tools

Пользовательская проверка опубликованной 0.6.92 подтвердила новый каталог из 13 инструментов и штатные сценарии, но выявила зависание `rg -n "add"` при `tty=false`. Причина установлена в `tools/codex-app-server-mcp/server.py`: `LocalFacade.exec_command` безусловно передавал `stream_stdin=True`, поэтому non-TTY процесс получал открытый stdin вопреки контракту Codex `rust-v0.160.0` (`process_manager.rs`: `stdin_open: tty`). Решение 0.6.93 — открывать stdin только для `tty=true`, хранить tty-режим command session и повторить поведение Codex для non-TTY `write_stdin`: пустой poll разрешён, одиночный `U+0003` завершает процесс, другой ввод получает точный `stdin is closed...` без остановки сессии.

В том же correction scope устранена отдельная задержка интерактивного ввода: прежний MCP применял 5000–60000 мс ко всем `write_stdin`, тогда как Codex 0.160.0 использует default 250 мс, 250–30000 для непустой записи и повышенный минимум только для пустого poll. Локальный предел poll остаётся 5000–60000 мс. Каталог 13 tools, `codex-tools.lock.json` и Windows-runtime не меняются.
