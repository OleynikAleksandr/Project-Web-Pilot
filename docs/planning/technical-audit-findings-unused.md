# T004 — Неиспользуемый код и зависимости

**Статус:** статическая проверка кандидатов, без удаления кода. Исходная линия и метод в [основном реестре](technical-audit-findings.md). Проверены явные ссылки `rg` в `src`, `tests`, `packages/workflow-kit/src`, `scripts`, `resources`; после поиска разобраны конкретные потребители, событийные, CLI, IPC, платформенные и внешние входы. Отрицательный поиск сам по себе не является доказательством ненужности.

## C-UNUSED-01 — переходные пути прежнего runtime (medium, не доказано, что можно удалить)

`src/main.mjs:73–74,254,814–827,1364–1366` сохраняет и обрабатывает `legacyMacRuntimeRetired` / `legacyWindowsRuntimeRetired`, `legacyRuntimeRoots` и запускает однократную утилизацию старой установки. `src/mac-runtime-switch.mjs:509–547` вызывает `retireLegacyRuntime`, для Windows — `src/windows-runtime.mjs:226` (`retireLegacyWindowsRuntime`); `src/platform.mjs:22` (`legacyWindowsStateFolder`) вызывается из `src/main.mjs:814`. `resources/runtime-control/windows-control.py` явно требуется в `scripts/verify-windows-package.mjs:69`, а `windows-first-run.py` **намеренно запрещён** строкой 70. В `tools/codex-app-server-mcp/control.py:572,623` учтён перенос туннеля и старый selector.

**Достижимость:** реальная ветка `main → runtime activation → retireLegacyRuntime`; наличие проверок `tests/windows-runtime.test.mjs:300–319` и `tests/mac-runtime-switch.test.mjs:412–425` подтверждает предусмотренный миграционный контракт. Это не мёртвый код лишь потому, что прежний сервер больше не используется. Удалять нельзя без согласованной политики поддержки обновления старых установок и Windows fixture; минимальное будущее действие — документально решить срок миграции и лишь затем удалить ветку и её потребителей единым изменением. Риск: потеря безопасной очистки старой службы/переноса туннеля на обеих ОС. Отдельный путь к внешнему Sidebar не затрагивается.

## C-UNUSED-02 — функции URL, видимые только тестам при узком поиске (low, НЕ удалять)

`src/workspace-session.mjs:28` (`conversationExperience`) вызывается при миграции сохранённых сессий внутри того же модуля (около строки 220), помимо `tests/workspace-session.test.mjs:290,473`; это динамически важный вход чтения устаревшего формата. `src/chatgpt-experience.mjs:36` (`isPendingChatGPTConversation`) используется в `src/context-session.mjs:121,227,254` для промежуточного URL после Send. `src/page-state.mjs:9` (`normalizePageObservation`) используется внутри `PageStateSource` (около строки 74). Следовательно, отсутствие большого числа внешних импортов этих символов не свидетельствует о ненужности. Упрощения не предлагаются.

## C-UNUSED-03 — адаптер Sidebar и сериализуемые функции (high contract risk, НЕ удалять)

`src/chatgpt-dom.mjs:63` экспортирует `chatGPTDOMScript`; `src/chatgpt-composer.mjs:9,211` экспортирует `pageOperation` и `pageScript`; `src/chatgpt-experience.mjs` — URL/experience API. Документ `docs/modules/chatgpt-dom-compatibility.md:58–65` закрепляет внешнего потребителя Web Pilot Sidebar, именованные импорты и формат сериализации, а `tests/chatgpt-composer.test.mjs:131–135` прямо проверяет контракт реконструкции `pageScript` из `pageOperation` и `chatGPTDOMScript`. `ComposerError` в `src/chatgpt-composer.mjs:4` намеренно внутренний, однако используется самим классом (`:260,308,339,389,428`). Нельзя объявлять экспорт неиспользуемым из-за отсутствия импорта в основном Electron-приложении; внешняя версия Sidebar не проверялась, соседний репозиторий не изменён.

## C-UNUSED-04 — IPC и событийные entrypoints (medium, нельзя решать по grep)

`src/main.mjs:569,585,937,1181,1227` регистрирует IPC handlers по строковым именам, `src/chat-colors-window.mjs:8` тоже регистрирует handlers; их потребители появляются через preload и renderer, не как JS-импорты. `src/page-state.mjs:1` определяет `PAGE_STATE_CHANNEL`, а `src/chatgpt-page-observer.mjs` формирует наблюдения внутри injected page script. `src/chatgpt-tool-filter.mjs:55` собирает executable string из `installToolFilter.toString()`; аналогично `pageScript` не требует обычного прямого импорта вызываемой функции. Факт невостребованности какого-либо канала **не установлен**: для решения нужна таблица соответствий `ipcMain.handle ↔ preload exposed API ↔ renderer call` с учётом динамических строк и событий; её проверка также относится к T005. Изменений не предлагать без доказанного отсутствия маршрута на обеих платформах.

## CLI, ресурсы, зависимости: проверенный охват и ограничения

Просмотрены декларации `package.json` и связи `scripts/workflow*` с `packages/workflow-kit/src/cli.mjs`, staging `scripts/stage-workflow-kit.mjs`, скрипты сборки/проверки и `tools/codex-app-server-mcp/control.py` как отдельные исполняемые входы. `resources/workflow-kit` и `resources/chatgpt-page-observer-preload.cjs` — генерируемые копии, не кандидаты на удаление источников. Платформенные entrypoints Windows CMD и macOS LaunchAgent не сводятся к Node-импортам. Для npm-зависимостей не проведено полноценное построение runtime/build графа; оснований рекомендовать удаление определённого пакета или ресурса пока нет. Нет подтверждённых недостижимых веток или неиспользуемых зависимостей с доказанной безопасностью удаления.

**Проверки будущего исправления:** fixture-тесты миграции старых runtime и сессий, контрактные тесты Sidebar wire format, IPC/preload consumer graph, platform-specific smoke после отдельного разрешения. Native Windows и чистую установку здесь не проверяли. **Итог:** обнаружены миграционные кандидаты на будущую ревизию политики, но подтверждённого безопасного удаления в проверенном объёме нет; отсутствие совпадений поиска не объявлялось достаточным доказательством.
