# Короткое стартовое сообщение MCP-сессии — релиз 0.6.88

Поручение пользователя 04.10.2026 после живой проверки 0.6.87: Web Pilot сам начинает сессию сообщением, которое заставляет агента получить контекст проекта через MCP.

## Что показала проверка 0.6.87

Новый чат с сообщением «Начинаем новую сессию.» — агент ответил без вызова `workflow_context_recover`: `instructions` сервера сами по себе вызов не гарантируют. С сообщением, называющим проект, папку и порядок чтения, агент сделал ровно два последовательных вызова (part=1; part=2 с ключом `after`), без обрезки, без `PART_ORDER`, без чтения файлов и git, sha256 обеих частей совпал.

## Результат

1. В режиме Codex App Server (macOS) новая сессия после подтверждения режима Chat/Work проверяет службы, записывает проект в `active-workspace.json` и **сама отправляет короткое стартовое сообщение** (до 1 КБ): проект, папка (JSON-строка), `workflow_context_recover` с part=1, затем каждую следующую часть отдельным вызовом с ключом `after` до `[КОНЕЦ ПАКЕТА]`, затем короткое подтверждение и описание проекта и состояния плана. Последняя строка — метка отправки `wp-request-…`: по ней Web Pilot узнаёт своё сообщение.
2. Пакет Workflow Kit не загружается и не вставляется; стартовое сообщение не устаревает при изменении плана.
3. Чат привязывается к проекту по отправленному стартовому сообщению (прежний механизм первого сообщения). Привязанный чат, чат, начатый пользователем вручную, и прежние чаты с переданным пакетом стартового сообщения повторно не получают — фаза «Чат проекта».
4. Черновик пользователя и идущая генерация откладывают стартовое сообщение, как и прежде; подготовленное сообщение другого режима доставки (полный пакет или стартовое) не отправляется.
5. Сайдбар: «Готовим стартовое сообщение» → «Начинаем сессию» → «Сессия начата» → «Чат проекта»; «Стартовое сообщение: Отправлено / Не отправлялось», «Пакет проекта: Агент читает через MCP», в подробностях — время стартового сообщения. Фаза `ready` («Можно начинать») удалена.
6. Codex Local Mac и Windows сохраняют доставку полного пакета первым сообщением.
7. Релиз **0.6.88**: версия → DOCS → парная сборка → установка → GitHub Release.
