# Push на GitHub только после DOCS — Workflow Kit 1.5.5

Поручение пользователя 04.10.2026: закрыть оставшуюся лазейку в порядке «документы → сборка → GitHub».

## Проблема

Порядок из [политики delivery](delivery-ordering-policy.md) в коде держится только для задач `verification_kind=package|installed`: они всегда после DOCS. Публикация исходников на GitHub без сборки защищена лишь текстом правил: если агент оформит её обычной задачей (`code`), Kit поставит её до DOCS, и push уйдёт с устаревшими документами.

## Результат

1. Управляемый `pre-push` hook (уже ставится Kit) отказывает в push, пока у текущего плана checkout есть незавершённая DOCS: ошибка `DOCS_BEFORE_PUSH` с scope и состоянием DOCS. Без плана (`NONE`) и после завершённой DOCS push разрешён — в том числе из delivery-хвоста после DOCS и после архивирования.
2. После `plan:extend`, который переоткрывает DOCS, push снова ждёт DOCS.
3. Форма плана (`plan:create --help`) и правила прототипа в recovery: публикация исходников на GitHub — отдельная delivery-задача после DOCS (`verification_kind=package` с проверкой удалённой ветки); push до завершения DOCS отклоняется hook; не обходить его `--no-verify`.
4. Новых полей схемы и эвристик по названиям задач нет. Версия **1.5.5**, upgrade-path 1.5.4 → 1.5.5.

## Проверка

- `runtime-fixture`: в delivery-фикстуре с локальным bare-remote push после T001/T003 до DOCS отклонён с `DOCS_BEFORE_PUSH`; после DOCS проходит; после повторного `plan:extend` снова отклонён.
- `package-check`: версия 1.5.5, число файлов и новый SHA-256 runtime.

## Границы

Hook проверяет только текущий план своего checkout. Обход `git push --no-verify` технически возможен и запрещён правилами. Проект, где Kit не установлен, не затрагивается.
