# Управляемая интеграция — рабочий контракт T004

Дополнение к [спецификации параллельного выполнения](parallel-execution-spec.md). При DOCS выпуска переносится в контракт Kit.

## Команды

Предшествующая выдача: `assignment:create/status/setup`. Журналы — в git-dir каждого worktree, без копии плана. Повтор create с тем же ID восстанавливает выдачу; `setup --npm-ci` готовит зависимости и pre-скрипты. DONE исполнителя — READY_FOR_INTEGRATION.

- `integration:start --input <JSON>`: `{id,source_commit}`, где id — назначение, source_commit — точный проверенный коммит исполнителя.
- `integration:status`: операция, задача, источник, конфликты и ошибка проверки.
- `integration:continue --id integration-<assignment-id>`: продолжение той же операции после исправления или прерывания.

Старт требует чистого main без другой задачи/Git-операции, завершённого назначения с чистым worktree и сохранённых успешных проверок source. Ветка исполнителя содержит ровно подготовку локального плана и один implementation-коммит; Kit проверяет контракт, область, базу, зависимости и идентичность назначения.

## Слияние и исправление

Git готовит merge без коммита. Только дочерний план заменяется исходным общим планом; исходники не разрешаются автоматически через ours/theirs. Установленные служебные файлы и конфигурация исполнителя не переносятся. Kit формирует завершение одной родительской задачи и запускает штатные hooks/назначенные проверки объединённого кандидата перед двухродительским merge-коммитом.

При конфликте общий план остаётся PENDING. Исправляющий агент работает в main в пределах задачи, явно устраняет конфликты и вызывает continue. Провал проверок также оставляет PENDING и незавершённое слияние. Чужие изменения не удаляются и не прячутся; они блокируют продолжение.

Журнал в git-dir main блокирует остальные записи Kit до подтверждённого завершения. Неизвестный исход merge не повторяется автоматически. Нет reset --hard, автоматической очистки, удаления веток или worktree.

## Доказательства и повтор

Коммит исполнителя однородительский. Интеграция имеет двух родителей: прежний main и точный source. Trailers содержат роль integration, ID операции и source SHA. Родительский план хранит эту идентичность, а integration SHA восстанавливается из Git; собственный хеш в создаваемый коммит не записывается.

Повтор восстанавливает ту же операцию после подготовки кандидата, создания коммита и сохранения доказательств. Успешное завершение отмечает назначение INTEGRATED. Fixture проверяет последовательные слияния независимых веток, базу зависимого назначения, конфликты, ошибку объединённых проверок, сохранение чужих изменений, CLI, сбои и отсутствие повторных коммитов. Native Windows и живой интерфейс этим тестом не проверяются.
