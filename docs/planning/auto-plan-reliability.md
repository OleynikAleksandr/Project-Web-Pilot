# Автовыполнение без ложных остановок

## Результат

Режим «Автовыполнение» сохраняет существующую схему: после завершения одной микрозадачи и её коммита Web Pilot проверяет фактический current plan и автоматически отправляет точное «Продолжай». Изменения этого scope устраняют ложные остановки, обнаруженные в реальной работе 02.10.2026, не превращая AutoPlan в отдельного агента и не добавляя новый планировщик.

После исправления пользователь не должен вручную писать «Продолжай» в случаях, когда агент способен продолжать самостоятельно. Остановка с ожиданием пользователя допустима только тогда, когда действительно требуется информация, выбор или решение пользователя.

## Подтверждённые причины текущих остановок

Диагностика 02.10.2026 показала, что автоматическое «Продолжай» само по себе работает, но цикл часто прерывается после этого:

- агент завершает ответ сигналом «Нужен ваш ответ.» даже при технической ситуации, которую можно исследовать и исправлять самостоятельно;
- watchdog через 3 минуты без наблюдаемого изменения текста переводит AutoPlan в paused, хотя ChatGPT всё ещё busy и позже продолжает выдавать результат;
- при наличии пользовательского черновика ChatGPTComposer правильно возвращает DRAFT_PRESENT и не затирает текст, но AutoPlan после этого полностью приостанавливается;
- состояние «Отправляем „Продолжай“…» существует слишком коротко, поэтому пользователь практически не видит факт автоматического продолжения;
- diagnostics пишет phase=paused без машинно-различимой причины, что затрудняет разбор реальных сбоев.

## Требуемое поведение

### 1. Сигнал «Нужен ваш ответ.»

Стартовая инструкция AutoPlan должна однозначно требовать этот сигнал только тогда, когда без информации, выбора или решения пользователя корректно продолжать невозможно.

Техническая ошибка, упавший тест, несовместимость, проблема сборки, Git/MCP или другая исследуемая агентом ситуация не являются основанием автоматически звать пользователя. Если агент может продолжить диагностикой или исправлением, итоговый сигнал остаётся «Готов продолжать.».

Существующие ограничения сохраняются: не более одной микрозадачи за turn, проверка и commit перед DONE, безопасная контрольная точка для длинной работы, запрет модельного делегирования без прямого поручения.

### 2. Watchdog не останавливает работающий turn

Три минуты без наблюдаемого текстового продвижения при busy=true становятся диагностическим предупреждением, а не причиной pause.

Web Pilot:
- не нажимает Stop;
- не отправляет повторное сообщение;
- не выключает AutoPlan;
- сохраняет текущий run и продолжает ждать штатного завершения turn;
- снимает/обновляет предупреждение при следующем наблюдаемом продвижении.

Терминальная ошибка связи, ручной Stop и другие уже существующие реальные причины остановки остаются отдельными.

### 3. Черновик не выключает AutoPlan

Если автоматическое «Продолжай» не отправлено из-за DRAFT_PRESENT:
- черновик пользователя не изменяется;
- режим остаётся включённым, но suspended;
- UI сообщает, что ожидается отправка пользовательского сообщения;
- после фактической ручной отправки сообщения в том же документе режим возобновляется через существующий resume-flow без дополнительного автоматического «Продолжай».

Это тот же принцип, который уже применяется после ручного ввода/Stop/вопроса агента.

### 4. Видимость автоматического продолжения

После успешной автоматической отправки «Продолжай» состояние sidebar должно оставаться понятным пользователю, например:

«Автовыполнение: автоматически отправлено „Продолжай“ №N — агент работает.»

Не требуется хранить историю текста чата или новый журнал действий. Достаточно счётчика текущего запуска и понятного статуса.

### 5. Диагностика причин

События AutoPlan должны записывать безопасный reason code для значимых остановок/ожиданий, без текста разговора. Минимально различать:
- AGENT_WAIT;
- DRAFT_PRESENT;
- MANUAL_STOP;
- MANUAL_INPUT;
- CONNECTION_ERROR;
- PLAN_CHANGED_OR_TRANSACTION;
- SEND_UNKNOWN;
- STALL_WARNING;
- NO_CHECKPOINT.

Набор кодов может быть расширен при реализации, если это требуется существующими ветками состояния.

## Проверка

Обязательны существующие Node tests и Electron smoke.

Проверки должны воспроизводить именно наблюдавшиеся сценарии:
- «Готов продолжать.» → план незавершён → автоматическое «Продолжай» действительно отправлено;
- busy остаётся активным дольше watchdog-порога → AutoPlan не переходит в paused;
- после watchdog-предупреждения последующий прогресс и завершение turn по-прежнему приводят к обычному продолжению;
- DRAFT_PRESENT не стирает черновик и оставляет режим способным возобновиться после ручной отправки;
- «Нужен ваш ответ.» по-прежнему ждёт пользователя и после его сообщения корректно возобновляется;
- видимый статус содержит устойчивый факт последней автоматической отправки, а diagnostics — reason code для пауз/предупреждений;
- смена разговора, connection error, неизвестный исход Send и завершённый план сохраняют fail-closed поведение.

## Границы

- Не переписывать AutoPlan с нуля.
- Не добавлять второй агент, модельный API, новый сервис или периодический polling Git.
- Не затирать пользовательский draft ради автоматизации.
- Не ослаблять проверки фактического current plan и Workflow Kit transaction.
- Не автоматизировать нажатие нативных safety/permission диалогов ChatGPT.
- Изменения относятся к Workspace & Sessions / AutoPlan и существующему ChatGPTComposer/PageStateSource только в необходимом объёме.
- Сборка и публикация нового release не входят в этот scope без отдельного поручения.
