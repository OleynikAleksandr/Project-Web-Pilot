# Исправления после рефакторинга Workflow Kit

Рабочая спецификация плана исправлений, найденных живой приёмкой выпусков после рефакторинга Workflow Kit (план `recovery-on-demand-research-20261006` закрыт 07.10.2026 по поручению пользователя). Новые находки приёмки добавляются сюда и в план через `plan:extend`.

## Результат
Web Pilot 0.6.100 и 0.6.101: каждый старт сессии отправляется автоматически, включая повторные старты в том же аккаунте ChatGPT; брошенные копии хранилища не накапливаются и не сохраняют данные удалённых проектов; долгая команда агента не теряется при уходе в фон. Выпуск по обычному порядку Kit: задачи → DOCS → сборка → установка → публикация (публикация поручена пользователем).

## 1. Уникальные имена частей контекста (регрессия 0.6.99)
- Факт: второй старт подряд в 0.6.99 не отправляется. ChatGPT переименовывает вложение с уже загружавшимся именем (`context-01-of-5.md` → `context-01-of-5(1).md`); Web Pilot распознаёт карточки по точному имени, не находит ни одной и, как задумано, не нажимает Send.
- Причина: неверное допущение T013 0.6.99, что уникальность имён не нужна (отдельная `/mnt/data` беседы не мешает ChatGPT сверять имена с прежними загрузками).
- Решение: имя `context-<8 hex>-NN-of-M.md`, где 8 hex — начало UUID из `requestId` отправки. Короткий фрагмент модель не искажает, как искажала 36-символьный UUID; новое имя на каждый старт исключает переименование. Распознавание по точному имени и строка о списке `/mnt/data` сохраняются.
- Тесты: два старта дают разные имена одного формата; имя содержит фрагмент своего requestId; карточка `…(1).md` не считается своей.

## 2. Брошенные временные файлы хранилища
- Факт: в папке данных приложения 58 файлов `workspaces.json.tmp-*` (160–420 КБ, с 15.09.2026). Это остатки прерванных атомарных записей; в них записи проектов, в том числе удалённых, — удаление проекта вычищает `workspaces.json`, копии `.v1–.v5-backup` и `diagnostics.jsonl`, но не их.
- Решение:
  - `WorkspaceSessions.save` удаляет свой временный файл при любой неудаче записи или переименования;
  - при загрузке хранилища (один экземпляр приложения) удаляются осиротевшие временные файлы: `workspaces.json.tmp-*`, `.tmp` копий `.vN-backup`, `diagnostics.jsonl(.1).tmp*`;
  - удаление проекта и локальное удаление сессий делают то же в очереди изменений хранилища, после завершения ожидающих записей — без гонки с собственной записью.
- Тесты: сбой записи не оставляет временного файла; загрузка убирает сирот и не трогает посторонние файлы; удаление проекта убирает сирот.

## 3. Долгие команды исполнителя (приёмка 0.6.100)
- Факт: на просьбу запустить `npm test` «в фоне с PID» агент выполнил `nohup … &`; процесс исчез сразу, журнал пуст. Проверено прямым вызовом исполнителя: `nohup sleep 40 &` исчезает через 2 с, обычный `sleep 40` возвращает session ID и продолжает работать; повтор этапа через `exec_command` и опрос сессии дал полный результат `npm test` после «Продолжай».
- Причина: Codex App Server завершает процессы команды, когда она возвращается. Агенту это нигде не сказано; PROTOTYPE говорит общее «с идентификатором процесса».
- Решение: правило в instructions сервера и в описании `exec_command` (`LONG_COMMAND_RULE`) и третьей строкой `EXECUTOR_TOOL_RULES` стартового сообщения: не уводить команду в фон через `&`/`nohup`; запускать обычным `exec_command`; при session ID опрашивать сессию `write_stdin` с пустым вводом (до 60 с за опрос), не запуская команду повторно. Поведение исполнителя не меняется.
- Тесты: тексты instructions и стартового сообщения закреплены.

## 4. Документ хранилища
- `workspace-sessions.md` описывает шаблоны временных копий уже, чем код: суффикс — `.tmp` или `.tmp-*` для `workspaces.json`, его `.vN-backup` и `diagnostics.jsonl(.1)`.

## Проверки
- Задачи: `unit-all`; задача 1 — дополнительно `electron-smoke`; задача 3 — `executor-channel` и `codex-tools-live`.
- Живая приёмка 0.6.100 пройдена 07.10.2026: два старта подряд отправляются автоматически, 6 частей (143 КБ) прочитаны полностью, временные копии удалены после перезапуска.
- Живая приёмка 0.6.101: после Refresh подключения в ChatGPT и новой сессии агент на просьбу о долгой команде запускает её обычным `exec_command` и после «Продолжай» опрашивает ту же сессию.
- Из приёмки 0.6.99 остаются: Доктор принимает проект на Kit 1.5.x; удаление тестового проекта не оставляет его записей в копиях хранилища.
