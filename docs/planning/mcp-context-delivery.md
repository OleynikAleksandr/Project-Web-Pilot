# Контекст проекта через MCP без вставки в ChatGPT — релиз 0.6.86

Поручение пользователя 04.10.2026: агент сам получает recovery через MCP частями; Web Pilot больше не вставляет пакет в поле ChatGPT. Сделать всё сразу и выпустить релиз.

## Что показала проверка (04.10.2026, ChatGPT в браузере, Chat и Work)

- ChatGPT передаёт модели `instructions` MCP-сервера; модель сама вызывает `workflow_context_recover` перед первым ответом и не повторяет вызов на следующих сообщениях.
- ChatGPT показывает модели результат инструмента примерно до 10 000 токенов. Пакет ~22 000 токенов приходил с вырезанной серединой; просьбу дочитать модель не выполняла и перепроверяла факты по файлам.
- С выдачей частями по ~30 КБ модель читала все части (один sha256), файлы и git не трогала. В Work первая часть один раз показалась обрезанной: результат дублировался текстом и структурой.

## Результат

1. `workflow_context_recover(workspace="", part=N)`: при `part ≥ 1` пакет выдаётся частями до 20 000 байт только текстом (без structured-дубля). В начале каждой части — «ЧАСТЬ N ИЗ M», sha256 пакета и следующий вызов; в конце — `[ПРОДОЛЖЕНИЕ] … part=N+1` или `[КОНЕЦ ПАКЕТА]`. Часть 1 начинается с правил сессии Web Pilot (`tools/codex-app-server-mcp/session-rules.md`, перенесены из стартового сообщения). `part=0` по-прежнему отдаёт весь пакет одним результатом.
2. Если `workspace` не указан, сервер берёт проект, открытый в Web Pilot (`active-workspace.json` в каталоге состояния executor); если его нет — ошибка с просьбой назвать путь.
3. `instructions` сервера: перед первым ответом в разговоре прочитать все части; повторять только по просьбе пользователя; не подменять непрочитанные части чтением файлов.
4. Web Pilot в режиме Codex App Server (macOS) не вставляет и не отправляет recovery: новая сессия открывает чат в выбранном режиме и ждёт первого сообщения пользователя; чат привязывается к проекту по этому сообщению; выбранный проект передаётся серверу. Сайдбар показывает «Можно начинать» и «Чат проекта». Codex Local Mac и Windows продолжают прежнюю доставку первым сообщением.
5. Релиз **0.6.86**: версия → DOCS → парная сборка → установка в `/Applications` → GitHub Release и синхронизация `main`.
