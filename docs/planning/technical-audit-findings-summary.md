Детальная [матрица и T002–T003](technical-audit-findings.md), [неиспользуемое T004](technical-audit-findings-unused.md), [ошибки T005](technical-audit-findings-lifecycle.md). ### A. Подтверждённые факты и дефекты

**A-01 — исключение обработчика PageState полностью подавляется.** `src/page-state.mjs:115–119`: `try { listener(event); } catch {}`. Доказательство — безусловная пустая ветка catch для синхронных исключений; для воспроизведения достаточно зарегистрировать listener, бросающий `Error`, и вызвать `accept()` с изменённым состоянием: никакой канал ошибки в `#notify` не вызывается. Последствие: тихая потеря сигнала одного подписчика при сохранении остальных. **Важность: medium; подтверждено поведение кода, но не реальный пользовательский инцидент.** Минимальная правка при отдельном разрешении: ограниченная диагностика callback exceptions без текста разговоров с сохранением изоляции других listeners. Проверка — отдельный unit fixture с падающим подписчиком и исправно работающим вторым. Риск: macOS/Windows — общий JS-код, диагностическая нагрузка; Sidebar — прямого изменения трёх публичных модулей нет.

**A-02 — ошибка записи unknown может быть подавлена.** `src/context-session.mjs:395–401`: запись статуса `unknown` через `updateSession(...).catch(() => {})` затем `emit('send-unknown')`. При инъекции отказа записи ошибку хранения не возвращают и сообщение интерфейса само по себе не подтверждает durable статус. **Важность: medium; статически подтверждённая потеря ошибки, пользовательская повторная отправка не доказана.** Минимальная правка: явно маркировать ошибку сохранения и сохранить запрет повтора до независимого подтверждения исхода. Верификация — fixture для отказа persist после начала Send и проверки рестарта без реальной отправки. Риск: изменение восстановления и AutoPlan, единый код обеих ОС; публичный формат composer/Sidebar не менять.

### B. Кандидаты на упрощение

**B-01 — два нормализатора заголовков, medium по сопровождаемости.** `src/workspace-session.mjs:135–153`, `src/chatgpt-title.mjs:3–16`: повторяются правила 80 Unicode символов / 200 UTF-8 байт, обрезка концов, разные способы подсчёта байт. Появление расхождений не установлено. Минимальная мера: маленькая общая чистая функция или сохранение отдельных реализаций с контрактным cross-test; не переносить тяжёлую зависимость `workspace-session` в адаптер. Проверка — одинаковые Unicode/emoji/границы и ошибки. Риск macOS/Windows: байтовая семантика, Sidebar: избегать изменения трёх экспортируемых адаптеров.

### C. Недостаточно доказательств, подтверждений удаления нет

- **C-01:** переходная миграция старых runtime (`src/main.mjs:73–74,814–827`, `src/mac-runtime-switch.mjs:509–547`, `src/windows-runtime.mjs:226`) достижима, пока должны поддерживаться обновления со старых версий. Нельзя объявлять мёртвым кодом и удалять без политики окончания миграции и тестов на обеих ОС.
- **C-02:** предположение о битом `./startup.mjs` в `tests/electron-smoke.mjs:242` **снято как кандидат на локально отсутствующий импорт**: путь — строка внутри `sidebar.executeJavaScript('import("./startup.mjs")...')`, разрешаемая относительно загруженной страницы UI, а не файла теста; `src/ui/startup.mjs` присутствует. При этом smoke не запускался, поэтому реальная загрузка не подтверждена.
- **C-03:** различия URL-предикатов, нормализации DOM и текста, platform helpers и повторения контрактов (T002) имеют разные контексты и потребителей; само сходство не доказывает вреда. Автоматическое объединение не предлагать.
- **C-04:** подавление ошибок необязательного фильтра (`src/main.mjs:247`) требует выяснения политики видимости; пользовательский сбой не воспроизведён.
- **C-05:** наличие отдельного Sidebar-контракта `pageOperation`, `pageScript`, `chatGPTDOMScript` подтверждено тестом `tests/chatgpt-composer.test.mjs:131–135` и `docs/modules/chatgpt-dom-compatibility.md:58–65`; внешняя версия Sidebar и её фактический vendor SHA в этой задаче не проверялись. Нельзя удалять экспорты по отсутствию внутренних ссылок.

## Рекомендации — отдельные решения, не задачи этого плана

1. **Приоритет medium:** единым небольшим пакетом фикстур подтвердить поведение A-02 при сбое durable записи после Send и восстановлении процесса; только затем выбрать точечную диагностику/защиту без автоматической повторной отправки.
2. **Приоритет medium:** проверить A-01 unit-тестом и при необходимости добавить безопасный error sink для падений подписчиков, не ломая других listener.
3. **Приоритет low–medium:** обсудить нормализацию заголовков B-01; объединять только маленький чистый алгоритм, не модули целиком.
4. **Без срочности:** отдельно решить срок поддержки миграции прежних runtime, до этого C-01 не удалять. Другие случаи C не исправлять без доказательств.

Intentional MCP/tunnel службы не считались утечкой. Не создавались новые зависимости, исходники не менялись и соседние репозитории не открывались для записи.
