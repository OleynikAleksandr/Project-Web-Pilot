# Ревью нового плана через Claude CLI

## Результат и согласованные решения

В карточке текущего плана Project Web Pilot рядом с «Автовыполнением» появляется независимая кнопка Review. При включённом Review основной агент готовит планировочный документ и машинный черновик to-do plan, получает внешнее ревью Claude CLI, отвечает на замечания и уточняет оба документа до согласования. Затем Workflow Kit публикует согласованные документы и создаёт ACTIVE scope. Пользователь не переносит ответы между агентами.

Первая версия работает только для нового плана из NONE; расширение ACTIVE остаётся прежним. У checkout один current plan, а временные черновики им не являются. Ревью не принадлежит чату; привязка к разговору нужна лишь для доставки продолжения. Реализацию выполняет основной агент. Claude — только рецензент.

Решения пользователя от 08.10.2026 заменяют исследовательские варианты:
- Практическая интеграция уже испытанного обмена, без отдельной предварительной исследовательской программы.
- Review и автовыполнение — две независимые кнопки в панели плана, не в Settings. Включённый Review заметно зелёный.
- Успешное Review завершается публикацией спецификации и плана. При включённом автовыполнении существующий AutoPlan начинает работу автоматически; при выключенном — пользователь просит начать вручную. Дополнительное поле разрешения исполнения не вводится.
- При существенном споре или ошибке Claude основной агент сообщает причину и спрашивает пользователя, что делать дальше. До ответа публикации нет; бесконечных повторов нет.
- При фактическом начале первой задачи принятого плана временная папка его ревью удаляется целиком. Опубликованные спецификация и план сохраняются. При споре материалы остаются для обсуждения.

Этот документ и текущий план готовятся по прямому поручению пользователя. Их создание само по себе не запускает реализацию или новые Claude-раунды. Уже выполненные эксперименты не считаются ревью будущего кода и не подлежат общей очистке по маске.

## Пользовательский сценарий

| Review | Автовыполнение | Поведение после подготовки документов |
| --- | --- | --- |
| OFF | OFF | Обычная публикация плана; выполнение по просьбе пользователя |
| ON | OFF | Согласование и публикация; выполнение по просьбе пользователя |
| OFF | ON | Обычная публикация; AutoPlan продолжает выполнение |
| ON | ON | Согласование и публикация; AutoPlan продолжает выполнение |

Review по умолчанию OFF. Выбор сохраняется при перезапуске аналогично автовыполнению. Настройкой владеет клиент, агент её не меняет. Для работы вне выбранного проекта используется последнее явно синхронизированное состояние этого checkout, а не настройка случайно выбранной в панели папки. Запись политики не меняет cwd уже работающего чата.

Кнопка доступна при NONE, в том числе после архивации scope; aria-pressed, название/подсказка и зелёный цвет показывают состояние без зависимости только от цвета. При ACTIVE переключатель задаёт режим следующего нового плана; текущее выполнение не перезапускается. Рядом выводится короткий статус: подготовка, раунд N из 4, согласовано, нужна помощь пользователя. Признаки CLI и внутренние идентификаторы не загромождают основной интерфейс.

Включение Review означает разрешение внешнего рецензента Claude и передачи ему документов этой задачи. Это объясняется в подсказке кнопки; отдельное подтверждение на каждый раунд не требуется. Авторизация Claude выполняется пользователем обычным способом. Недоступный CLI, неподдерживаемая модель или истёкшая авторизация дают понятную ошибку без установки, логина или смены модели за пользователя.

OFF до запуска оставляет обычный путь. OFF во время цикла прекращает будущие автоматические раунды и продолжения; текущий известный процесс учитывается до определённого результата, без повторного запуска. Переключение не публикует черновик само по себе и не снимает уже показанный спор: основной агент обсуждает дальнейший шаг с пользователем. ON при существующем черновике разрешает запуск после проверки его актуальности. Дубликаты событий не создают новый цикл.

## Первая архитектура

Использовать проверенный путь: ChatGPT Web → существующие MCP exec_command/write_stdin → команда установленного Workflow Kit → Claude CLI. Основной агент запускает и ожидает CLI в текущем ходе. Web Pilot хранит настройку, наблюдает состояние и при необходимости продолжает разговор через существующий Composer. Отдельная фоновая служба и модельный API не добавляются; MCP остаётся из девяти инструментов и сам модельных ходов Codex не делает.

В packages/workflow-kit реализовать небольшой opt-in протокол подготовки, запуска, чтения результата и публикации ревью. Рабочие имена команд: review:prepare, review:run, review:status, review:publish. Их точные схемы и help реализовать вместе, без ручного редактирования plan-файла. Claude-адаптер исполняется только явной командой основного агента при разрешённом Review. При выключенном Review другие потребители Kit не получают обязательной зависимости от Claude или Web Pilot.

Не помещать исполняемый runtime в scripts приложения: scripts отсутствует в asar. Источник Kit — packages/workflow-kit; установленный runtime обновляет install --update, ресурсы генерирует штатный stage. Изменение публичного контракта Kit получает версию и проверки установки/совместимости.

Инструкцию основному агенту доставлять через recovery Kit: актуальная политика, текущий цикл и краткий порядок команд. Для уже открытого чата проверка перед созданием нового scope возвращает понятный результат REVIEW_REQUIRED с следующим действием; не требуется повторно доставлять весь recovery при щелчке по кнопке. Изменение startupMessage и проектного AGENTS ограничить узким разрешением Claude-review при включённой кнопке. Не снимать общий запрет произвольных модельных агентов. Проверить согласованность recovery, startup text, AGENTS, MCP instructions/tool descriptions и backend ошибок. Глобальные инструкции пользователя не изменять.

## Документы и запуск раундов

Рабочая область одного цикла: .harness/runtime/plan-review/<run-id> внутри явного checkout. В ней версии спецификации, машинного плана, ответы автора, запросы, сырые ответы CLI, stderr и состояние цикла. Все они вне Git. Итоговые пути спецификаций в docs/planning определены заранее; в плане указаны именно эти пути. До согласования временные файлы не попадают в ACTIVE plan или в коммиты.

review:prepare проверяет NONE, форму плана, назначенные существующие verification_ids, размеры Markdown, ссылки и соответствие спецификации задаче; сохраняет базовый HEAD/revision и SHA-256 всех входов. Содержательные решения проверяет агент/рецензент, валидатор — структуру и идентичность. Проверяемая нормализация Kit должна быть общей для предварительной проверки и публикации: рецензент видит фактические задачи, зависимости и DOCS, которые будут опубликованы. Не изобретать второй нормализатор.

Готовность публикуется атомарной записью manifest после сохранения всех входов. Один checkout — один незавершённый цикл. Минимальное состояние: schema, run-id, base HEAD/revision, номера раунда и поколения, список входов с SHA и конечными путями, Claude session ID, стадия, ссылки на результат и ошибка. Идентификатор разговора для продолжения хранится отдельно от идентичности плана. Никаких токенов, cookies, ключей или адресов коннектора.

Начальные параметры: claude-opus-5-5, effort high, не более четырёх раундов; один запуск не более 900 секунд. Первый раунд использует новый UUID, следующие — --resume с точно возвращённым ID. Не использовать --continue, fork или новую сессию как тихий fallback. Модель подтверждать по ответу CLI, effort — по argv; независимый замер внутренних размышлений не обещать.

Аргументы запуска — массив, prompt через stdin, output-format json. Начальная проверенная конфигурация: Read/Glob/Grep, dontAsk, permission-prompts none, strict-mcp-config, setting-sources пусто, disableAllHooks, disable-slash-commands, no-chrome, max-turns 30. Перед применением сверить поддержку с установленным CLI; не ослаблять ограничения молча. Доступ к репозиторию только на чтение по задаче, Claude не редактирует документы и не публикует план. Основной агент пишет полученный результат в свою рабочую область.

Полный stdout/stderr сохраняется в файлы; ограниченный вывод MCP служит статусом. Долгая команда остаётся в exec session, ожидание через write_stdin, без shell background и nohup. До повторного действия сначала проверять существующий запуск. При таймауте завершать только подтверждённый собственный дочерний процесс и фиксировать ошибку, не искать/убивать чужие PID.

Успешный процесс: exit 0, is_error false, непустой результат, совпадение session/model, целые входы. Ошибка разбора или несоответствие — ошибка ревью, не согласие. Сырой ответ хранится рядом с машинным результатом; ссылки рецензента на постороннюю память не принимаются как требования пользователя. Известно, что в опыте Claude сообщил о чтении памяти: параметры не являются песочницей. Не обещать изоляцию, не менять глобальные Claude-настройки и не создавать отдельную систему ключей/подписей. Убирать очевидно нерелевантные инструкции из запроса и сообщать о обнаруженном влиянии на выводы.

## Согласование и помощь пользователя

Рецензент проверяет оба документа вместе: соответствие задаче, пропуски, зависимости, проверки, исполнимость и несогласованность спецификации с планом. Ответ содержит связанный с входными SHA вердикт и замечания с id, важностью, состоянием и объяснением. Проверять форму ответа; не превращать ошибку формата в APPROVED.

После каждого ревью основной агент читает весь ответ, пишет позицию: согласен / не согласен / требуется решение пользователя, с обоснованием и исправлениями. Следующий раунд получает новые версии обоих документов и позицию автора; Claude продолжает ту же сессию. Автор не объявляет существенные замечания снятыми от имени рецензента.

Согласование достигнуто, когда рецензент подтвердил последнюю пару и не осталось существенных открытых замечаний либо противоречий, которые сам автор считает нерешёнными. Признанные второстепенные ограничения можно включить в спецификацию. Не маскировать существенный спор статусом «принятое ограничение». Если согласие достигнуто раньше четвёртого раунда, лишние раунды не запускать.

При существенном споре после четырёх раундов или любой ошибке Claude цикл переходит в NEEDS_USER. Основной агент кратко описывает проблему, позиции и варианты и спрашивает, как действовать дальше. Материалы остаются. Нет автоматической публикации, бесконечного retry или автоматического выбора победителя. Дополнительный раунд, повтор после исправления авторизации или публикация без ревью допустимы по явному решению пользователя; решение сохраняется в состоянии до публикации. Обход этого ограничения текстом самого агента не является решением пользователя.
