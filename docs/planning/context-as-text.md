# Контекст текстом, MCP только инструменты — релиз 0.6.96

Решение пользователя 06.10.2026 по итогам разбора «что было — что стало» после релизов 0.6.86–0.6.95.

## Почему

Доставка контекста через MCP (0.6.86–0.6.88) не дала того, ради чего вводилась. Без DOM работать всё равно нельзя: в MCP инструменты вызывает только модель, сервер не может начать сессию или запустить задачу, и проверка 0.6.87 показала, что одни `instructions` вызова не гарантируют, — поэтому в 0.6.88 стартовое сообщение вернулось на DOM. Взамен одной гарантированной вставки появился протокол чтения по частям с ключами и запретами под потолок одного ответа инструмента (около 10 000 токенов у ChatGPT).

Довод «через MCP контекст доступен внешним клиентам» снят: контекст — это текст в папке проекта, и агент с доступом к папке читает его обычными инструментами по одной строке с путём.

Сбои OpenAI начала октября (лимиты, «дополнительная проверка») причиной отказа от вставки не считаются: в те же дни одновременно менялись форма доставки, длина хода (одна микрозадача на ход) и канал (VPS). Причина не установлена.

## Что показал осмотр кода (main `c188d71`, 0.6.95)

- Доставка полного пакета первым сообщением никуда не делась: `startupMessage` в `src/context-session.mjs` и вставка через `ChatGPTComposer.deliver` работают для Windows. macOS переведён на MCP одной строкой — `CodexAppServerRuntime.contextDelivery` возвращает `'mcp'`.
- Пакет на macOS Web Pilot уже получает напрямую от Workflow Kit: `SessionPlans.loadContext` запускает `scripts/workflow.mjs recover --format packet`. Инструмент сервера `workflow_context_recover` клиенту macOS для этого не нужен; он нужен только модели и входит в обязательный список `LocalMcpClient` (`requiredTools`).
- Правила сессии существуют в двух местах: в `startupMessage` (для первого сообщения) и в `tools/codex-app-server-mcp/session-rules.md` (для MCP). Во втором есть две строки, которых нет в первом: про работу с инструментами и про один повтор после блокировки OpenAI.
- Текущий пакет recovery этого проекта — 87 085 байт (59 299 символов): через MCP это четыре последовательных вызова, через поле ввода — одна вставка. Сайт может показать большую вставку как вложение; `ChatGPTComposer` считает отправку состоявшейся в обоих случаях.
- AutoPlan отправляет голое «Продолжай» (`CONTINUE_TEXT` в `src/auto-plan.mjs`), хотя прямо перед отправкой читает актуальный план.
- Блок Workflow Kit в `AGENTS.md` уже говорит агенту: если recovery не доставлен — `./scripts/workflow recover --format text`. Новая версия Kit для внешних клиентов не нужна; не хватает только готовой строки для первого сообщения.
- В меню проекта уже есть «Скопировать полный путь» (`copyWorkspacePath`).

## Результат

1. **Старт сессии.** На macOS Web Pilot отправляет одно стартовое сообщение с правилами сессии и полным пакетом recovery, как на Windows. Правила для macOS дополнены двумя строками из `session-rules.md`.
2. **Старт задачи.** Сообщение автопродолжения несёт текст следующей задачи из плана: id, название, зачем, критерии приёмки, файлы, проверки.
3. **Внешние клиенты.** В меню проекта есть «Скопировать строку для внешнего клиента»: имя проекта, папка, указание прочитать `AGENTS.md` и получить recovery в файл командой Workflow Kit, затем прочитать его целиком.
4. **MCP.** `workflow_context_recover`, протокол частей, `session-rules.md`, `active-workspace.json` и инструкция про чтение контекста удалены. Каталог macOS — девять инструментов: `exec_command`, `write_stdin`, `apply_patch`, `view_image`, `bridge_status`, `turn_watchdog`, `computer_list_windows`, `computer_capture_screen`, `computer_capture_window`. Server instructions — короткие правила работы с инструментами.

## Отступление от согласованной формулировки

Пункт «документы задачи вкладываются в сообщение, которым она запускается» сужен до текста самой задачи. Обязательные документы плана (контракт и карты) уже входят в стартовый пакет; собственный список файлов задачи — это то, что она будет править, и он слишком велик для вставки (`docs/VERIFICATION.md` — 548 КБ). Документы задачи агент читает инструментами по мере надобности.

Пункт «recovery готовым файлом в проекте» выполнен без изменения Workflow Kit: файл создаёт сам агент командой из скопированной строки (`recover --format text > .harness/runtime/recovery.txt`), потому что вывод команды целиком не помещается в один ответ инструмента.

## Границы

- Одна микрозадача на ход остаётся.
- Чтение по запросу агента остаётся за инструментами; содержимое файлов от лица пользователя посреди хода не подставляется.
- Запасной вариант доставки — вложение текстовым файлом; в этот релиз не входит и включается, только если полноразмерная вставка даст проблемы.
- Экспорты `src/chatgpt-dom.mjs`, `src/chatgpt-composer.mjs`, `src/chatgpt-experience.mjs` и формат `pageScript` не меняются (контракт Web Pilot Sidebar).
- Windows-runtime, его каталог и его доставка первым сообщением не меняются; код и версия Workflow Kit 1.5.5 не меняются.
- Остальные девять инструментов macOS, `codex-tools.lock.json` и канал VPS не меняются.
- В уже привязанные чаты ничего автоматически не отправляется.

## Запуск

Установить 0.6.96, полностью выйти из Web Pilot (⌘Q) и открыть снова, в ChatGPT в настройках коннектора нажать «Обновить инструменты».

## Риски

- Большая вставка в начале каждой сессии по времени совпадала с жалобами OpenAI на лимиты. Связь не доказана; если жалобы вернутся, включается запасной вариант с вложением.
- Чаты, начатые в режиме MCP, сохранили отметку доставки другого вида. Они остаются привязанными; контекст в них передаётся только явным обновлением.
- AutoPlan — чувствительный механизм (три контракта и разбор инцидента 03.10.2026). Меняется только текст сообщения, логика пауз и контрольных точек не трогается.
