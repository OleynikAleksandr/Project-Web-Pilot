### B-DUP-01 — два самостоятельных алгоритма ограничения заголовков (medium, кандидат)

- **Факты:** `src/workspace-session.mjs:135–153` (`sessionName`) обрезает нормализованную строку по 80 Unicode code points и 200 UTF-8 байтам через `Buffer.byteLength`, затем удаляет конечную пунктуацию. `src/chatgpt-title.mjs:3–16` (`normalizeTitle`) повторяет ту же последовательность и границы, но размер символа вычисляет через `new TextEncoder().encode(character).length`. Оба алгоритма выполняются в Node/Electron-контексте; `chatgpt-title` отдельно отвечает за заголовки ChatGPT, `workspace-session` — за локальную сессию.
- **Риск:** при будущей правке пределов/обрезки можно синхронно не обновить оба алгоритма; названия локальной сессии и облачного чата начнут различаться. На просмотренных строках доказано **дублирование правила**, но не фактический пользовательский сбой.
- **Минимальная мера:** после проверки всех потребителей выбрать один независимый от Electron shared helper для нормализации Unicode/UTF-8 и оставить отдельные обёртки с собственными типами ошибок и политикой источника; альтернативно явно задокументировать два контракта, если их границы должны различаться. Проверка: тесты двух входных сценариев с Unicode, emoji, ведущими/конечными пробелами, превышением обоих лимитов и ошибочным вводом, без реального ChatGPT.
- **Цена:** один общий алгоритм устраняет необходимость синхронной правки двух мест, но создаёт зависимость названия ChatGPT от внутреннего shared helper. Не импортировать весь `workspace-session` в адаптер; если зависимость нежелательна, сохранить отдельные реализации с тестом одинакового контракта. macOS/Windows: проверить Node TextEncoder/Buffer паритет. Sidebar: `chatgpt-title` не входит в три объявленных публичных DOM-модуля, но при переносе учитывать импортный граф.

### C-DUP-02 — повтор URL-валидации с неодинаковыми назначениями (low, не объединять автоматически)

`src/workspace-session.mjs:17–25` (`normalizeChatUrl`) валидирует **сохраняемый URL беседы** и обязательный ID; `src/chatgpt-experience.mjs:5–14` (`parsedChatGPTUrl`) валидирует host/credentials для **страницы**, в том числе `/` и `/work/`, а `chatGPTExperienceForUrl` определяет режим. `src/chatgpt-title.mjs:19–24` извлекает ID из уже нормализованного URL, а `renameChatGPTConversationPage` повторно проверяет ID в renderer (строки 28–38). Прямое объединение всех предикатов ошибочно: entrypoint без conversation ID допустим для определения режима, но недопустим как сохранённая беседа; renderer должен независимо проверять привязку перед запросом. Возможен компактный общий предикат безопасности происхождения URL, **только** если сохраняется независимая проверка контекста и не возникает перенос Node API в Sidebar-модули. Доказанного вредного расхождения нет; тесты проверить в T003/T005.

### C-DUP-03 — нормализация пробелов по разным семантикам (low, осознанное повторение)

`src/chatgpt-page-observer.mjs:12` сжимает пробелы в DOM-снимке, `src/chatgpt-tool-filter.mjs:18` дополнительно приводит к нижнему регистру для сравнения служебного текста; `src/chatgpt-composer.mjs:17` отдельно нормализует переводы строк и NBSP, сохраняя модель ввода. Один regex не означает общего бизнес-контракта: объединение увеличит связанность renderer/DOM и может изменить распознавание пользовательского текста. Не рекомендовано.

### C-DUP-04 — платформенная конфигурация разделена по владельцам (low, оставить)

`src/platform.mjs:1–34` выбирает пути bundled/runtime Node и каталог Codex App Server для macOS/Windows; `packages/workflow-kit/src/lib/platform.mjs:1–29` выбирает Git/Node внутри `.harness/runtime` и переменные среды Kit. Назначение папок и исполняемых файлов отличается; Kit — самостоятельный пакет. Объединять эти platform helpers нельзя без ненужной зависимости Kit от приложения. Отдельно `tools/codex-app-server-mcp/control.py` намеренно знает путь состояния для входа пользователя независимо от окна (комментарий `src/platform.mjs:8–10`); контракт пересечения стоит проверить в T003, но дублирование между JS и Python обусловлено независимым стартом службы.

### C-DUP-05 — документационные ограничения повторяются как контракт (low, оставить)

`docs/modules/workflow-kit-recovery.md:7,22–25` и `docs/modules/context-delivery.md:21–25` повторяют потолки 180000 байт/7 частей и ссылку на `budget.document_bytes`; это два уровня контракта: Kit производит пакет, Web Pilot проверяет полученный. Документы сами уточняют, что Web Pilot дублирует лишь ограничение 180000, а число частей обеспечивает Kit. Не удалять сведения на стороне потребителя. При смене протокола требуется парная проверка документов и тестов, не общий код через границу пакета. `README`, архитектура и документация Review повторяют необходимые пользовательские/внутренние правила по разным аудиториям; точного противоречия в проверенных фрагментах не подтверждено.

### C-DUP-06 — похожие атомарные JSON-записи (low, не считать подтверждённым дефектом)

`src/main.mjs:259–260` пишет settings во временный файл и переименовывает; `src/workspace-session.mjs:266–269` реализует `writeJsonAtomic` для файлов сессий; `packages/workflow-kit/src/lib/common.mjs:22–33` содержит собственную `atomic` запись. Они похожи по паттерну, но имеют разные владельцы, требования к режимам файлов и транзакциям. Вынос из Kit в приложение не рекомендуется. Для `src` можно исследовать небольшую унификацию только после проверки условий отказа, одновременных записей и восстановления в T005; пока подтверждённого дефекта нет.
