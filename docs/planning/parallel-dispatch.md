# Выдача заданий и очередь main — рабочий контракт T006

Дополнение к [спецификации](parallel-execution-spec.md); при DOCS переносится в контракты модулей.

`execution_origin_session_id` — происхождение неизменного снимка настроек. Основной агент получает поле в стартовом сообщении и сохраняет в новом плане (в scope при Review). Это не владелец плана и не получатель Review. Перед выдачей `ParallelExecution` ищет именно эту сохранённую сессию, сверяет ON и точный max_workers; чужая выбранная сессия, Settings и неизвестный снимок не заменяют источник. Sequential сохраняет прежний основной чат без worktree. Обычный AutoPlan не отправляет продолжения основному parallel-плану.

Узкие IPC `pilot:execute-tasks` и `pilot:correct-integration` используют штатный registerAction/assertLocalSender и принимают только workspace выбранного проекта. Кнопки/проекция — T007. Ручной запуск выдаёт доступную группу; последующие группы требуют AutoPlan ON. OFF не прерывает уже начатую команду или безопасное завершение интеграции. Повтор не создаёт новый ID задания. Подготовка пользуется Kit assignment:create/setup, npm ci выполняется в worktree. Ошибка подготовки/неизвестный исход сохраняют назначение и видимую причину, не порождают замену.

Каждая задача получает собственный worktree и одну сохранённую сессию с метаданными родителя, задачи и назначения. Она наследует experience и снимок разрешения; создание не меняет выбранный чат. Стартовый контекст исполнителя поручает прочесть recovery и выполнить только эту задачу через task:start/commit. Отдельные AutoPlan/ledger/PlanMonitor работают и на скрытой странице, сохраняют неизвестный Send и останавливают продолжения после локального DONE. Settings не управляет этими контроллерами.

Очередь main сериализована на checkout. Зависимости требуют parent DONE; новые задания берут текущий подтверждённый HEAD после интеграций. Области сравниваются с незавершёнными назначениями, исключительная задача является барьером и ждёт их интеграции. Готовые результаты идут по времени готовности, при равенстве — по порядку плана; ранняя незавершённая независимая задача не задерживает готовую.

Для слияния нужны точный проверенный source, чистый worktree, завершённая транзакция, наблюдаемая пауза assistant в своём чате, отсутствие Composer/доставки/команды и свободный main. MCP оставляет только отметку активности в `.harness/runtime/command-activity` (PID исполнителя и время, без команды/вывода/секретов). Она удаляется после подтверждённого завершения exec/write_stdin/apply_patch. Неизвестное завершение оставляет отметку и блокирует интеграцию. Подписки на каталоги событийные; функционального polling нет. Восстановление неизвестных отметок/перезапуска — T008.

Конфликт и провал проверки сохраняют эксклюзивную интеграцию. Явное действие доставляет основной сессии одно поручение исправления с operation ID и командой integration:continue; до Send пишется ledger. UNKNOWN не повторяется. Доказательства main/source, Git-блокировки и проверки остаются у Kit. Состояние приложения хранит лишь очередь/доставку, не заменяет план.

Unit-проверки: происхождение, OFF/лимиты, повторные события, исключительный барьер/пересечения, готовые зависимости и актуальная база, завершение команд, UNKNOWN merge/Send, адресация и сохранение сессий. Kit fixture проверяет происхождение в схеме/сериализации; полные kit-check/unit-all/Electron smoke обязательны. Сквозная приёмка новой очереди — T010, живой ChatGPT и native Windows проверяет пользователь.
