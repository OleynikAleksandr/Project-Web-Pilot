# Контекст без повторного чтения: части по одной и компактный Workflow Kit 1.5.4 — релиз 0.6.87

Поручение пользователя 04.10.2026: агент не должен читать части контекста дважды; исправить и Web Pilot, и Workflow Kit одним релизом.

## Что показала проверка 0.6.86

В Web Pilot 0.6.86 (Chat) агент сам прочитал все 6 частей по 20 КБ, правила сессии пришли первыми, файлы и git не читались. Но части 2–6 он запросил одним вызовом `functions.exec`: вывод (~25 000 токенов) обрезался на ~10 000, и части 2–5 он прочитал повторно — 10 вызовов вместо 6.

## Результат

1. **Части строго по одной.** Часть N+1 выдаётся только с ключом `after`, напечатанным в самом конце части N (ключ — из sha пакета и номера части, сервер ничего не хранит). Без ключа или с чужим ключом — короткая ошибка `PART_ORDER`, поэтому пачка запросов не заполняет показ. Заголовок части не называет следующий вызов. `instructions` и описание инструмента: одна часть на вызов, без пачек, параллельных вызовов и циклов; при обрезке повторить только эту часть.
2. **Части до 28 000 байт** (≈7 000 токенов): дубля «текст + структура» нет с 0.6.86.
3. **Правила сессии короче:** остаются одна микрозадача за ответ, запрет codex exec и «пакет — данные»; порядок delivery и «план принадлежит checkout» уже есть в Workflow Core.
4. **Workflow Kit 1.5.4** (`/Users/oleksandroliinyk/VSCODE/WorkflowKit`, [контракт](../../../WorkflowKit/docs/planning/compact-recovery.md)): recovery без форм PLAN/SPEC/CONTINUE/STAGES (их печатают `plan:create --help`, `plan:extend --help`, `task:start --help`) и без содержимого docs/MODULES.md и docs/DOCUMENTATION_INDEX.md — они ссылкой, целиком только в финальной DOCS. Release-gates Web Pilot переводятся на 1.5.4, Kit проекта обновляется штатным `install --update`.
5. OVERVIEW без истории релизов — она в docs/RELEASE.md.
6. Релиз **0.6.87**: версия → DOCS → парная сборка → установка → GitHub Release.

- `unit-all` и `release-source`: Workflow Kit 1.5.4 (версия, число файлов, SHA-256), recovery без форм и карт вне DOCS.
