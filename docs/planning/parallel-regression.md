# Сквозная регрессия параллельного исполнения

`packages/workflow-kit/scripts/check-parallel-execution-fixture.mjs` входит в npm run check пакета. Fixture создаёт настоящий временный Git-проект с локальной npm-зависимостью, проверкой её импорта и тремя задачами. В каждом новом worktree до npm ci проверка импорта падает и task:start возвращает NEEDS_SETUP. После штатной подготовки два независимых source-коммита не меняют main; конфликт исправляется явно; третья задача получает обе проверенные зависимости. Повтор интеграции не создаёт лишний merge. Отдельно проверяется сохранность исторических доказательств после закрепления и удаления рабочего документа.

`tests/parallel-execution-smoke-fixture.cjs` вызывается общим Electron smoke. Через реальные защищённые IPC проверяются Settings и неизменный снимок новой сессии, создание исполнителей, переключение живых страниц, состояние и время в обеих темах, отправка единственного поручения исправления именно основному чату, интеграции и зависимая задача. Git/Kit работают с временными настоящими worktree; ответы агентов имитируются только на TEST FIXTURE, без модельных запросов. Результат пишется в parallel-execution-result.json тестового каталога.

Обнаруженная сквозным тестом ошибка: очередь WorkspaceReadiness сохраняла только последний выбранный проект и могла отменять проверку скрытого исполнителя. Фоновые запросы контекста теперь удерживаются по workspace и выполняются последовательно; UI-навигация продолжает оставлять только последний ожидающий выбор. Изменение Git во время полной проверки получает один ограниченный повтор. Отдельные unit-тесты проверяют удержание фоновых запросов, дедупликацию, ограничение повтора, черновик и запрет повторного Send при UNKNOWN.

Ошибка подготовки видна у своего исполнителя. Явная повторная сверка может продолжить только ещё не отправленную подготовку и не сбрасывает сохранённый черновик или неизвестную отправку. Окончание подготовки основной страницы будит очередь интеграции отдельным событием доступности. Наблюдатели страниц используют один IPC listener с адресацией по WebContents и прежними проверками mainFrame/document identity; закрытие последней страницы снимает listener.

Это автоматическая регрессия. Живые Chat/Work, чистая ОС и native Windows остаются пользовательской приёмкой после установки выпуска.

Дополнительные случаи: ручной запрос одной группы сохраняется, пока основной чат завершает подготовку, и не превращается в разрешение следующих групп при AutoPlan OFF. Последовательный legacy-проект не вызывает новых команд назначений своего старого Kit. Staged-кандидат интеграции не показывает DONE до подтверждения SHA коммита через validate.

Исправление конфликта ждёт окончания текущей сверки. Кнопка учитывает готовность основного чата; после допуска проверка продолжения допускает собственные inFlight и вставку Composer, сохраняя защиту от чужого черновика перед началом, генерации, смены чата и активной команды. События во время исправления объединяются в одну сверку после отправки. Это устраняет самоотмену отправки и гонку между публикацией конфликта и завершением очереди.
