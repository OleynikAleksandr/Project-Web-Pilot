## A. Агенту не передаётся правило безопасной остановки (обязательно)
- В 0.6.97 из `startupMessage` удалено правило: незавершённую работу сохранить на безопасной точке, закончить ответ без DONE, следующее «Продолжай» продолжает её. В Workflow Core его нет. AutoPlan на это правило рассчитан ([auto-plan](../modules/auto-plan.md) § Открыто).
- Вернуть в Workflow Core (`packages/workflow-kit/src/WORKFLOW.md`, п. 4) — один канонический источник. В PROTOTYPE закрепить: уже запущенную долгую команду не перезапускать; при продолжении сначала прочитать её результат по process ID.
- Не дублировать в обёртке Web Pilot. Тест recovery: правило присутствует в ядре пакета дословно один раз.

## B. Стартовое сообщение и вложения
- Короткие имена частей: `context-NN-of-M.md` вместо `<requestId>-NN-of-M.md`. Причина: модель переписывает длинный UUID в путь `/mnt/data/…` с опечаткой (`FileNotFoundError` на живом старте). Новая беседа имеет свою `/mnt/data`, уникальность не нужна; requestId остаётся в тексте сообщения и в обнаружении отправки. Сохранить распознавание карточек по точному имени.
- В транспортный текст одна строка: «Если файл не найден — выведи список /mnt/data и открой по фактическому имени; не подтверждай восстановление, пока не прочитаны все части». Существующую строку о чтении каждого вложения отдельно сохранить дословно.
- Контракт Sidebar: имена файлов не входят в публичный API трёх модулей; если изменение затрагивает `pageOperation`, отметить в описании коммита.
- Тесты: имена частей; повтор после reload без второй вставки; текст стартового сообщения.

## C. Workflow Kit
1. Recovery: `AGENTS.md` в строке «Включено» только при непустой проектной части (`recovery.mjs`, список `included` берёт `instructions.file` без проверки `instructions.text`). Живой старт показал противоречие «включено, но содержимого нет». Тест: новый проект с одной Kit-секцией.
2. `install --update`: проверки автора Git (`GIT_IDENTITY`), незавершённой Git-операции и посторонних staged-файлов (`FOREIGN_STAGED`) выполнять до записи runtime, manifest и плана. Повтор после отказа не должен уходить в ветку reconnect без коммита. Обновление из приложения получает автора Git так же, как новая установка. Тест: отказ до записи, дерево и manifest не изменены.
3. `check-runtime-fixture`: проверки `doesNotMatch` ищут прежний заголовок `--- ДАННЫЕ:` и проходят всегда — привести к фактическому формату; убрать устаревший комментарий о картах для финальной DOCS.
- Версия пакета Kit повышается только при изменении пакета; установка в этот checkout — штатный `install --update` в задаче раунда.

## D. Web Pilot
1. Доктор проекта (`resources/project-doctor/core.mjs`): поддерживаемые версии — из `upgradeFrom` установщика плюс 1.0.0 и текущая, как в Workspace Setup. Сейчас 1.0.0, 1.4.13 и 1.5.x получают `DOCTOR_VERSION`. Тест на каждую границу списка.
2. Удаление проекта (`src/workspace-deletion.mjs`, `purgeCopies`): чистить записи удалённого проекта во всех копиях `.v1–.v5-backup`, как это делает удаление сессии. Тест проверяет каждую копию.
3. Выпуск:
   - `scripts/check-installed-release.mjs`: identity корневого app — volume UUID + inode, без строгого сравнения device (ложный отказ после перезагрузки);
   - preflight-файл `.harness/runtime/release-<v>-preflight.json` записывает скрипт, а не человек;
   - `release-all` отказывает при незакоммиченных изменениях (sourceCommit = HEAD, а упаковывается рабочее дерево).
4. Мастер первого запуска: при отозванном ключе или удалённом туннеле пользователь может заново ввести ID и ключ (сейчас `activate` падает до `activated=true`, а `configure_tunnel` отклоняет запись при запущенном tunnel-client). Остановить tunnel-client под блокировкой, записать новые данные, запустить.
5. Мелкие:
   - `clipboard.writeText` ожидается в `pilot:copy-vps-connector-url` и «Скопировать диагностику»;
   - `WorkspaceSessions.mutate` не пишет `workspaces.json`, если данные не изменились;
   - ledger `autoPlanCheckpoint.entries` ограничен (например, последние 200 записей, без потери идентичности текущей паузы);
   - статус задачи в карточке плана доступен экранному диктору текстом;
   - «Все N задач выполнены» — с правильными формами числа (сейчас «Все 1 задача выполнены»);
   - диагностика `context-truncation-state` слушает фактический путь `/backend-api/conversation/<id>`;
   - `diagnostics.jsonl` получает ротацию по размеру, как журнал Chromium.
