# Продукт

## Идея

Project Web Pilot — самостоятельное локальное приложение, объединяющее подготовку проектов Project Workflow Kit и доступ веб-агента к компьютеру через Codex Local Mac. Пользователь работает в одном окне: слева собственный сайдбар, справа настоящий ChatGPT Web внутри встроенного Chromium.

Пользователь прямо выбрал встроенный Chromium. Использование внешнего Chrome, его текущего профиля или отдельно открытого Safari не соответствует этому решению. Вход в ChatGPT выполняется пользователем в профиле нового приложения и сохраняется между запусками.

Модель работает через имеющийся веб-аккаунт ChatGPT. Приложение не вызывает модельные OpenAI API и не запускает отдельного кодирующего агента. Доступ к локальным файлам и командам обеспечивает MCP. Транспортный ключ Secure MCP Tunnel не является ключом для генерации ответов и не должен попадать в чат, документы или Git.

## Согласованный пользовательский сценарий

1. Пользователь создаёт новый workspace или открывает существующую папку слева. Приложение показывает результат проверки и необходимые изменения до открытия чата.
2. Приложение определяет workspace и выбранную в его дереве сессию, подготавливает MCP и подключение.
3. Справа открывается ChatGPT; приложение получает полный пакет контекста и после готовности поля отправляет его первым сообщением.
4. Агент читает уже переданный пакет, коротко подтверждает восстановление и описывает назначение и текущее состояние проекта без дополнительных вызовов инструментов.
5. Сайдбар показывает передачу контекста и версию плана. Пользователь продолжает обычный диалог.

Подробный порядок, параметры и обработка ошибок находятся только в [CONTEXT_DELIVERY.md](CONTEXT_DELIVERY.md). Остальные документы ссылаются на этот контракт.

## Сессии workspace

Под каждым workspace хранится список созданных в Web Pilot сессий. Двойной клик по workspace или стрелка раскрывает и сворачивает дерево; выбор сессии открывает её собственный чат. Новый чат добавляется к списку. Название берётся из заголовка ChatGPT, номер и дата помогают различать похожие названия. Список, выбранная сессия и раскрытие сохраняются после перезапуска. Прежние сохранённые связи переносятся автоматически; утраченные старой версией связи не импортируются из всей веб-истории.

## Полная цель продукта

Сайдбар версии 0.5 включает создание нового workspace, проверку и подключение существующего, недавние проекты, дерево чатов, состояние плана и локальных служб. При создании папки устанавливаются инструкции, структура документации, план и необходимые скрипты Workflow Kit. При подключении существующей папки сохраняются её файлы, план, история и hooks.

Смысл объединения — один рабочий интерфейс и согласованный жизненный цикл. Источники плана, Git-состояния и recovery остаются в ядре Workflow Kit. Агент выполняет поручения пользователя через локальный MCP. Сайдбар отображает факты ядра и доставки, не исправляет статусы Markdown самостоятельно.

## Первый проверочный scope

На 11.09.2026 macOS-прототип реализован и собран на компьютере пользователя. Он использует выбранные существующие workspace с Workflow Kit, существующее подключение Codex Local Mac и встроенный ChatGPT. Реальная цепочка проверена на WF001; история задач находится в единственном активном плане.

В версии 0.2 выбран полный пакет в первом сообщении и короткое подтверждение с описанием проекта. Проверка хука и машинный ACK удалены из пользовательского сценария. Граничные ошибки дополнительно проверены в fixtures; доказательства и ограничения — VERIFICATION. Пользовательская приёмка ожидается; массовый перенос двух исходных приложений не выполнялся.

Для первого опыта допустим явно настроенный путь к существующему Codex Local Mac. Это временная зависимость прототипа, а не самостоятельная поставка конечного продукта. В дальнейшем перенос нужных модулей выполняется в новый репозиторий с фиксацией происхождения.

## Следующее расширение

Ядро подготовки Workflow Kit, создание и подключение уже включены в версию 0.4 по поручению пользователя. Следующие возможные задачи — развитие отображения плана и самостоятельная поставка локального MCP/runtime. Переносимость на Windows учитывается при выборе оболочки, но отдельная Windows-версия и её физическая проверка не входят в первый macOS-прототип. Эти направления не образуют второго активного TODO: конкретные задачи добавляются управляемой командой после уточнения объёма.

## Граница compact

Пользователь хочет восстановление и после автоматического compact. Отправка через поле ввода решает доставку сообщения, но не обнаружение внутреннего события ChatGPT. В доступном Web Work подключении автоматические hooks ранее не были подключены. Новый Chromium сам по себе этого не меняет.

В первом scope подтверждается стартовый сценарий. Восстановление перед следующим пользовательским запросом обсуждалось как возможная альтернатива; оно не утверждено как обязательное действие на каждом ходе. Надёжный сигнал compact остаётся отдельной исследовательской задачей, а не скрытым обещанием прототипа.

## Приёмка

Пользователь видит одно окно со встроенным ChatGPT, сам выбирает папку и получает автоматический старт без копирования промпта. Агент и сайдбар показывают совпадающие факты выбранного проекта. Переключение проекта не перенаправляет работающий чат в другую папку. Ошибки подготовки, подключения и отправки различаются. Сборка, HTTP-ответ или ручной вызов хука отдельно не считаются этой приёмкой.

## Архив проектов в версии 0.5

Меню ⋯ у workspace переносит его в архив Web Pilot, сохраняя папку и все сессии. Шестерёнка справа от подробностей подключения открывает настройки со всеми архивными проектами. Их можно вернуть в активные без нового стартового сообщения либо удалить с диска вместе с локальной историей. Перед удалением показаны путь, размер и количество сессий; требуется подтверждение точным именем. Чаты остаются в ChatGPT. Архивирование не изменяет статусы плана Workflow Kit.


## Тема оболочки

В Settings пользователь отдельно выбирает светлую или тёмную тему Project Web Pilot. Она охватывает весь левый сайдбар, включая проекты, сессии, состояние контекста, формы и архив, а также нативную верхнюю панель окна macOS. Выбор сохраняется между запусками. Встроенная страница ChatGPT Web не получает команду смены своей темы: её оформление пользователь по-прежнему настраивает внутри ChatGPT.

## Скрытие служебных строк инструментов

В Settings пользователь может выбрать «Скрывать» или «Показывать» строки активности вызовов инструментов во встроенном ChatGPT. Это косметический фильтр Web Pilot: он не отключает MCP, не блокирует tool calls и не меняет содержимое разговоров. Настройка сохраняется между запусками и применяется к уже открытому диалогу без перезагрузки.


## Микрофон и геолокация

Встроенный ChatGPT может использовать микрофон для веб-диктовки и запрашивать геолокацию, когда это требуется пользовательскому сценарию. Web Pilot разрешает эти возможности только `chatgpt.com`; камера, screen capture, notifications и остальные browser permissions остаются запрещёнными. Системное согласие macOS остаётся под контролем пользователя и запрашивается при первом фактическом обращении.

## Регулируемый сайдбар и отдельный архив — scope 002

Левый сайдбар Web Pilot можно расширять и сужать перетаскиванием его правой границы. Текущая ширина 312 px является минимальной; при уменьшении окна приложение сохраняет достаточно места для встроенного ChatGPT. Выбранная пользователем ширина сохраняется между запусками.

В Settings вместо встроенного списка архивов остаётся одна кнопка «Архив проектов». Она открывает отдельное локальное окно управления архивом. Список поддерживает обычный desktop multi-select: обычный клик выбирает один проект, Shift — непрерывный диапазон, Command на macOS и Ctrl — отдельные элементы.

Для выбранных архивных проектов доступны «Вернуть в активные» и «Убрать из списка». Последняя команда удаляет только локальную запись Web Pilot вместе с локальными привязками сессий; папка на диске и чаты ChatGPT сохраняются. Такой workspace можно позже снова подключить через «Открыть папку проекта». Физическое «Удалить с диска» сохраняет прежнее точное подтверждение и выполняется по одному проекту за раз.
## Самостоятельный блок «План» — scope 003

План — отдельный пользовательский блок левого сайдбара и основной индикатор хода работы. В нём показываются все микрозадачи текущего scope с понятными состояниями: `✓` — выполнена и зафиксирована коммитом, `●` — выполняется сейчас, `○` — ещё не начата. Главная строка блока объясняет состояние человеческим языком: во время работы — «В работе · X из N выполнено», после завершения последней микрозадачи — «Все задачи выполнены · ожидается ваша приёмка». При BLOCKED показывается заблокированное состояние; после явного закрытия scope интерфейс отличает архивированный scope от проекта, где план ещё никогда не создавался.

`plan_revision` остаётся внутренним техническим счётчиком Workflow Kit и в пользовательском блоке не отображается. Пользователю важны названия микрозадач и их фактическое состояние, а не номер внутренней ревизии.



## Завершённый scope — scope 004

После штатной приёмки и архивирования карточка «План» показывает «Scope завершён и архивирован» и отдельную строку «Проект готов к следующему новому плану.». Это состояние определяется по `execution_scope_status=NONE` вместе с `archived_scope_id`; новый проект без истории архивированного scope по-прежнему показывает «План ещё не создан».

## Исследование auto-compact — scope 005

Project Web Pilot пассивно накапливает диагностический журнал поведения встроенного ChatGPT Chromium, чтобы после предполагаемого auto-compact сравнить фактические события до и после него. Журнал сам не определяет compact и не запускает «Обновить контекст»: текущий scope только собирает доказательства. Основной файл находится в `~/Library/Application Support/Project Web Pilot/diagnostics/chromium-events.jsonl`, предыдущая ротация — рядом с суффиксом `.1`. Пользовательские сообщения, recovery context, cookies, authorization headers, request bodies и query values не записываются.

## Целевая context telemetry — scope 006

Chromium diagnostics теперь ориентирован не только на общий forensic log, но и на конкретные server-side признаки контекстного окна. Для WebSocket и `POST /backend-api/f/conversation` (`text/event-stream`) Web Pilot в памяти ищет безопасные token/context поля и markers, подтверждённые на нативных Codex JSONL: `token_count`, `last_token_usage`, `input_tokens`, `model_context_window`, `compacted`, `ContextCompaction` и наличие `compaction_response_id`. В журнал записываются только числовая telemetry и признаки событий; сырой SSE/WebSocket payload, текст сообщений и summary не сохраняются. Этот scope по-прежнему не запускает автоматическое «Обновить контекст»: сначала требуется реальное наблюдение сигнала ChatGPT Web.

## Индикатор контекстного окна — scope 007

В левом sidebar есть отдельный компактный индикатор «Контекстное окно». Он показывает процент и пару «использовано / окно» только когда Chromium diagnostics получил от ChatGPT Web подтверждённые числовые `inputTokens` и `modelContextWindow`; никакой локальной оценки по длине переписки не подставляется. Пока серверная пара не обнаружена, пользователь видит «Ожидаем данные» без фиктивной полосы. При навигации на другой чат наблюдение сбрасывается. Для поиска отличающихся Web-названий parser дополнительно сохраняет только безопасные пути ключей и числовые candidate values вне message/content-поддеревьев. Auto-compact в этом scope остаётся наблюдаемым событием и ещё не запускает автоматический refresh контекста.

## Результат полного transport-эксперимента — scope 008 / T002

Контролируемый raw-capture двух коротких turn показал, что ChatGPT Web не передаёт browser-клиенту числовые `input_tokens`, `output_tokens`, `total_tokens` или текущую занятость context window даже внутри вложенного `encoded_item`. Зато live `GET /backend-api/models` для используемого `gpt-5-6-thinking` возвращает `max_tokens=262144`, а полный объект разговора содержит отдельное поле `context_truncation_continuation`, которое в момент эксперимента равно `null`. Временный raw-capture удалён из продукта. Обычная диагностика теперь сохраняет только безопасный model limit и булево/типовое состояние truncation continuation; содержимое continuation, история разговора и сырые payload не записываются.

## Граница платформы macOS/Windows — scope 008 / T004–T006

Project Web Pilot остаётся одним Electron-приложением с общей Chromium/UI/workflow-логикой. Подготовка к Windows выполнена без отдельной кодовой ветки: platform-specific различия локального runtime, Python venv, внешнего Node и default runtime folder вынесены в `src/platform.mjs`. На macOS поведение и текущий путь Codex Local Mac сохранены. Windows layout и packaging target добавлены как подготовка; это не означает, что Windows Local MCP/Desktop runtime уже реализован или принят пользователем.
